# showcard-pro

需要展示周报、项目汇报、可展示的总结时使用。单纯问概念/翻译不制作文件；明确点名本技能按指定技能使用，不能偷偷替换。能力与来源见 `references/sources.md`。不把本技能正文写入系统提示词，不访问在线转换服务、不上传用户记录、不在使用时安装npm依赖。

**第一步的技能选择**：如果用户这次任务包含“分析销售CSV，再做周报”，加载本技能后的**下一个动作先调用 `skill`，`name="data-analysis"`**。两项技能选齐之前，不调用read、pwsh、不检查路径/Node版本、不读取或处理材料。不要等分析进行到一半才补加载；只说“会分析”不算。即使目录只列本技能，也按名字加载该依赖。依赖加载失败须如实说明，不绕过停用/未信任限制执行它的脚本。

1. **再读取真实材料**：选齐需要的技能后，读取用户已提供/授权的本周记录，核对日期、事实、完成和未完成。没有记录就简短询问，不虚构成果或套用examples的数字。多来源保留出处；涉及销售CSV时按已加载data-analysis的规范核对列/时间范围、执行汇总，再把真实结果用于周报。
2. **确定这次交付**：默认简报式周报：本周要点→完成→数据→风险→下周→依据/待确认。来源详细内容不够支持结论就标待确认。用户已有明确的格式、风格、主题、输出位置直接遵循；只问阻塞的缺项。长篇完整文章/复杂设计需要先给提纲和风格让用户确认，再按需读 `vendor/beautiful-article/references/` 的编辑与主题规则，不能默默删重要信息。
3. **实际生成**：读取 `references/input.md`，将用户材料整理为JSON，使用其指定离线命令（应用随包Node + `scripts/render-report.mjs`）生成完整HTML和小摘要。输入只做文本，保留来源和待确认，输出选新文件名。没有可用Node时如实说明环境限制，不擅自装依赖；不执行上游会联网的脚手架。来源对应固定版本，默认无需联网、无需账号。
4. **立即完成展示**：生成成功后读 `.card.html` 全文，直接调用现有 `show_card`，title为自然中文标题、html为该摘要HTML。摘要有意不含完整指标表/图及全部出处，完整内容在另一份HTML，不因摘要精简而反复重做。先展示再给文件链接，不用文件路径假冒html参数，不编造卡片ID。不申请网络、文件、执行绑定；卡片只用既有宿主的已阅状态。
5. **核对后回执**：确认生成成功，读取产物核对正文/来源/数值和非空文件；有浏览器时实际打开核对中文、图表、窄屏可读和无外链依赖。没有视觉工具时说明仅做结构检查。失败区分生成失败、卡片展示失败、未做视觉检查；不将三者合成通过。不要声称PDF/Word/PPT已导出，除非另有工具实际完成。

原始 beautiful-article 在 `vendor/beautiful-article`，用于按需参考完整编辑流程；默认走这里已固定依赖的离线路径，避免其scaffold.sh默认安装latest包。ReActicle不是要上传资料的在线服务；希望使用任何联网/账号方案时先说明方式与传输内容并等待用户决定。
