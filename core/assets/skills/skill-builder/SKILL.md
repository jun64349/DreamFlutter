name: skill-builder
description: 创建、安装或更新可复用的 Agent 技能，先比较成熟社区来源，再测试和登记。只做概念讲解、解释示例或聊天文字改写时直接回答，不加载创建流程；素材缺失先请用户提供原文。
---

交付能复用、能测试、有明确支持边界的技能，使用当前 DreamFlutter 的管理工具，不写进系统提示词或直接更改内置目录。

社区条目尚未信任，而用户要求安装后直接执行时，先准确说明“未信任，不能直接执行”。继续来源审阅、静态读取和待确认登记即可；用 `read`、`glob` 等读取工具查看文件，连列目录也不要改用 pwsh/bash，不执行社区脚本或调用 `skill_script_trial`。直接执行不等于用户另行授权了隔离试运行。用户明确新建技能并要求隔离验证时，仍按下面的脚本测试流程办理；用户已给的这项授权不重复索取。

1. 从用户已给的信息确定用途、输入/输出、工作台或蝶君环境和一个可验证例子；只问影响结果的缺项。
2. **先搜索**成熟方案。优先维护者官方仓库，再社区索引；可搜索 `filename:SKILL.md <需求关键词>`、中英文同义词。优先来源包括 anthropics/skills、obra/superpowers、vercel-labs/agent-skills、badlogic/pi-skills；ComposioHQ/awesome-claude-skills 只作索引。记录真实 URL、固定 commit/版本、具体技能许可、维护/采用信号、依赖和需求差异。stars 不代表安全；不伪造搜索或统一评分。网络不可用就说明，并停在可审阅的候选/需求阶段。
3. 有适配技能时展示候选与出处；只获取选定技能的完整目录，`skills.import` 或 `skill_register` 登记后仍需用户确认。不可因为“没搜到”就视作用户同意自建。
4. **用户明确要独特设计才自行编写**；即使已授权自建，也先完成可行的社区查询。用户已明确时不重复索要同一授权。名称用 1–64 个 Unicode 小写字母/数字/单横线，与目录名一致，无首尾或连续横线。完整 SKILL.md 包含 name、description；触发描述有边界。按需添加 references、scripts 和 assets 目录及相对引用，不编造所需工具。
5. 用 `skill_register` 提交完整 content 和可选 files，保存原始出处。content 是含 frontmatter 的完整 SKILL.md 文本；files 的键是相对文件名，值是该文件的完整文本/源码字符串（例如 `{"helper.py":"print('ok')\n"}`），不能填本机文件路径，也不能重复放 SKILL.md。无需用 write 中转。自行编写设 sourceKind=agent，实际社区导入设 community；参考链接不等于社区安装来源。它只生成 pending 建议，同名用于更新；别自己改信任、启用或复制进内置目录。保存返回的 proposal id。
6. 对 proposalId 调 `skill_test`。有脚本时再对相同 proposalId 和具体 script 调 `skill_script_trial`，按代表性输入校验输出/产物。试运行由后台复制到蝶君临时目录，以 agent 用户执行并限时限输出；不使用本机 pwsh/bash 绕过。沙箱不可用、缺依赖、不支持脚本类型、超时分别如实报告。无脚本时说明“纯指令技能，无脚本可试运行”，不能编造试运行通过。
7. 检查成功后报告来源、支持环境、格式检查与试运行各自结果、待确认 id。用户在管理页确认后才能启用，**测试成功不等于授信**；Agent 没有确认自己的工具。对未知/不支持的输入明确说明边界。

社区来源链接是发现入口，不直接复制整套上游工作法或默认下载/执行上游脚本。要修改内置技能，请让用户先在管理页复制为用户技能，再走更新与确认。
