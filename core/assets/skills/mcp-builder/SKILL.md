---
name: mcp-builder
description: 为尚未配置的外部服务发现、配置或创建有边界的 MCP 接入，完成待确认、连接和只读业务验证。不用于概念解释、已有服务的普通业务查询或权限状态说明；已有服务未授权、停用或撤销信任时先停止业务请求并提示用户处理权限。
---

先明确需要读/写什么、用工作台还是蝶君，以及验收的只读查询。复用成熟服务优先，不把“接上服务”扩大为全 API 支持。

已有配置的权限问题不是新接入任务。对未授权、停用、撤销信任的服务，先说明不能执行业务，提示用户在管理页处理；不新建替代服务、不自授信、不用网络或脚本绕过。用户只询问权限状态时直接解释；用户明确要求测试已信任但停用的服务时，可做连接测试并保持停用。

1. 查询服务商**官方文档**和官方 Registry（只读查询）。Registry 搜索地址 `https://registry.modelcontextprotocol.io/v0.1/servers?search=<编码关键词>&limit=10`；跟随 metadata.nextCursor 分页，按 servers[].server 读元数据；固定选中版本，排除删除项，标明 deprecated。Registry 是目录，收录不等于安全背书。还需核对源仓库许可、平台、运行依赖和鉴权方式。
2. 首版支持 stdio 或 Streamable HTTP；旧 SSE `/sse` 不支持。客户端固定 Pi 现有 **2025-11-25** 及其可协商的旧协议；不升级 SDK。对只接受更高版本的服务，连接测试应给出“协议不兼容”和对方版本，不能声称接通。
3. 优先生成已有服务配置；确需开发时先约定少量明确工具、输入输出、分页和错误。使用随包运行时和已验证的依赖，不在运行时偷偷安装未知包。未知服务命令/脚本不在本机试跑。密钥字段标 secret，由后台加密，不写到命令行、日志或说明中。
4. 用 `mcp_register` 提交 server（name、transport、command/args 或 url、必要 env/headers）及 sourceUrl；自行创建/配置用 sourceKind=agent，社区安装用 community。它只生成 pending；等待用户在共享待确认队列确认，不能自己改信任/启用，也不能绕过未信任测试限制。更新同名服务同样重新确认。
5. 用户确认后重新加载会话使新工具可见，再调用 `mcp_test` 做真实启动/连接、握手、完整工具枚举和关闭。缺程序、鉴权失败、协议不兼容、超时分别报告。只列工具不能冒充账号权限/业务验证成功。
6. 连接成功后，在已经授权且启用的服务上，用发现出的准确工具名执行一次**已知答案的只读业务查询**，核对结果；不发送消息、不修改日历、不创建真实外部记录。没有合适只读工具就报告“连接通过，业务验证未完成”，不随便调用写工具。
7. 分开报告：①连接测试；②只读业务验证；③信任；④启用。列出已验证的工具/输入边界、原始来源与版本、失败原因；蝶君权限另列，默认未授权，用户须按服务单独开启。MCP 服务即使授权给蝶君，也在本机运行。

用户仅提供本地可控测试服务时，可使用其 fixture URL/命令和已知答案验证，无需索要第三方账号。网络/Registry 不可用时如实列出未核验项，不能伪造查询或连通结果。
