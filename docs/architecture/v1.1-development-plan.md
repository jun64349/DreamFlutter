# Windows V1.1.0 开发计划

2026-11-20。目标是让用户带着原来的数据打开梦蝶，在原有界面完成 1.0 的工作，后台使用随安装包交付的官方 DeepSeek Harness（DSH），蝶君在 Windows 原生工作区工作。用户接受插件重启后装卸。V1.2、V1.3 留到本版结束再规划，macOS 迁移排在 V2.0.0 完成以后。

## 已确定的插件体验

- **V1.1 交付应用内插件管理。** 普通用户打开梦蝶就能浏览、安装和管理插件。从目录选择一个插件，到安装后看到它起作用，再到停用或卸载，都要能在梦蝶里完成。后台与内置插件继续随程序在本地交付。
- **目录只列梦蝶实测过的插件。** 上架记录对应实际测过的插件版本和梦蝶版本。插件上游发布新版本后，先验证，再将该版本列为可安装更新。
- **记忆默认内置，用户可以停用和重新启用。** 管理页提供这两项操作，提示重启生效。停用保留记忆数据；重启后继续原对话时不再带记忆快照、调用记忆工具或启动后台整理。重新启用并重启后可以使用原有记忆。
- **验收用两个基础功能插件。** 从用户列出的用量、仪表盘、桌宠和快捷键中，选择用量仪表盘和窗口内快捷键。前者检查插件能否拿到正确用量并在 Flutter 中显示，后者检查插件能否触发已有命令、停用后解除绑定。记录实际包名、来源、版本、梦蝶适配和复用的上游代码。从 Windows 插件目录分别安装并使用这两个插件。
- **后续模块的产品形态已确定，版本待定。** 一组插件可以打成一个模块包，安装后在左侧栏与「工作台」「蝶君」并列。点击后进入模块自己的操作界面，使用它专有的 UI 和功能。模块提供的设置项追加到梦蝶现有设置中。V1.1 的两个基础样例使用各自合适的界面位置，独立模块的开发安排在后续版本。与原研究的对应关系见[模块化设计](../research/dsh-2.0/02-plugin-composability-and-modules.md)。

目录可沿用上游插件索引格式，由梦蝶维护实测清单。实施时要用梦蝶实际交付的 DSH 版本验证安装流程。[上游插件索引文档](https://github.com/deepseek-ai/deepseek-harness/blob/9c2670d3bce5275e0d1610272958121af87787bb/docs/user/guide/plugin-market.zh.md)

用量样例可沿用梦蝶现有账本，与「花费」页对账。快捷键样例优先选用已有窗口命令；上游提供命令注册和设备键位约定，窗口按键由梦蝶的 Flutter 客户端承接。[梦蝶花费页](../../app/lib/ui/spending_page.dart) · [上游快捷键文档](https://github.com/deepseek-ai/deepseek-harness/blob/9c2670d3bce5275e0d1610272958121af87787bb/packages/client/shortcuts/README.zh.md)

## 升级和蝶君的验收场景

1. **旧对话保留原件。** 用户可以回看 1.0 对话及分支。点击「继续」时创建新的 DSH 对话，把选中分支的上文带过去。验收使用含分支、工具结果和附件的旧记录，核对两个会话的 ID、原文件内容、新会话的模型输入，以及重启后两条记录仍可打开。历史里的命令只作为历史内容，打开和续聊都不会重新执行它们。
2. **资料研究与模拟。** 给蝶君一个普通科研问题，例如排队系统的等待时间怎样随负载变化。让它从可追溯资料整理假设，在原生工作区运行模拟，交付带来源的结论、脚本和结果。用同样参数复算，核对报告中的数值与适用条件。固定资料和合成模型用于回归；公开资料检索、桌面提交和打开产物分别记录实际覆盖。
3. **软件与插件兼容性。** 给蝶君一个插件和两个明示版本或配置的测试环境，让它实际安装或加载样例，运行相同行为，比较输出，交付兼容性表和复现方法。核对报告里的结论能从原始输出还原。以本地测试样例起步，另从成品入口验证实际插件和客户机的组合。

## 施工顺序

| 顺序 | 开发内容 | 验收方式 |
| --- | --- | --- |
| 1. 接通插件目录和管理页 | 用梦蝶实测清单生成目录，接通本地 DSH 的插件安装和装配。在 Flutter 中浏览、安装、管理目录中的插件；内置记忆提供停用和重新启用。 | 在 Windows 窗口从目录安装两个样例，核对显示或操作效果，停用或卸载后确认贡献撤下，再安装后可用。核对可安装版本均有实测记录。用同一条对话从窗口完成记忆停用、重启、重新启用、再重启。 |
| 2. 完成日常会话切换 | 在现有 Flutter 入口迁移标准、临时、侧边会话，保留原来的落盘规则。旧会话只读；「继续」另建一条带所选分支上文的新对话。 | 用 1.0 数据副本核对原件、选中分支的上文和附件，新会话收发、审批、压缩、重启恢复；检查模型、账本和真实 DSH 运行记录。 |
| 3. 按功能完成插件迁移 | 沿现有入口逐个迁移或确认记忆、技能、MCP、目标、日程、审批和交付。固定内置的能力也要列明原因。 | 对记忆复跑三次启动；对其他选定可拆插件复跑有插件、无插件、装回三种情况。检查普通聊天、其他插件及既有数据。按权限、依赖、前端适配三项验收官方样例。 |
| 4. 收完蝶君原生工作区 | 对照常用任务解决默认安装路径下工具的可用性，接好旧工作文件的迁移或保留，以及安装、重置、存储搬迁和卸载流程。 | 在普通 Windows 用户和真实安装位置，用工作台或蝶君原窗口跑选定任务，提交实际产物。核对离线、显式联网、目录访问边界、迁移失败回退和进程退出。 |
| 5. 验收 Windows V1.1.0 | 固定官方依赖，按上游升级检查重新装包，构建最终候选，用干净目录和 1.0 数据副本各走一次。 | 用成品执行依赖/历史检查、原有界面契约、插件装卸、旧版升级及回退，核对本机后台、工作区、窗口和数据。按项目约定交用户验收；推送、打标签、合并、发布仍逐次授权。 |

三轮需求确认于 2026-11-20 完成。此计划为 Windows V1.1.0 的开发与验收依据，完成进度记录在[交接文档](../HANDOFF.md)。
