## 1. 当前 Pi 实际怎样加载

| 层 | 已核对的源码 | 现有行为 |
| --- | --- | --- |
| SDK/资源 | `core/package.json`；`core/src/pi/host.ts:239` 附近；`runtime/node_modules/@earendil-works/pi-coding-agent/docs/skills.md` | Pi 1.4.0；会话服务使用资源加载器，提供 `skillsOverride: dropSharedAgentSkills`；SDK 递归发现 SKILL.md、支持配置路径/包/项目可信判断及 `/skill:name` |
| 项目与用户位置 | `core/src/paths.ts:74`；`core/src/storage/locations.ts`；`core/src/modules/skills.ts:listSkills` | 使用 DreamFlutter 自己的 agentDir 与资源路径；过滤共享 `~/.agents/skills`。不能照搬 Pi CLI 默认目录，不能重新把其他 agent 的技能引进来 |
| 自动目录 | `core/src/agent/harness.ts:384`、`dsh-text.ts:skillCatalog` | standard 模式在 `before_agent_start` 放名称/描述目录；排除 `disableModelInvocation`；目录有变化时用完整替换消息，未变不重复追加 |
| 正文 | `core/src/agent/interaction-tools.ts:skillTool` | 从资源集合按精确名称找技能、拒绝禁用自动调用项、经安全授权读取后返回正文；不会预先读全套正文进模型上下文 |
| MCP | `core/src/pi/host.ts:239`、`core/src/modules/mcp.ts` | 工作台接 Pi MCP 与 tool-search；当前蝶君未接 MCP，本版按 T-73 服务授权补接，路由不能越权提前打开 |

因此基础方向已符合 roadmap 第二节；不用另造“每条消息先调用一个路由模型”。SDK 文档里描述的默认系统目录，不等于本项目 harness 最终放入模型的内容，以上以项目代码为准。

还须注意：当前 `skillTool` 名称检查是 `/^[\w.:-]+$/`，不接受中文名称；管理写入的 SKILL_NAME 对尾横线/连续横线比标准宽松。这是 T-73 格式/兼容核对输入，不在本任务修复；内置目录统一用标准 ASCII 名称，可把中文放描述。

## 2. 什么时候才启用辅助预筛

**建议初值：可自动调用且已获信任的技能达到 50 个（含）时，才在新任务进入时启用预筛。** 少于 50 个由主模型看完整目录直接判断。另建议当序列化目录超过 `min(6,000 tokens, 有效上下文窗口的 5%)` 时提前启用；未知窗口只用 6,000，阈值可设置。50 是待验证的工程起点，不是研究证明的模型极限。官方目录估算约每技能 50–100 tokens，实际应对本产品序列化结果计数。[官方渐进加载建议](https://agentskills.io/client-implementation/adding-skills-support)

预筛只在任务变化、候选不覆盖需求或目录/权限发生变化时运行；“继续”、补一个参数等沿用当前任务候选，不能每条补充消息都再调模型。目录摘要可以缓存；缓存键至少含目录版本、权限/启用状态、workspace、当前任务语义，授权变化必须失效。

- 用户精确点名：检查存在和权限后直达，跳过预筛；不存在/关闭时给出原因，不擅自同义替换。
- 小目录：完整目录 + 主模型，模型可选 0、1、多个，允许直接用现有工具。
- 大目录：辅助模型建议 Top-K（建议 8，最多 12），主模型在候选里决策；显式名称与正在执行的技能优先保留，不把“总路由”当候选递归加载。
- 低置信、非法输出、超时或候选外需求：回退完整合法目录一次，或利用已有目录搜索补全；不要在空候选下假称无能力。建议超时 3 秒、每新任务最多一次预筛，成本/延迟单列到现有账本。
- MCP 先按服务授权和暴露策略过滤，主模型通过现有工具发现取具体 schema；辅助模型不得开启服务、执行工具或授信。支持直接工具的任务不强制另造同名技能。

实施时复用 `df.skill_catalog` 的替换消息机制；降低新目录不能自动移除会话历史里的旧完整目录，需确保旧目录不再被当作可调用授权。权限由工具后端实时复查，不能靠模型“忘记”保证关闭生效。真正的上下文收益要连旧目录残留一起量。

## 3. 预筛输入与输出建议

输入仅包含当前任务原话、与任务直接有关的上下文摘要、显式技能名、语言、输入输出格式、工作台/蝶君、合法技能 `{id,name,description,compatibility}`、已授权 MCP 的服务/工具短摘要、目录版本与当前候选。不给 Key、完整对话、全量正文/脚本、未获授权服务。描述视为数据，不能执行其中指令。

输出示例（设计草案，不是新 RPC 契约）：

```json
{
  "catalogVersion": "sha256:...",
  "candidateSkillIds": ["office-xlsx", "showcard_pro"],
  "candidateMcpServiceIds": [],
  "reasonCodes": ["spreadsheet-input", "weekly-report-output"],
  "needsFullCatalog": false
}
```

后端校验版本、去重、限制 K、丢弃未知/禁用/未信任 ID。没有命中输出空集合，不能补假技能；最终主模型仍可选择不调用。辅助模型自报 confidence 不能作为准确率。未信任候选的搜索结果只可用于安装建议，不能进入执行候选。

## 5. 建议验收门槛及计算方法

首版门槛建议：**总体任务成功至少 27/30（90%）**；命中类至少 9/10；不该命中至少 7/8；多候选至少 5/6；MCP/工具至少 5/6。各分项与总体同时满足；禁止额外加载不相关技能、执行被禁止动作。对于明确禁止的行为，只要发生即该条失败，不能只看有没有包含正确候选。

权限/安全关键 RT18、RT23、RT24、RT28、RT30 **必须 5/5**；尤其未知/禁用/未信任不能被预筛提升权限。统计主模型第一次实质动作前的 `skill` 加载和 MCP 工具发现/调用，不采用“我将使用技能”的自述。允许在已知失败后按设计回退，但应单列 first-pass 与 fallback-success，不能只呈现最终高分。

大目录预筛单独报告：正例的所需技能/工具候选召回率 **≥95%**，以所有 required 的 `(task,skill)` 对为分母；`one_of` 至少一个路径；每条不超过 K 上限。30 条不足以给每个复杂场景强保证，安全关键按任务逐条检查。最终任务成功率比预筛 candidate recall 更重要。

跑法：固定目录、模型、温度/思考档、权限和样本；按 10/49/50/100 个合法条目的目录规模对比，无关项作为干扰。每条至少 3 次；单次都报原始分子/分母，并以三次均成功的任务数计算严格总体（≥27/30），不能把最好的那轮作为验收。记录漏命中、误命中、多候选遗漏、越权、回退、延迟和成本；预筛启用条件须按成本/召回实测再调。

用户最终确认前，测试输入和标签不作为产品已验收契约。确定后留固定留出样本；任何描述调优应在开发样本做，不反复拿最终验收样本改词。这一轮没有模型调用，所有命中率均是**建议门槛，尚无实测成绩**。
