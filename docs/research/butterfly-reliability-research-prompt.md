## 提示词

````text
你是一名做学术和工程调研的研究员。请就「长期运行、高自主性的 LLM Agent 如何做到可控、可靠」做一次文献调研，产出一份中文调研报告。

# 背景（只作为调研的落点，不需要你评价这个项目）

我们在做一个桌面 AI 助手应用。里面有一个叫「蝶君」的常驻 Agent：
- 在一个隔离的 Linux 沙箱（WSL2，普通用户，没有 root，可开关联网）里干活，沙箱里不需要用户审批；
- 主动性强、频率高：会按用户给的长期目标自己决定学什么、做什么，给自己写技能、装工具，空闲时会主动找用户聊天；
- 有固定的人设（几种性格预设，由用户选），有长期记忆；
- 能长时间推进多步任务（目标、调度、续跑、验收），任务完成由它自己验收；
- 少数操作会影响沙箱外面（用户的电脑、对外发送等），这些必须经过用户审批。

项目负责人是做可靠性系统工程和测试的工程师。我们的基本立场是：大模型是不可靠元件，可靠性不能靠模型本身，要靠外围的 harness（运行框架、约束、监控、恢复）来保证。目前的设计思路：
1. 边界内模型说了算，过边界时程序说了算（出沙箱、超预算、报完成、改受保护配置这几个关口由确定性程序把关）；
2. 按后果分级：沙箱内出错自己重试、换方法；沙箱外一律走用户审批；
3. 自我修改禁区：规则、权限、预算、人设、审计记录 Agent 自己改不了；
4. 防护分四种时机：每次动作前的同步检查（联锁）、运行中的旁路监视（看门狗）、完成后的复核、开发期的离线分析（FMEA / FTA，加 FRACAS 把运行中的故障反馈回失效模式表）；
5. 分层：物理隔离 → 程序硬约束 → 提示词软约束 → 监测审计 → 恢复。

请用文献检验、补充或推翻这些思路。

# 时间和来源

- 重点是近两年（约 2024 年底到现在）的成果；更早的经典工作只在奠基意义上引用。
- 来源：顶会和期刊论文（NeurIPS、ICML、ICLR、ACL/EMNLP、USENIX Security、CCS、S&P、ICSE、FSE、DSN、ISSRE、SafeComp 等）、arXiv 预印本、主要模型厂商和研究机构的技术报告与工程文章、相关标准（如 ISO/IEC 42001、NIST AI RMF、ISO 26262 / IEC 61508 里可借鉴的部分）。
- 每条结论都要给出处（标题、作者、年份、会议或网址）。**不要编造文献**；拿不准是否存在的就不要写，或明确标「未核实」。
- 区分证据强度：有实验数据的、只是提出框架的、只是观点的。

# 要回答的问题

## A. Harness 和运行时防护
1. 现在有哪些 Agent harness / guardrail / 运行时监控的架构？各自在哪一层、什么时机拦截（动作前、运行中、完成后）？
2. 「模型提议、程序裁决」一类的设计（策略引擎、能力令牌、权限系统、形式化约束、参考监视器）有哪些研究和效果？怎么在不扼杀自主性的前提下做？
3. 怎么防止 Agent 修改自己的约束、权限、目标（自我修改、奖励篡改、规格博弈）？
4. 沙箱和隔离对 Agent 的实际防护效果，有哪些逃逸或绕过的实证研究？

## B. 失效模式和系统安全方法
5. 有没有对 LLM Agent 失效模式的系统分类（taxonomy）？尤其是：虚报完成、死循环和失控花费、提示注入（含间接注入）、重复执行副作用、越权、目标漂移、记忆污染、工具误用。
6. FMEA、FTA、STPA、HAZOP、FRACAS、安全案例（safety case / assurance case）这些系统安全和可靠性方法，有没有被用到 LLM Agent 上？怎么用的，效果如何，有什么局限？
7. 能不能给 Agent 建可靠性指标体系（类似 MTBF、失效率、可用度）？已有的度量（任务成功率、pass^k 一致性、虚报率、干预率等）有哪些？

## C. 验证和评测
8. 长时程、多步 Agent 的可靠性评测方法和基准有哪些？怎么测「同一任务多次运行的一致性」？
9. 故障注入、混沌工程、红队在 Agent 上的做法。
10. 自我验收 / 自我验证（self-verification、LLM-as-judge）可靠到什么程度？怎么配合程序的硬检查？

## D. 人格和行为的稳定性
11. 长期运行的 Agent 人格漂移、角色一致性的研究：怎么度量、怎么防？
12. 长期记忆对行为的影响（记忆污染、记忆注入、身份混淆）和防护办法。

## E. 主动性
13. 主动型 Agent（会主动发起对话和任务）在打扰、信任、可控上的研究：怎么设定主动的频率和边界？

# 产出格式

一份中文 Markdown 报告：

1. **摘要**：一页以内，最重要的十条发现。
2. **按 A–E 分节**：每个问题给出结论、主要文献（每篇两三句话：做了什么、发现了什么、证据强度）、对「蝶君」设计的启示。
3. **对现有五条设计思路的逐条评价**：文献支持、需要修正、还是反对，理由和出处。
4. **一份 Agent 失效模式清单（FMEA 草表的起点）**：列为表格，每行：失效模式、典型表现、可能原因、检测手段、文献里的防护办法、出处。
5. **建议**：可以直接采纳的设计、需要我们自己做实验或仿真验证的问题、建议的仿真或实验方案。
6. **参考文献**：完整列表，带链接；标出哪些你亲自读过原文、哪些只看了摘要。

不需要写代码。篇幅以把问题讲清楚为准，不要堆砌。
````
