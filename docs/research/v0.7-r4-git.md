## 4. 两个方案比较

| 方案 | 本版新增体积 | 工作台与用户影响 | 维护成本 |
| --- | --- | --- | --- |
| A：标准 MinGit 随包 | Windows 解压 +91.78 MiB；资产压缩 38.00 MiB；沙箱 +0 | 无系统 Git 也能离线做本地 7.7 功能，版本统一；优先包内路径，不改系统 PATH；仍使用用户 Git 作者配置；需要复杂 hook/Perl/GUI 的用户可配置完整 Git | 应用发布时跟踪 Git 安全更新、固定版本/架构/官方 hash、保留随附许可并补入第三方清单；每升级跑代表性命令和恢复点回归 |
| B：不带，提示用户安装 | 随包 +0；用户另装占用另计，未实测完整 Git 安装体积 | 有系统 Git 可直接用；无 Git 的干净机器工作台返回未安装、功能暂停到用户安装完成；蝶君仍可用。需联网下载或另找离线安装介质，版本/配置差异更多 | 随包二进制少一项，但仍须处理版本能力差异、路径配置和安装指引；安全更新由用户负责，排障成本更高 |

**推荐 A**：派工要求工作台和蝶君均可用，且保留离线随包承诺；B 的减重代价是工作台初始缺能力，不能把这种缺口称为同等验收通过。实际解压成本约 **92 MiB**，高于 roadmap 的“约 50 MB”粗估，必须让用户依据实测取舍。若用户选 B，应明确接受无 Git 时工作台受限，并由 Claude 记录对应行为。

不需要新增常驻 Git 服务进程、自动下载器或用户全局配置。复用应用现有更新/许可清单工作，把找 Git 路径做成已派的配置项即可。用户未决定前，不改打包、不替换已有 Git、不动 T-74 文件。
