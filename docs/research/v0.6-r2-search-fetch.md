# R2：联网搜索、抓取与正文提取

查询日期：2026-11-07（Asia/Taipei）；T-60，只读调研；基线 `deb6224`。以下为官方文档报价快照，不是采购承诺。本轮没有购买、调用付费服务、登录供应商或做网络性能实测。

## 推荐与现状

建议用户选 **DeepSeek 原生 Search + Fetch 为第一家远程服务**，现有 HTTP 抓取继续作为基础能力；服务可切换，先不同时实现全部候选。JavaScript 页面确有需求时，再提供沙箱内按需无头浏览器。此选择待用户确认，不自动沿用 OpenCode Go 的 key 调 DeepSeek。

[core/src/modules/web.ts](../../core/src/modules/web.ts) 当前可下载网页、去除部分 HTML 并提取正文，不执行网页 JavaScript，没有独立搜索服务。已有大小/长度限制、公共地址检查及 DNS 连接层防护；这些防护需要随新适配器保留。当前正则提取不能保证复杂网页结构、登录页面或反爬页面的效果。

## DeepSeek 的可执行接入依据

- 原生地址：`POST https://api.deepseek.com/v1/tools/search` 与 `/v1/tools/fetch`，Bearer API key。Search 的 query 为 1–128 字符，count 1–50（默认 10）；need_content 可请求正文。Fetch 接收 HTTP(S) URL，不接受 URL 内嵌用户名/密码。[S1]
- 文档所列账户级限流为 Search 100 QPS、Fetch 25 QPS；不能据此承诺应用达到该吞吐。客户端仍需有界并发、取消、超时、429 退避和响应大小限制。[S1]
- Go、其他中转渠道与原生 DeepSeek 凭据分别配置。原生工具支持不意味着 Pi 的任意模型会自动获得此工具。
- 将工具实际费用纳入 6.6，关联会话/运行和请求时间；API 没有返回最终费用时按文档估算并标记来源，不能伪称供应商已结算。

## 建议的产品边界与工程验收

选项 A：仅现有 HTTP 抓取，成本最低但无搜索且动态页缺口仍在。选项 B（推荐）：DeepSeek 搜索/抓取 + 现有 HTTP。选项 C：同时引入多个服务和浏览器，覆盖可能更广，但密钥、计费、包体和维护范围显著扩大，本版先不选。

后续适配层建议统一返回标题、最终 URL、来源、抓取时间、正文、截断/失败原因和费用来源。搜索结果/网页正文属于外部数据；不因网页写了“执行命令”而取得工具权限。保留 DNS/重定向/私网防护，明确仅公开网页，不自动上传本机文件或使用个人浏览器登录态。

本地浏览器如果实施：运行于现有非 root 沙箱，使用临时 profile；所有子资源/WebSocket/跳转也需要网络策略，不能只校验首个 URL。现有 web_fetch 的 SSRF 检查不自动保护浏览器。无网络模式必须仍有效。不要把浏览器放进 Windows 主进程，亦不默认携带新的整套浏览器镜像。

正式开工后的最小对比集：中文官网、英文技术文档、JS 正文、重定向、404/429、超长页、反爬页；直连/代理各测成功率及 p50/p95，核对来源 URL、正文完整性与每次费用。失败应有可追溯原因，不把验证码/空正文当成功。以上**均未在 T-60 执行**。

6.14 交接：先实测当前包体基线，远程服务原则上只加 HTTP 适配；正文解析如需新依赖，比较轻量解析器及现有依赖复用。不要为减重删除既有离线沙箱；浏览器可选策略须单独确认，不影响已有离线承诺。
