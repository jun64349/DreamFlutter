# R1：套餐用量与余额接口

查询日期：2026-11-07（Asia/Taipei）。T-60，只读调研；代码基线 `main@deb6224`。没有使用密钥、调用计费接口或测试国内网络。本文的“已核实”仅指官方文档与本地源码；实际账号权限、接口响应、国内直连和稳定性均须另验。

## 结论

必须区分账户余额、供应商套餐用量、DreamFlutter 本机累计用量。DeepSeek、Kimi 开放平台的余额不能当作 Coding 套餐剩余量；OpenCode 的逐次 allowance 可以累计，但本机看不到其他客户端的消费。官方未公开或本轮未找到的接口不能写成稳定公共契约。

## OpenCode 的累计边界

官方 Go 文档给出每模型月度计量上限及 5 小时/周/月规则；模型和套餐不同，上限不同，不能把所有模型 allowance 直接相加后除以任意一个上限。[O1] 响应的费用还可能在最终余额/用量更新时被调低，因此本机逐次数据仍不能声称等于供应商最终账单。[O2]

建议保留：渠道、供应商、模型、请求时间、会话/运行、用途（主对话/子 Agent/记忆/压缩/搜索）、原始 token 分类、货币、实际费用/目录估价/套餐占用的区别，以及数据缺失原因。字段名由后续账本任务确定，本调研不修改接口。

- OpenAI 流式接口要请求最终 usage；Responses / Anthropic 分别在完成事件中收集，不能按 chunk 重复入账。[O2]
- 相同请求只结算一次；供应商已返回费用时，不再用 token 单价叠加一笔费用。缓存 token 与 reasoning 不能重计。
- 历史复制、分叉重开不产生新请求，不进入新增用量。压缩候选即使未启用，真实调用仍记账。
- 没有最终 usage、程序崩溃或供应商账单延迟时，记录“缺失/待核对”，不杜撰精确费用。
- 其他客户端消费、跨设备、未被平台观察到的调用均不在本机累计内；不能据此宣布账户还剩多少额度。
- 不统一硬编码“非高峰五折”：以各供应商适用套餐、时区、时段、请求时间和版本化价格规则为准；优先使用官方返回的实际计量。

## 本地实现差距与定位

1. [quota.ts](../../core/src/gateway/quota.ts) `readQuota`：MiniMax 仍用旧 `www.minimaxi.com/v1/api/openplatform/coding_plan/remains` 和 `current_interval_*_count`。只能确认与当前文档不同，**不能断言旧地址已停服**。
2. 同文件 `clampPercent`：缺失/非有限 percentage 返回 0；响应变化可能被展示成“用了 0%”。DeepSeek `Number(total_balance)` 没有有限值校验。这些是静态可定位的修复候选，本轮未执行回归测试。
3. [platforms.ts](../../core/src/gateway/platforms.ts) 已配置 Go 路由；[gateway.ts](../../core/src/gateway/gateway.ts) 有额度/余额查询及缓存。`core/src` 未检索到 allowance 或 billing_source 的实际存储处理，不能宣称已有完整套餐账本。
4. [runs.ts](../../core/src/runs.ts) `costSince` 按运行开始时间归日/月；需要 6.6 的逐请求账本，不能仅扩充额度查询解决。

## 国内连通性、成本和验收

| 服务 | 官方部署/产品线线索 | 国内直连结论 |
| --- | --- | --- |
| DeepSeek、智谱、Kimi、MiniMax 国内站 | 有官方国内服务域名及中文 API 文档 | **未核实**：域名/文档可访问不等于用户本机 API 可直连、账号可用或稳定。 |
| OpenCode Go | 国际服务；当前官方文档也描述了中国请求的地区设置处理。[O1] | **未核实**：不凭定位推断“必需代理”或“保证直连”。 |

后续在用户允许的账号上分别记录 Windows 与沙箱、直连与代理、HTTP 状态、脱敏 schema、时延、429/重试和重置时间；不得把 key 或全响应写进报告。只读查询是否有计费/频率限制，本轮无完整官方承诺，标 **未核实**。不要用多次模型调用代替额度查询验证。

第二波建议先做通用账本与已确认的余额接口；MiniMax 样本验证随后适配；智谱/Kimi Code 未核实部分保持 unknown/unsupported 与估算标签。涉及 SDK 丢弃厂商扩展字段时，先核实公开扩展点，不依赖私有字段。
