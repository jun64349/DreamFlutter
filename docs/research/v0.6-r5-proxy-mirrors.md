## 各工具读取方式

| 工具 | 代理 | 镜像/配置 | 集成注意 |
| --- | --- | --- | --- |
| uv | `HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY`。[P1] | `UV_DEFAULT_INDEX` / `--default-index`，或 uv.toml / pyproject.toml 的 index；默认 first-index 策略。[P2] | uv 不读取 pip.conf/PIP_INDEX_URL 作为自己的配置契约，必须单独设置。[P3] 具体变量支持以随包 uv 版本复核。 |
| pip | `--proxy` / `PIP_PROXY`，配置文件和环境变量；命令行通常优先于 env，env 优先于配置文件。[P4] | `--index-url` / `PIP_INDEX_URL`；Windows pip.ini、Linux pip.conf，也可用指定配置文件。 | 不把额外索引当“自动失败切换”：多个源参与选包有混源/依赖混淆风险；TLS 验证保持开启。 |
| npm | `.npmrc` 的 proxy/https-proxy，或 `npm_config_*`；底层支持 HTTP(S)_PROXY。[P5] | registry / `npm_config_registry`；用户、项目配置均可能影响结果。 | registry 只覆盖 npm 包源，postinstall、浏览器/原生二进制下载和 Git 依赖仍可能走其他域名。 |
| Git | HTTP(S) 传输用 `http.proxy`，环境 `http_proxy/https_proxy/all_proxy`；可按 URL/remote 配置。[P6] | Git 没有通用 registry；`url.<base>.insteadOf` 是 URL 重写，不能当所有仓库镜像。 | SSH 不是 HTTPS 代理；需自己的 SSH ProxyCommand 等配置，不自动转协议或改 remote。默认不写用户全局 gitconfig。 |

各工具最终优先级并不完全一致。建议应用记录“采用了哪一层来源”，尊重项目明确指定的私有源和凭据，不以一个进程级环境变量强行覆盖所有工作区。应用显式设置与项目设置冲突时的产品策略由后续任务契约定义；本轮不设计新设置页。

## 推荐配置范围

1. 保留默认“跟随系统/现有配置”的行为，提供显式选择的 Python/npm 预设与恢复；不静默把所有用户切到同一国内镜像。
2. 只向 DreamFlutter 启动的工具进程/受管配置注入，不写系统环境、用户全局 pip/npm/git 配置，也不重写项目 lockfile。后者可能含源地址，切换镜像时需检查兼容性。
3. HTTP(S) 代理 URL 与 PAC URL 是两种东西。不得把 `.pac` 地址直接赋给 HTTP_PROXY；不能解析的系统代理形式明确标“不支持/未解析”。T-62 实施时核实 Windows 公共接口。
4. 凭据放既有密钥存储；日志/诊断遮盖用户名密码、Authorization；不要通过关闭 TLS 校验、设置 trusted-host 或下载脚本绕过证书错误。
5. 不自动多源竞速或把私有包名发送到公网作为回退；恢复到官方源应可见且符合工作区配置。

## WSL 沙箱怎么设置

Microsoft 文档说明默认 WSL NAT 与 mirrored 模式的宿主可达地址不同；Windows 11 22H2+ 支持 `autoProxy=true` 获取 Windows HTTP 代理信息。[W1] 这不证明当前用户系统版本、WSL 版本、网络模式、PAC 或 loopback 代理均可用，均须实施时检测。

- 优先在受管沙箱内以 agent 用户配置 Linux 环境/软件源，不复制 Windows 全部环境、路径和密钥；Windows 的 `127.0.0.1:port` 在 NAT 下不能直接当宿主代理。
- 若必须用宿主可达地址，明确代理监听范围与安全边界；不自动打开面向局域网的代理或放宽防火墙。既有“离线”设置必须优先，不能为代理放开离线规则。
- 不擅自写用户全局 `.wslconfig` 或改变其他发行版模式。autoProxy/mirrored 是可检测的系统能力，不是应用可无感强改的单沙箱配置。
- 持久 shell 缓存 env；配置变更需决定重建 shell/仅新会话生效并显示状态，不能界面已变、旧 bash 仍用旧代理。
- npm/git/Python 分开验证。代理成功不等于镜像成功，能请求索引不等于能下载 wheel、Git submodule、LFS 或安装脚本资源。
