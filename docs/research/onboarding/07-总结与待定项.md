# 07 总结与待定项

**供用户和 Claude 讨论；界面建议，尚未据此修改设计。** 本轮是资料研究与方案，不代表产品已实现、已实测或已通过验收。两个版本是路线方向，阶段、人日、功能选项均为建议；0.12 前端设计由 Claude 负责，所有涉及既有定型的改动须由用户明确决定具体条目。

## 十条值得先看的发现

以下是**未验收的阶段性结论**；证据等级用于区分用户反馈、文档、原型、有限截图与推断，不表示已测出用户完成率。

1. **用户确实反馈整体上手门槛偏高，具体卡点仍待验证。** 用户报告涵盖安装、初始化、配置和熟悉平台；Q2 的 30 项只是基于文档和原型提出的假设，10 / 18 / 2 是潜在影响分档，不能当作真实故障数或用户人数。**证据：用户整体反馈 + 待验证假设。** 来源：[门槛清单](02-门槛清单.md)、第二张任务卡第 1 节。
2. **复制品尚不能证明与用户旧数据隔离。** 发布说明描述的旧目录与全局偏好可能影响数据选择；本轮复制时排除顶层用户 data，但未启动副本、没有 DreamFlutter 首启或操作截图。**证据：历史发布说明 + 本轮安全处置记录。** 实际是否会导入、完整性和可执行性均未验证；详见 [Q1 走查](01-新手走查记录.md) 与第二张任务卡 Q-03（与第一卡的误建条目 Q-03 不同）。
3. **十款客户端的官方资料提供了不同上手路径，不能数成实测向导屏数。** 有的依靠账号与托管服务，有的使用本地模型或自配服务；网络、硬件、费用、隐私和资格各有代价。**证据：公开官方资料的文档研究。** 实机界面、空态、完成率及条款当前状态不一；详见 [外部调研](03-外部调研.md)。
4. **Chatbox、Cherry Studio、Cursor 已按公开教程细拆首次使用。** 分别整理登录/连接、首次任务或阅读项目、失败与未核实环节。**证据：三款产品的官方网页；非产品实测。** 网页示例不是应用空态证据，教程段落不是屏数，账号、价格与配额需重新核对。来源：[Chatbox](加深-06A-Chatbox首次使用.md)、[Cherry](加深-06B-Cherry首次使用.md)、[Cursor](加深-06C-Cursor首次使用.md)。
5. **HanaAgent 首启向导的本机实际步骤未知。** 审计有有限空态、设置说明和一张可见「打开面板」提示的截图（触发方式未验证）；其公开 README 描述了首次配置事项，但未证明本机版本的实际步骤、完整提示覆盖或用户成功。**证据：另一产品的有限截图与公开说明，二者不能互相替代。** 不能将其推广为 DreamFlutter 行为或直接判断哪种设计更有效；详见 [HanaAgent 对照](04-HanaAgent的上手设计.md)。
6. **悬停表的 28 行只是设计原型样本。** 源码盘点受 Q-02 限制，副本未启动；原型中的 `title` / `aria-label` 不能证明实际应用的提示覆盖或无障碍。**证据：只读 HTML 原型。** 两版本实际控件未知；12 字与 300 ms 是待验证的设计目标，不是通用标准。详见 [逐项复核](加深-07-悬停文案逐项复核.md)。
7. **简化首启与托管界面要先处理数据恢复和定型冲突。** F2 设计对检测到卸载保留数据时的「找回来 / 重新开始」有保护；托管版若锁定渠道、模型组、选择器或花费展示，可能触及定型第 4、5、8、10、11、16 条。**证据：既定设计和方案对照。** F2 实机未测；内容概况的信息来源未在查询契约列出（Q-08），历史卸载契约的保留模式仍计划删除沙箱虚拟磁盘；删除或注销失败可能留下记录中的残留，安装版未验收（Q-09）。具体例外与用户选择尚未定；见 [首次启动方案](05-方案-首次启动.md)、[两版本方案](06-方案-两个版本.md)。
8. **作者代付需要服务端限制与真实预算核验。** 不把总 Key 放进客户端；候选措施是独立可撤销凭据、模型白名单、额度/限速、全局告警及对账，必要时评估薄代理。**证据：官方安全资料与针对项目的架构推断。** 实际站点、并发/流式计费和撤销能力未知，配额不能保证零超支；参见 [令牌与风险](Q3-来源-令牌与风险.md)。
9. **隐私告知、运营责任与具体取舍仍需用户决定。** 中转站和下游、请求数据、保留和访问范围、每人额度、费用展示、反馈与诊断、名称及帮助位置都需要具体确定。**证据：已定两版本方向 + 尚未定的运营方案。** 没有调查真实账户、日志或服务合同，不能承诺零留存或默认无额外费用；下方决策表逐项列出。
10. **入门指南的 G01–G20 是 20 个截图占位，尚未取得。** 草稿描述了从安装到工作台与蝶君的两个文字示例；蝶君自主执行任务另有待测计划，但实际按钮、可用服务、结果和恢复路径都没有逐步验证。**证据：指南草稿和截图计划。** 不可将它当成已验收、可直接给新手执行的正式教程；见 [指南草稿](05-方案-使用说明与入门指南.md)、[截图拍摄清单](加深-08-指南截图拍摄清单.md)。

## 证据与限制：看到什么，不能得出什么

- **用户已定方向**：开放版面向开发者，保留自选渠道和模型组；托管版面向零基础试用者，不自配模型、强制进入作者配置的模型池，费用由作者中转站账户承担；同一代码库按打包区分，两版都需守护测试。这不等于具体服务、交付方式、界面例外、额度或隐私条款已决定。来源：`docs/roadmap.md` v1.0、第二张任务卡。
- **Q0–Q2**：Q0 是只读设计材料摘要；Q1 因 Q-03 的隔离风险**没有启动复制品、没有 DreamFlutter 实机截图或真实首启走查**；Q-02 限制仓库访问为文档与原型，未读源码，故也没有真实按钮全量清单。Q2 的 **30 条**是可能影响及严重度的**待验证假设**，不是已发现缺陷、受影响人数或频率。按潜在影响暂分 10 / 18 / 2，并非真实用户放弃数、卡住数或轻微问题数。
- **Q3**：十款同类客户端及平台引导、文档分类、令牌风险使用公开资料研究，不等于逐个实机试用。平台、组件和版本差异不可合并成统一 tooltip 延迟或长度；上游文档能力不代表用户实际中转实例已配置或验证。[外部调研](03-外部调研.md) 附直接来源。
- **Q4**：HanaAgent 的截图可参考有限的空状态、设置说明和一张「打开面板」提示画面（触发方式未验证）；首次向导、完整悬停覆盖、完整占位轮换和帮助入口没有充分证据，不能当作 DreamFlutter 现状或用户测试结论。[HanaAgent 对照](04-HanaAgent的上手设计.md)。
- **Q5 / Q6**：四份方案和两版本方案均是可供审议的草稿，不是代码或设计的修改；客户端隐藏设置、混淆、加密或安装开关不能强制服务端授权，服务端控制也只能约束受控服务本身，不控制测试者自己的整台电脑。

| **卸载时保留哪些数据** | 核对历史契约中保留模式仍注销沙箱并删除其虚拟磁盘的边界，明确哪些内容应保留、怎样提示和恢复。 | Q-09；真实安装版与两版隔离未实测，须在合成数据环境验收。 |
| **F2 保留数据内容概况来源** | 前端规格要求展示保留数据的内容概况，当前查询接口返回契约只列路径、字节数和保存时间；核实是否另有来源或需要补契约。 | Q-08；不能据文档差异断言实现缺失，恢复重启响应也不等于最终成功。 |
| **恢复本轮缺口的安全路径** | 如何提供经过验证的隔离测试环境；是否允许后续只读应用源码做图标盘点；何时可单独授权真实服务连接和收费验证。 | Q-02/Q-03；先验证不会读取或修改真实全局数据，再做 Q1；未经批准不触碰真实 Key。 |
