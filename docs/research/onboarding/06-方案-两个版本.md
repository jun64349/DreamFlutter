# Q6 方案：开放版与托管版

**建议，尚未据此修改设计、代码、配置或发布。** `docs/roadmap.md` v1.0 已定两个版本的方向：开放版由使用者自由配置渠道和模型组；托管版给零基础测试者，模型使用受项目提供的池约束，费用由项目作者的中转站账户承担。同一套代码打包区分。具体名称、模型、实际中转站、凭据、数据政策及运维机制尚未确定；不能把方向当作已上线服务。本轮没有启动 DreamFlutter 副本、取得 DreamFlutter 截图、登录中转站、查看或填入真实密钥，也未测试费用、隐私或安全能力（见 Q0、Q1、第二卡 Q-02/Q-03）。

依据：`Q0-设计材料与边界.md`、`01-新手走查记录.md`、`02-门槛清单.md`、`03-外部调研.md` 及 `Q3-来源-令牌与风险.md`、`04-HanaAgent的上手设计.md`、Q5 四份方案；项目的 `roadmap.md` v1.0、`design/interaction-design.md` 4.1、`design/model-groups.md`、`design/settled-0.8.3.md` 和 `design/v0.12-frontend-spec.md`。Q2 的 M 编号均为待验证风险假设；Hana 的有限截图不是 DreamFlutter 实测或托管方案证据。界面建议由 Claude 在现有页面与位置设计，**涉及已定型交互、布局或用词时须用户明确决定具体条目；现阶段不修改守护测试期望**。

## 一、版本怎样分、能否共存

| 决策项 | 建议供评估 | 未知、代价与验证 |
|---|---|---|

**卸载保留范围的前置核验：**[历史卸载接口契约](../../api/uninstall.md)称选择保留数据时仍注销该安装登记的沙箱并删除其虚拟磁盘和干净副本；这是契约中的清理流程，并非已验证的成功结果；注销失败会记录残留，磁盘三次删除仍被占用时记录路径，须根据结果与日志核验。安装根外数据、系统 WSL、其他发行版及用户工作区按契约有不同保留边界。不得将“保留我的数据”当成所有沙箱内容均保留。真实安装版卸载当时待验收，test.5 便携包不支持该卸载流程。本轮未做卸载、恢复或双版本隔离测试。未来要用合成数据验证沙箱中哪些内容可恢复、外移数据及另一变体/工作区是否不受影响，差异见任务卡 Q-09。
## 二、托管版界面变化与定型冲突

下表是待 Claude 绘制与用户决定的选项，**不是已获批 UI**。托管版“不允许自配模型”是已定方向，但如何同 0.8.3 的现有定型条款共存并未定。为避免暗示功能已实现，服务商名、价格和入口均用占位，正式文案只能填实际核验结果。

| 位置 | 建议与可选方案 | 定型影响和结论 |
|---|---|---|
| 设置 › 模型：渠道 / 密钥 | 开放版保持现有自由配置。托管版可研究保留位置为只读，展示已核实的「模型由〔服务方待定〕提供」；隐藏、新建不可用或替换卡片是备选。不得仅靠隐藏阻止连接自选服务。 | **可能冲突第 4 条设置布局及第 5 条渠道编辑、固定测试/保存与离开确认**；若不再允许进入或编辑，冲突不能由只读标签消除。须逐条列具体例外让用户定；未决定前现条款不变。 |
| 设置 › 模型：模型组 | 开放版保留用户自建、编辑、排序。托管版可考虑以只读方式展示受限的模型组，或不展示具体配置；由用户在约束内明确选择，而不是声称两版相同。 | **直接涉及第 10 条用户可自建任意模型组、成员和顺序**，隐藏/锁定/仅只读都与其表面规则有冲突；不能自行定例外或改测试。 |
| 初次向导：连接模型 | 开放版按 4.1 的设计保留服务商、密钥与推荐；托管版候选是**以经核实的服务、费用及数据告知和领取/激活流程替代自配模型步骤**。若不需激活如何领取待定，不能承诺“无向导”；数据位置、F2 保留数据选择、称呼、工作区和 B1 蝶君配置不因托管自动消失。 | 4.1 的五步流程被改变，**需要 Claude 设计和用户对具体变化作决定**；不能默认为已获准。F2 的「找回来 / 重新开始」及 B1 性格、主动性、自己做事每天最多花须遵守；真实默认与实现未测。 |
| 输入框模型选择器及各处选模型 | 候选 A：按既有布局只列池内经允许的模型组与渠道模型，并评估池内可选择范围；直接选模型时按定型第 11 条显示完整「模型 · 渠道」，选择组时模型组设计规定按钮显示组名、悬停看当前成员，该组的回复下按第 8 条显示实际「渠道 · 模型」。组按钮与第 11 条文字的适用关系仍须 Claude 与用户核对；候选 B：固定选择并提供解释。 | 两者均需核对 **第 10–11 条**：隐藏“更多模型…”、锁定选择、不能自建或改变模型列表的排序/成员，均可能或直接冲突；固定模型按钮还可能影响第 8 条实际渠道模型显示。**逐项待用户决定**，不能把“只保留外观”当作满足操作规则。 |
| 花费页 | 候选 A 保持现有图表、金额/次数及当前适用数据，清楚区分“作者承担”和“测试者付款”；候选 B 仅显示次数或额度，或隐藏金额。具体怎样计价、是否显示以及数据从哪里来未定。 | A 也须核验事实与账务口径；B **直接碰第 16 条**近 30 天柱状、用途/模型环形图及金额/次数切换；隐藏或替换须用户明确决定。回复下方仍遵守第 8 条，不自行增加花费。 |
| 其他 | 帮助、隐私说明、反馈与激活入口优先研究现有位置；必要知情在请求发生前可见，不将关键信息只放图标悬停或外链。 | 任何新常驻文案、按钮、页面、名称和默认行为要按 v0.12 总规矩及「让布局自己说话」评审；新增设计不由本文批准。 |

两版均保留保护清单其余体验，包括第 1–3 条蝶君对话/侧栏、6–7 条工作区与文件、12–15 条表现；日程和麦克风是已有明确例外，不等于托管版可以新增其他例外。两版都需要能看到真实使用条件和处理失败，而不是默认把费用或数据去向藏起来。

## 三、模型池与路由：尽量复用已有规则

### 建议架构与信任边界

1. 本地按**设计**复用渠道和模型组的抽象，将受支持的用途映射到受控候选组。托管版由发行配置/服务端策略提供候选范围，不让测试者通过应用界面自配模型是目标；如何与第 10–11 条协调见上一节。模型组的成员、渠道、顺序、实际切换规则以 `model-groups.md` 为设计依据，当前实现未经本轮源码或实测核验。
2. 每次远端请求由服务端根据**独立凭据和服务端策略**核验身份、用途、可用模型、权限和额度，映射或拒绝客户端请求；客户端提交的“托管版”标志、模型名、隐藏按钮、本机配置、混淆或加密均不足以强制路由，也不能阻止凭据被持有者复制。假如现有中转站不能执行限制，就需要额外的服务或换用可验证的服务。本轮不声称任何后端已具有该能力。
3. 控制范围要覆盖工作台、蝶君、后台模型、带图、工具相关模型和计划任务等**一切实际会产生托管模型请求的路径**；搜索、语音云端等其他对外服务也要分别盘点，不能假定都走同一网关。是否有本地离线路径、网络阻断和服务端审核须在隔离环境验证。

| 用途 | 池内建议 | 失败或代价 |
|---|---|---|
| 对话 | 待选的主模型与符合成本、时延和质量要求的候选；名称、供应商、地区、单价、上下文和协议均待定。 | 调用前验证允许清单及预算；替换后说明实际可显示的信息，具体 UI 遵守第 8、10–11 条。 |
| 小任务 / 后台用途 | 待选的低成本、足够胜任的候选；要核实后台记忆、整理等用途各自的数据与限额。 | 不以价格推断质量或可处理的内容；错误不能悄悄走未授权模型。 |
| 大任务 | 待选能力与预算上限匹配的候选；长任务的循环次数、单次输入输出和并发都需控制。 | 某型号不可用时仅在被批准的能力和费用范围内选备用；没有可用项就明确失败，不把无限重试当恢复。 |
| 看图 | 待选支持图片的允许模型；只发送用户授权的数据，附件处理政策待定。 | 带图不能落到无图片能力的模型；无合适成员时按设计可转看图模型，但仅限同样获授权的池内模型，否则明确提示。 |
| 语音 | roadmap 10.4 的方向为本地语音识别为默认、云端为高级选项；本地识别**不是托管大语言模型池**，是否随当前包可用未实测。云识别若启用，要单独确定供应商、凭据、音频数据去向、配额、费用与授权。 | 若云语音不受同一服务端限制，不能宣称它受到模型池预算保护；本地模型体积及运行能力待核。 |

**故障与切换：**`model-groups.md` 的定型设计为先同渠道换 Key 再换渠道、订阅优先、对话尽量粘住当前成员、前面恢复后新对话重新从前开始；带图跳过不支持成员，切换时对话内显示提示。模型额度、无效凭据、限流或持续超时可能触发下一受允许成员；用户停止、内容过长或已输出一半则不能简单自动切换。模型组设计的高级选项还允许关闭「订阅用完后转按量付费」：关闭时订阅均不可用应停下询问；同档成员可按比例轮流。托管版若取消这些选择或服务端改变切换语义，须识别与现有组编辑和规则的冲突并交用户决定，白名单本身不能证明行为一致。所有候选失效时说明可核实原因和下一步；托管版若没有“换个模型/去设置”的权利，现有错误卡或按钮是否可变亦涉及第 10–11 条及 4.4，先由用户决定设计，不编造可用恢复入口。具体后台响应与副作用尚未实测。

## 四、凭据与费用安全

### 威胁与推荐边界

将中转站**总 Key**写进安装包、资源、客户端配置或随包后台，接收者可通过查看解包后的资源、静态分析和运行时观察等方式尝试取得；混淆只增加难度。拿到的人可能绕开客户端直接调用、共享或滥用，从作者账户扣费，且难以只封禁一个测试者。OWASP 官方材料讨论移动应用中硬编码敏感数据可恢复；把风险类比至 Windows Flutter/Node 是安全推断，本轮没有逆向任何安装包。[OWASP MASWE-0004](https://mas.owasp.org/MASWE/MASVS-STORAGE/MASWE-0004/)、[Google Cloud API Key 最佳实践](https://docs.cloud.google.com/docs/authentication/api-keys-best-practices)。

**推荐候选：**总 Key 只置于受控服务端；为每个测试者发独立、能逐个吊销和过期的子令牌，或以可撤销的一次性激活凭据换取独立调用凭据。每人至少要有服务端有限额度、模型/能力允许清单、速率与并发限制以及按人归因的使用记录；额外设置整体预算、告警、人工暂停和应急轮换。具体额度、速率、模型、过期时间、运营人与服务实现均待定。独立凭据仍可被复制和共享；要设计遗失、滥用、封禁和恢复流程，不能承诺绝对防刷。

激活码和调用令牌是两种凭据：只把同一永久总 Key 换个名字不安全；一次性兑换必须由服务端执行防重放、失效和撤销策略。客户端只应保存试用者的有限凭据，采用适用系统可用的受保护存储并限制日志输出；但本机持有者有机会提取它，具体保护方案及平台兼容性待验证。

### 区分现成预扣与预算预留

[New API 公开计费设置](https://docs.newapi.ai/zh/docs/guide/feature-guide/system-settings/settings-billing)说输入预扣倍率基于预计输入费用，不预估输出 token，按次和任务计费不受该倍率影响；[计费表达式说明](https://docs.newapi.ai/zh/docs/guide/feature-guide/admin/billing-expression)还描述预扣时输出及其他用量按 0，结算再按实际用量求值、多退少补，求值失败按预扣额结算。估算器不包含请求规则或分组倍率，请求模拟也不包含分组倍率。以上是该公开文档的规则，不证明具体站点的版本和配置一致。

因此，文档中的输入预扣不能直接当作本方案在请求前覆盖最坏输入、输出、模态及并发的**保守预算预留**；提高输入倍率也不证明可覆盖任意输出。需在假服务与授权环境分别验证余额门槛、按次/异步、长输出、表达式失败、分组倍率和对账，再评估是否需要代理及可承受的在途超额风险。本轮未访问实际实例或调用服务。
### 虚构例子：并发、预留与迟到费用

下面全部数字是纸面示例，不是报价或任何现有站点已实现的行为。假设只算模型费用、不计税费汇率，服务端能够以经过验证的原子操作同时管理总预算与在途请求；把暂时为未完成请求留出的额度称为“预留”。预留不是已经付款，也不是供应商保证的最高费用。可用额度按示例规则计算为 **预算 − 已结算费用 − 在途预留**。

1. 假设总预算 10 元，A 和 B 几乎同时到来，分别需要预留 6 元和 4 元。安全确认两笔预留后，可用额度为 `10 − 0 − (6 + 4) = 0 元`；此时即使 C 只需 1 元，也应等待或被拒绝。
2. A 完成，实际花 2 元；其 6 元预留解除，其中 4 元净释放。B 仍预留 4 元，可用为 `10 − 2 − 4 = 4 元`。若 C 需要预留 4 元，可以在同样的原子规则下开始，此后可用又为 `10 − 2 − (4 + 4) = 0 元`。
3. 随后 B 的上游账单迟到，实际花 5 元，比原预留高 1 元。应如实记 B 的 5 元；此时 A、B 已结算 7 元、C 仍预留 4 元，按公式可用为 `10 − 7 − 4 = −1 元`。这是**包含 C 在途预留的预算缺口**，并不等于当前已经实付超出预算；应暂停新增并对账。
4. 若 C 最终实际花 4 元，合计 `2 + 5 + 4 = 11 元`，最终超过原预算 1 元；若 C 最终花 2 元，总费用则为 9 元，未超过预算。不能把超出的真实费用抹掉或因客户端断线就当免费。

现实中价格、可限制的最大用量、并发一致性、上游费用和迟到结果是否可核实都未知；预留、告警和暂停只能在实际机制有效时降低风险，不能保证零超支。具体上游限额、故障处理、日志及费用责任仍须在假服务和获准环境中验证。
### 发放、使用与失效（未来流程草案）

1. **发放前：**先确认具体服务、运营责任、测试者身份和双方约定；在服务端创建每人独立的有限期凭据、限制模型与额度及速率，核验撤销与用量显示，记录发放和失效时间但不记录明文密钥。若无法做到必要控制，暂不发放。分发和身份核验渠道待用户决定，不能声称任何渠道绝对安全。
2. **交给测试者：**通过经用户确认的适当私密方式交付单人激活码或限权凭据，并在发行说明中解释它是个人使用、应妥善保存、遗失时如何联系；不把凭据贴到公开群或反馈表。实际领取及身份流程未定。
3. **首次使用：**若最终选激活方案，在 Claude 和用户确认的已有流程位置输入一次并兑换，成功后安全保存有限凭据；没有实际兑换服务时不能声称“只填一次已经可用”。换设备、丢失、重复激活、离线启动及撤销后凭据是否仍被接受均需设计和验证。
4. **用完、过期、被吊销、连接失败：**建议只显示经服务端核实且不泄漏凭据的原因，以及真实存在的联系/重新领取/稍后重试选项；原因未知时明确说无法确认，不把所有失败都归为额度用尽。是否允许继续使用非模型功能以及恢复位置待设计，不能承诺有服务。
5. **计费控制与对账：**服务端记录假名化或其他受控测试者标识、调用时间、模型、状态、用量和可核实金额；可关联到人的固定标识不能仅因不记姓名就称匿名，须限定访问权限及保留期；不要默认收集正文。周期性与中转站和上游账单核对、处理并发和延迟计费，设置总预算告警及人工停用。有限配额是减小风险的控制，**不能保证零超额或替代上游账单上限**。

## 补充：托管服务的强制边界与定型冲突

- **服务端能约束的范围：**服务端可以验证和限制使用作者付费服务的请求；不能阻止测试者控制的电脑安装或调用其他第三方服务。托管版产品内“不让自配模型”是发行体验方向，服务端强制策略是保护作者账户的边界，二者不可混同。必须针对模型别名、备用 API 端点、其他模态和所有实际调用路径验证白名单与权限，不声称可管住计算机的一切网络访问。
- **第 4–5 条：**把渠道设置藏起来、改为只读或不能测试/保存，可能改变设置布局且会与渠道编辑操作相冲突；是否允许托管版例外由用户逐条决定。只读画面不是证明原有编辑行为仍可用。
- **第 10 条：**托管固定受限模型组与用户可自建任意模型组、选择成员及顺序存在实质冲突；服务端虚拟组或保留类似外观不能解决用户操作权、实际成员和切换语义。无例外决定前不能宣称守护满足。受允许成员切换须保留或经明确决定调整已定型的对话提示；切换状态和实际成员必须真实。
- **第 11 条：**把模型选择器锁定、移除组/渠道或「更多模型…」、截短名称都可能违反既定列表和完整展示规则；即便列表视觉相同，也要核实真实可选成员与可用行为。逐项交用户决定，不自行改测试期望。
- **第 8、16 条：**回复信息行按定型显示模型、输出速度、用时和时间，不显示花费；使用模型组时显示实际「渠道 · 模型」。直接选模型时是否同时显示渠道须另核对适用设计，不能把模型组条件泛化。花费页须保持已定型图表和金额/次数切换。建议服务端提供可核实的实际执行渠道、模型、切换事件及计费依据；元数据不足时记未知，并逐项评估是否妨碍满足适用的定型要求与真实计费，不能用虚拟组名或客户端请求值冒充实际。只显示次数、假设费率、隐去模型组真实渠道或移除图表均不能视作已满足；托管方想改变这些内容，逐条交用户决定。

## 补充：限额和凭据的实现验收条件

以下均为**待设计、待验证的方案要求**，不代表选定系统或当前实例已支持：

1. **预算预留和最终对账：**按每个身份及全局预算在服务端进行并发一致的原子检查与在途预留，按允许的各上游可信价格上限、最大输入/上下文、输出长度、附件、缓存计费、重试次数和支持模态计算风险；价格、模态或授权未知，以及账本、共享计数或可信价格表不可用时拒绝或暂停新请求，不得借后结算或备用路径绕开预算。上游账户另设独立限额/熔断和告警，逐笔对账；即使采取这些措施，已在途请求、计费延迟或上游规则仍有剩余超支风险。
2. **恢复与防重复：**分别测试超时重试、重复请求、流式断开、异步任务、服务宕机及恢复，设计幂等键、预留释放与补结算，验证失败时不会重复扣减、漏算或产生无限重试。最终账务取实际合同、上游账单及验证结果，不能承诺零超支。
3. **兑换与失效：**一次性码也可被复制或抢先兑换；兑换操作需要原子防重放、有限有效期、逐个撤销和补发，建立失窃后的冻结与处置流程。个人令牌泄露需撤销该人的凭据、停用相关激活码并评估补发；总 Key 泄露还需暂停关联入口、上游撤销或轮换、评估并限制在途请求、核账并验证旧凭据被拒。调用令牌撤销后新请求及**已有流**分别何时受影响需要验证，不能断言立即终止。
4. **跨人隔离：**验证 A 未取得 B 凭据时不能查 B 的额度、用量、日志或凭据；若 A 已持有 B 的 bearer token，不能保证识别冒用者。验证多账号/多令牌、分布式部署时的共享计数、模型别名与多端点绕过。New API [令牌文档](https://docs.newapi.ai/zh/docs/guide/feature-guide/user/token) 所述「允许查询用户额度」默认为开启；多人共用账户时可能暴露账户额度，部署前应按具体版本关闭或隔离，并通过接口和日志验证，不能仅依赖界面状态。
5. **文档时效：**上文所引预消费说明所在 `new-api-docs` 仓库已于 2025-12-01 归档，属于历史官方文档，不能断言现用版本总是预扣；当前计费页面正文描述满足钱包与有限额令牌余额门槛可跳过预扣，订阅和异步任务始终预扣；正文以普通只读 HTTP 获取，网页读取工具仍不可访问。部署版本、具体配置及异常场景须独立核实。
