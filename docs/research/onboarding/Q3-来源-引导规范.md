## 1. Tooltip：不同平台，不要混用数值

| 来源 / 适用范围 | 页面明确支持的内容 | 本次没查到或不能推出 |
|---|---|---|
| [Microsoft Windows App SDK / WinUI 工具提示](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/tooltips) | 工具提示由指针悬停、焦点或长按等交互触发，辅助信息应简短；没有文字标签的图标工具栏/命令按钮需要提示；已有明显文字或重复内容不必再提示。关键任务所需信息应直接可发现；错误、警告、状态和需要交互的内容应使用其他合适控件。自定义提示要包含可用的键盘快捷键；不要把交互控件放进这个普通 tooltip。 | 该页面未给出一个适用于所有 Windows 产品的统一最大字数或悬停延迟。上述规则特指该页面的普通 WinUI tooltip，不能推断所有富提示都禁止交互。 |
| [Microsoft 基本无障碍信息](https://learn.microsoft.com/en-us/windows/apps/design/accessibility/basic-accessibility-information) | 对纯图像按钮等控件提供可被辅助技术读取的名称。 | 这是 WinUI/XAML 指导，不证明 Flutter 产品已经具备名称或通过读屏验证。 |

| [Apple UIKit：help tags / tooltip interactions](https://developer.apple.com/documentation/uikit/showing-help-tags-for-views-and-controls-using-tooltip-interactions) | 该 macOS 12+ 示例描述指针停留数秒后显示、数秒后或指针离开时消失。 | “数秒”不是确切毫秒值，也不是所有 Apple 系统或 DreamFlutter 的延迟。 |
| [Material 3 / Android Compose tooltip](https://developer.android.com/develop/ui/compose/components/tooltip) | 区分 plain tooltip（简述图标/动作）与 rich tooltip（更多背景，可含标题、链接或按钮）；示例按设备支持悬停或长按。 | 这是 Android Compose 组件说明，不证明 Flutter 桌面有相同行为；所查页面未给出适用于所有 Material 3 的固定字数、键盘快捷键格式或统一悬停延迟。官方 [Material 3 网页](https://m3.material.io/components/tooltips/guidelines) 此次工具仅返回需 JavaScript，未能直接读取完整正文；不能补造其数字。 |
| [Flutter `Tooltip.waitDuration`](https://api.flutter.dev/flutter/material/Tooltip/waitDuration.html) | API 文档称该属性表示指针悬停多久后显示，属性默认值为 0 毫秒。 | 这是 Flutter API 文档里的属性默认，不是 Material 3 通用设计规范，不证明项目未设置主题/组件覆盖值；本轮没有读取 `app/lib`，实际项目延迟未知。 |
| [W3C WCAG 2.2：1.4.13 悬停或焦点内容](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus) | 对满足适用条件的自定义悬停/焦点附加内容，要求可关闭、指针可移入、持续可见，标准列有例外；键盘可操作还需结合相关准则。 | 这是 Web 无障碍准则，Flutter Windows 桌面不是自动因此证明合规；应把它作为可访问设计检查依据，并依实际技术与适用范围做评估。原生浏览器 `title` 等由用户代理完全控制的情况有不同适用说明。 |

**项目适用推断，待 Claude/用户决定**：图标控件优先提供短而明确的动作名，并保证键盘焦点、读屏与适当的触控替代；关键的费用、隐私、权限和不可逆后果不能只藏在悬停提示里。提示可放在需要时出现的位置，符合“让布局自己说话”的方向；具体文案、出现时机、延迟和样式仍须在现有设计约束下测试，不能把任何外部组件的参数当成本项目已批准规范。已定型交互、布局、用词若需变化必须由用户明确决定。

## 3. Diátaxis：帮助内容按需求组织

Diátaxis 把文档需求分为四类，组织形式可按实际项目调整，而不是要求四类都成为常驻界面入口：

| 类别 | 来源支持的定义 | DreamFlutter 文档结构示例（建议，非已实现） |
|---|---|---|
| 教程 Tutorial | [Tutorials](https://diataxis.fr/tutorials/) 面向学习，通过有意义且可完成的实践带人获得能力。 | 安全准备好之后，从第一次使用工作台到得到结果的入门教程；涉及真实模型请求、权限和可能费用要先说明。 |
| 操作指南 How-to | [How-to guides](https://diataxis.fr/how-to-guides/) 围绕具体目标或问题，帮助读者完成现实任务。 | 如何更换工作区、如何处理连接失败、如何理解一次审批。 |
| 参考 Reference | [Reference](https://diataxis.fr/reference/) 提供结构化、准确、便于查询的产品或技术事实。 | 设置项、状态和快捷键表；只收已验证的当前行为。 |
| 解释 Explanation | [Explanation](https://diataxis.fr/explanation/) 给出概念、背景与关联，帮助理解。 | 解释工作台与蝶君、工作区、渠道和模型组、数据路径与服务的区别。 |

**应用内与在线的取舍（本项目推断）**：应用内保留关键任务的简短说明和可发现入口，可在离线时提供基本帮助；较长教程和参考可维护为随包文档/在线文档。在线链接依赖网络和持续维护，随包文档可能随版本过期；不能在本轮保证任何一种已实现、已同步或离线可用。实际位置须符合现有页面结构及用户对定型体验的要求。

## 4. 未核实事项与下一步

- 各平台和语言中最合适的提示长度、延迟、焦点/长按行为，需要对 DreamFlutter 自身实现和目标用户测试；本轮不读取仓库 `app/lib`，没有进行真实悬停、焦点或无障碍测试。
- “多数人跳过 tour”“某种引导提高完成率”等普遍效果和量化结论未在此次官方资料中找到；不作为事实写进方案。是否需要清单/示例/教程，应在安全隔离环境中用真实任务与目标用户验证。
- 以上资料给出设计选项，不替代当前仓库的已定型约束，也不证明费用提示、权限说明、数据保护或托管服务已实现。

## 补充：Windows 教学提示组件（公开资料）

2026-11-14 只读 [Microsoft WinUI Teaching tip](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/dialogs-and-flyouts/teaching-tip)：该组件用于简短情境教学，可按配置轻触外部关闭或显式关闭；文档指出它是非永久的提示，不推荐用于错误或重要状态变化；官方建议这类提示不包含对应用体验至关重要的信息或选项。文档还描述打开时从显式关闭切换为轻触外部关闭可能使提示滞留的特定组件风险。

**对本项目的推论，尚未设计或测试：**若将来使用类似短暂提示，应分别验证可关闭性、焦点和无法正确放置时的退路；费用、权限、数据去向、错误和关键状态须有与实际流程相符、可再次找到的说明，不能只放在短暂提示中。WinUI 的具体属性、默认值和实现风险不能直接套到 Flutter，不能由此断定 DreamFlutter 已有该控件或任何现状；无需增加常驻说明行，具体位置仍由 Claude 按定型规则设计。
