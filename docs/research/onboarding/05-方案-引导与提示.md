## 2. 悬停提示规则（待设计评审）

1. **覆盖条件。** 对没有可见文字且仅靠图标不能可靠表达动作的按钮，提供明确名称及按需短提示，优先覆盖会关闭、停止、删除等后果不同的按钮；可见文本已经说明动作时通常不重复。信息状态或开关应暴露状态，而不把它伪装成另一个动作。是否覆盖禁用按钮需针对无障碍框架验证：不能要求不可聚焦控件承担唯一的错误原因，应在原有附近状态位置说明。
2. **文案。** 首选动词加对象，如「添加文件」「查看后台任务输出」。建议中文主体尽量 12 个字以内，复杂对象可适当超过，不硬截断关键信息；状态变化分别写动作，避免只写「更多」却隐瞒危险操作。12 字是本方案的设计目标，**不是** Fluent、Apple 或 Material 统一标准。快捷键只写经过项目文档及实现验证的组合，例「发送（Enter）」；输入法组合输入需遵守实际实现。尚未核对之前不追加快捷键，不从其他软件复制。旧原型 1188 行演示 Enter 发送及输入法组合限制；这只证明原型，不证明候选包实现，发版前须核验。
3. **出现与消失。** 建议首轮评估鼠标悬停约 300 ms 后显示，键盘聚焦也能获得等价名称和说明；移到提示区域可保持、离开或失焦后消失，Esc 关闭可关闭的浮层，文本不遮挡控件。300 ms 是受 Q3 中 Fluent React 某组件启发的**实验参数**，不是 Windows/Flutter 要求或本机实测；`interaction-design.md` 5.4 节的约 150 ms 是悬停等**动效时长**，不是出现等待。与原有组件/系统行为冲突时先核实，不能为了统一擅改已定型交互。
4. **视觉。** 沿用 `design-language.md` 第 1 节主题颜色、字体和圆角，夜间使用当前深色主题语义色，不硬编码黑白；让文字与背景有足够对比，日夜两套和放大显示实测，必要时复用项目既有设计 token。无障碍名称不是鼠标悬停的等价实现；须分别验证并记录鼠标悬停、键盘焦点和关闭、读屏名称与状态，以及目标设备支持时的触屏替代；不支持或未测试分别标明，不能由一项推及全部。按需说明不得成为唯一操作线索。
5. **例外与验证。** 图表悬停内容已有定型第 16 条，不改现有图表含义和表现；回复信息第 8 条、模型组与渠道分段、常用模型、「更多模型…」及完整模型名的第 11 条也不能被改动；按钮显隐另需核实现行体验。逐状态测试打开/关闭、录音/停止、删除与后台任务停止，避免文案误导。具体实现、可访问性和是否符合 WCAG 不能从本文推断。依据和平台边界见 [Q3 规范来源](Q3-来源-引导规范.md)：WinUI 普通 tooltip 不含交互控件，Material 3 富提示是不同组件；Apple 60–75 字符建议不等于中文固定字数。
