# 加深：托管版预算、隔离与撤销的验证方案

**研究方案，未部署、未调用、未验证任何真实站点或凭据。** 本文把 [两版本方案](06-方案-两个版本.md) 中的风险转成将来可执行的测试条件；具体服务、价格、模型、额度、数据处理及运营责任均待用户决定。测试须另有隔离环境和对应授权，不要求在本轮登录、发放 Key、提交请求、创建账号或搭服务。此处的“通过条件”是未来目标，不是当前测试结果。

## 边界和成功条件

- 目标是限制**作者付费的受控服务**：验证试用者身份、所允许的模型与端点、个人及总预算、速率/并发、有效期和撤销。用户控制自己的电脑仍可使用其他服务；本方案不能承诺封住整台电脑的一切外部连接。
- 独立令牌有助于按人限制和撤销，但持有人仍可能复制它。主 Key 仅留受控服务端；一次性激活码和调用凭据是不同对象，前者也可能被抢先兑换。客户端隐藏设置、编译开关和混淆不构成服务端安全控制。[OWASP](https://mas.owasp.org/MASWE/MASVS-STORAGE/MASWE-0004/)、[Google Cloud](https://docs.cloud.google.com/docs/authentication/api-keys-best-practices)。
- [New API 文档](https://docs.newapi.ai/zh/docs/guide/feature-guide/user/token)描述部分令牌配置，但实际实例、版本、权限和默认值须核实；令牌查询账户额度可能暴露共享账户信息，用户级限速不必然是每令牌限速。旧的预消费说明所在仓库已归档；当前系统的预扣及结算行为不可据历史文档断定。详见 [来源与风险](Q3-来源-令牌与风险.md)。
- 关键安全能力若无法证明：**不发放试用凭据或暂停新增请求**，先补能力、调整服务或重新限定测试。个人额度、总额度、供应商真实账单与作者实际风险应分开说明；不能保证在途请求、延迟计费、汇率/价格变更或异步任务导致的绝对零超支。

## 未来的请求与预算状态（设计候选）

1. **未激活 / 已激活 / 冻结 / 过期 / 撤销**：服务端保存可关联单人的授权状态、有效期及模型能力白名单；客户端只持有限权凭据。一次性码以服务端原子操作兑换并失效，重复或并发兑换应拒绝；换设备、补发及丢失处理须明确定义。
2. **接收请求**：认证并核对身份、版本无关的服务端策略、模型别名实际映射、端点和模态；验证必要的输入、附件、上下文、输出及重试上限。不得信任客户端声称的版本、用途或预计花费。
3. **预留**：根据各允许上游的可信价格与最坏输入/输出/附件/缓存/重试条件，计算保守预留；个人和全局额度及并发计数应在具备一致性保障的服务端原子判断、登记在途预留。价格/身份/计数/账本不可用或上限不可算时停止新增请求，不能把未知价格当 0；这是一种候选设计，并非现有中转站已支持。
4. **执行与结算**：只在受控服务转发到被允许的上游；建议在服务端内部记录必要的实际执行渠道、模型及可核实计量依据，供账务和适用的定型规则对照；内部记录与模型组回复行要求显示实际「渠道 · 模型」是不同层次。完成后幂等结算并释放未用预留；中断、超时和崩溃时按已验证策略对账与恢复，不擅自假定上游未计费。
5. **预算耗尽 / 停用**：拒绝新请求并提供已实现的可理解恢复路径；是否显示数额、支持联系方式、处理中流如何结束需用户决定。全局紧急暂停、供应商账户上限和告警是额外防线；告警本身不是硬限额。

上面是对风险的设计推演。若实际站点无法公开可信的单次最大成本、实时计费、原子额度或全局硬上限，必须把不足和可承受损失明确列出；需要额外薄代理时，其性能、可用性、数据处理、部署、审计和运维成本应一并估算。

### 账本不变量与不确定账单

需要先约定货币最小单位、费率版本、舍入、可退款项和账务调整，再验证：每个受控请求只有一笔有效预留、同一结算版本只生效一次；按约定口径，个人和全局可用额 = 上限 − 已结算 − 有效预留（调整和退款另有明确方向及幂等规则）。结算与释放应原子转移，不能重复释放、产生未定义或不平衡的账务记录，或把上游结果未知当作未计费；退款、冲正及超额按约定方向分别入账并允许如实表达欠额；迟到成功与超时补偿竞争、节点在落账前后崩溃、重复回调和重复退款均须单独覆盖。若上游最终费用超过保守预留，必须如实记账、暂停新增并披露残余超额风险，不能以内部余额上限抹掉真实费用。跨节点原子性是否可实现取决于实际技术方案，本轮未测试。
### 断线和迟到账单：虚构算例

假设总额度 100 点，仅用于纸面说明；服务端能够原子预留、按请求和结算版本幂等处理。这些是**候选目标，并非已经验证的能力**。

1. 请求 A 预留 40 点，已结算 0、在途预留 40，可用 `100 − 0 − 40 = 60`。客户端超时但上游结果未知时，不能把费用当作 0；按该候选策略暂保留预留并对账，同键重试不盲目另发上游请求。
2. 若策略允许、且用户已明确授权另一个独立请求 B，B 再预留 30，合计预留 70、可用 30；若该策略要求在 A 未知时暂停相应新调用，则 B 不应发生。B 确认费用 22，原子结算并释放其预留后，已结算 22、仅 A 预留 40，可用 `100 − 22 − 40 = 38`。
3. B 的重复回调不应再次结算或释放；若 A 迟到结果确认为 18，已结算 `22 + 18 = 40`、无在途预留、可用 60。超时补偿和迟到成功不能各自释放同一笔预留；重复 A 回调不得再加一次 18。
4. 作为第 3 步中 A 最终费用为 18 的另一互斥情形，若 A 最终实际被上游计费 90、B 为 22（不是先结 18 再加 90），则真实总费用 112、按示例公式可用 `100 − 112 = −12`；应如实记录缺口、暂停新增并对账，不能把 90 改记为 40。假设不证明上游支持幂等或只执行一次；无键、过期键、退款和无法查明结果时如何恢复仍待确定。
## 隔离测试矩阵（设计，不是执行记录）

| 编号 | 测试输入或故障 | 期望观察 / 必须单独核实的边界 |
|---|---|---|
| S01 身份 | 两个合成身份各有独立限权凭据 | A 在未持有 B 凭据时不能读取、代用或越权访问 B 的额度、日志或请求记录；若已取得 B 的 bearer token，通常可冒用直至撤销，不能保证识别借用者。检查接口而非仅看 UI。 |
| S02 权限 | 改模型名、别名、用途、模态或不同 API 端点直接请求 | 不在服务端允许清单的目标均被拒绝；测试所有实际出站路径，含后台小任务、带图与长任务。 |
| S03 发放默认值 | 用模拟站点按发放流程配置凭据 | 检查有限额度、到期、模型/端点限制和额度查询权限，不依赖站点默认值；多人共用账户时额外验证跨人查询。 |
| S04 激活重复 | 同一个短期激活码顺序与并发兑换 | 按选定规则只能兑换一次，失效与补发有记录；抢先取得码者仍可能兑换，不能宣称防复制。 |
| S05 过期与撤销 | 过期、人工撤销、禁用后发新请求 | 新请求按验证过的生效时延拒绝；已有流如何处理独立测试，不预先承诺即时终止。 |
| S06 个人预算 | 设一个模拟小额度，连续发送估算金额不同的假请求 | 授权、预留、结算、退还和剩余额度前后一致；未知价格或不支持的模态不按零元放行。 |
| S07 并发竞态 | 两次请求分别低于但合计高于剩余预算 | 在验证过的一致性条件下拒绝超额组合；跨节点、并发增大、时钟变化和重试重复执行。 |
| S08 全局预算 | 多个身份同时请求，合计逼近总预算 | 个人额度足够也不能越过全局限制；上游账单与在途风险单列，不能把内部拒绝当上游零超支保证。 |
| S09 限速隔离 | 单人多个令牌、多人共用账户、NAT、多个代理节点 | 测计数粒度与共享存储故障；IP 限速是补充，可能误伤共网用户且不能替代身份/令牌限速；若无可验证身份约束，无法保证同一自然人不会以多个账号绕过按人限额。 |
| S10 流式断线 | 客户端断连、服务中断、供应商仍在处理 | 已输出量、上游已计费用量、在途预留及最终退款/结算可追踪；不能假定断线即免费。 |
| S11 超时与重放 | 同一操作的网络重试、重复幂等标识、无标识重发 | 在受控有效期内，同主体、同幂等键及相同请求指纹按约定在代理侧去重；相同键不同内容应拒绝或明确冲突。用支持与不支持上游幂等的假服务分别计数；上游结果未知时阻止盲重试并保留未知，不能凭代理去重声称上游恰好执行一次。无键或键过期的重发可能是新请求并产生费用，须对账。 |
| S12 宕机与恢复 | 预留后进程退出、节点重启、共享计数暂不可达 | 新请求按故障策略拒绝或暂停；恢复后能区分未完成、未知结果与已结算，避免丢预留、重复结算。 |
| S13 异步/多模态 | 模拟图片、音频及异步请求，价格和用量上报延迟 | 独立核验允许的模态、附件、价格与计量；不把本地语音识别自动归为同一远端模型池。 |
| S14 价格变化 | 供应商价格/倍率变化，或缺少可信费率 | 覆盖价格表版本切换、陈旧费率、下游隐藏倍率及请求发出后涨价；未确认前暂停新增受影响请求，分列可控损失与上游在途风险，记录货币、汇率、税费和四舍五入口径；另用假服务区分系统按预计输入的预扣与本方案最坏输入/输出预留，覆盖输出远大于输入、按次/异步、表达式结算失败和分组倍率。 |
| S15 路由回退 | 池中模型故障、超时、内容过长、用户停止、已流出部分内容 | 遵守现行模型组设计：用户停止或已输出一半不自动换；过长先整理上下文再用原模型。托管策略若冲突须用户明确决定，真实渠道/模型和切换提示需可信元数据。 |
| S16 虚拟模型欺骗 | 上游内部改写模型或代理二次回退但只返回虚拟别名 | 不能将客户端请求名冒充实际执行成员；渠道、模型或计费依据不可获得时记未知并评估本方案的账务和透明度风险。使用模型组时若无法证实实际成员，另记定型第 8 条的风险；不能一概要求非模型组回复行显示内部每层上游渠道。 |
| S17 个人泄露 | 模拟单个测试者令牌或激活码泄露 | 可只撤销该人、暂停/重发有关激活，调查脱敏账务；其他人是否可继续须根据实际风险判断。 |
| S18 主 Key 泄露 | 模拟服务端总凭据泄露 | 暂停相关入口、上游撤销或轮换、控制在途风险并核账；恢复前验证旧凭据被拒，不能保证已在途调用立即消失。 |
| S19 日志与诊断 | 令牌、请求头、正文、附件、路径、错误堆栈注入合成敏感标记 | 日志、监控、报错、导出、URL 和支持材料不得泄露凭据；对合成正文、附件、路径和堆栈标记分别核实何处允许记录、访问者、保留期和删除责任。诊断白名单及预览是否实现必须实测，不能笼统承诺所有内容从不记录。 |
| S20 数据生命周期 | 模拟试用者拒绝、退出、撤销授权及按约删除 | 逐处理方核对正文/附件/音频、日志、缓存、服务端备份副本及下游的实际访问、保留与删除责任；这些副本与客户端用户导出的备份包是不同范围；不可完成删除的副本或未知期限分别记录，不能承诺已清除。 |
| S21 已定型守护 | 开放与托管构建分别执行已有守护测试 | 不改断言掩盖冲突；逐条检查具体方案对第 4、5、8、10、11、16 条的潜在或直接冲突；需要改变已定型条目时由用户明确决定具体例外。 |
| S22 文案和知情 | 请求前展示经过核实的服务方、数据去向、费用/额度和退出路径 | 分别核验可见信息与实际配置/政策一致、拒绝后的行为；用户是否理解需事先设计任务和问题并由真实用户研究验证，未招募时记未验证。不能把必要信息只放在悬停或外链，也不能把一次观察推广为所有人都理解。 |

### 额外路由与账本边界用例

- **S23 模型组顺序**：模拟同渠道多个健康/失效 Key、订阅与按量成员、限流重试和可恢复成员；核对先同渠道换 Key，再换渠道，订阅优先、同一对话黏住成员，前面恢复后旧对话不回切而新对话从首个可用成员开始。具体恢复条件与服务端白名单共同验证，不能把虚拟组包装当成用户自建能力。
- **S24 看图与切换提示**：带图时跳过无图能力成员；仅在授权池内选择合适看图模型，没有合适成员时明确失败。模型组成员切换时按既定规则出提示；服务端在同一已知成员内部的二次路由是否构成对话层成员切换，须结合结构和可验证事实判断。内部路由不可追踪记作本方案的透明度/账务风险，不伪造实际成员；模型组实际成员不可证实时另评估定型要求。
- **S25 重复结算与迟到结果**：以同请求的重复回调、重复退款、超时补偿与迟到成功并发、落账前后崩溃和恢复组合，验证唯一预留、幂等结算、释放和余额不变量；不依赖没有幂等键的调用天然去重。
### 补充的授权、并发与隐私边界用例

- **S26 在途时撤销、过期或冻结**：模拟流进行时撤销、到期和紧急冻结，分别观察已有流、之后的新请求、上游执行和最终对账。先确定产品政策再验证其实现；不预设撤销可立即中断上游或免除已产生费用。
- **S27 并发数限制**：设置合成用户和全局的在途上限 N，分别达到 N 后发起新请求，确认拒绝或排队符合政策；先定义 N 统计代理请求还是上游实际运行，以及确认结束、租约和故障策略；请求结束、超时、崩溃与取消后按已定策略及证据检查计数，未知在途状态保守保留或隔离。并发槽和未知账单预留分别处理，多节点失联时按安全策略处理。并发个数限制与 S07 的预算原子性、S09 的速率是不同约束。
- **S28 模型组高级规则**：订阅不可用时，分别验证允许和关闭转按量的选项；关闭时按设计停下询问，允许时仍受实际授权与额度约束。对同档按比例选择使用足够样本和事先确定的统计容差，不能要求每次机械轮流；与服务端白名单冲突时记录为待用户决定。
- **S29 合成凭据扫描**：在独立测试服务端应持有主凭据的位置放入假值作为合成哨兵，仅扫描经授权的隔离构建产物、配置、调试符号、日志和受控崩溃转储，并用单独的可控阳性样本证明扫描能检出；另外验证限权凭据的系统存储、权限与清理。测试不能证明所有秘密都不存在，也不能保证设备所有者无法提取本机凭据；本轮未读取实际包内容或凭据。
- **S30 反馈与额外遥测同意**：用隔离服务和合成内容观察未选择、拒绝或取消反馈时是否有额外上报；主动确认后只发送预览和政策允许的内容，并区分完成正常服务必需的数据流。对每种构建和网络故障重试分别检查；不接真实服务。
- **S31 用户主动取消与结算**：模拟用户停止与上游完成并发，核实是否依已定政策传递取消、取消已接收并生效后不再发起新回退调用；对取消之前已发出的在途请求逐笔追踪并正确记录用量和迟到结果，并避免重复释放预留；上游可能继续处理或计费，不能承诺取消即零费用。

### S14 / S25 / S26：部署方案确定后的补充验证

- **配置跨节点和保存边界：**若以后选用相应 New API 版本及多节点功能，在假服务中模拟配置收紧后各节点的新旧版本并存、节点离线、同步延迟和保存中途失败；在控制新请求的条件下核验目标配置已到达全部相关节点，再按策略恢复，另核算已在途请求。官方[系统设置说明](https://docs.newapi.ai/zh/docs/guide/feature-guide/system-settings/system-setting)描述对于共享同一主数据库、且不属于需重启例外的相关系统设置，保存节点立即更新、其他节点按 `SYNC_FREQUENCY` 周期同步（文档默认 60 秒），但仅是该文档的条件和默认值，不是本项目实测或保证。保存规则依设置域而异：逐项保存的部分字段失败不回滚已提交项；请求策略每个分区分别对本次变更整体校验并事务保存，无版本冲突检测、后保存覆盖先保存；计费与支付中“模型定价”的模型价格批量事务保存且检测版本冲突，跨分区不构成同一个事务。应分别模拟，不把全部设置当成同一种保存方式。
- **订阅作废与删除：**若未来使用相应订阅功能，只在假站点模拟请求或异步任务仍在途时作废与删除、迟到结算和重复回调，分别核查新请求、待结算记录、退款及人工对账。官方[用户管理说明](https://docs.newapi.ai/zh/docs/guide/feature-guide/admin/user)称作废保留记录、在途结算或退款通常仍可按订阅 ID 完成，删除记录后按 ID 查询可能失败，结算或退款也可能无法完成；两种操作本身均不自动退款。本轮没有运行服务或删除记录，不能承诺任何版本的实际行为。
