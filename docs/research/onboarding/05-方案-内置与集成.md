## 待选与验证顺序

1. 先核实现包的组成和功能，但须先解决 Q-03 的副本隔离；在获准的干净环境分别验证首启、沙箱准备、真实文件权限、失败和恢复，不读取用户凭据。相关 M 项仍为假设，结果可能推翻本表。
2. 核对已定的 Git 随包和办公库推荐档在现包中的状态；若拟更改，再请用户决定。与用户及 Claude 确定转换范围，以及托管搜索/语音是否在模型池之外另供；分别记录服务提供者、付费、数据去向、访问与故障责任。禁止把模型池主密钥打入客户端。
3. 打包前后用同一基线记录压缩包、安装后逻辑文件、实际磁盘分配、沙箱镜像及缓存；先扣除已有共享依赖，记录依赖许可证和版本，再进行离线及功能验证。每次版本升级重新评估许可证、模型条款与安全补丁。
4. 任何涉及定型第 4–11、16 条等已保护表现的调整，应逐项标明并由用户明确决定；保持原有守护测试期望和大小窗口、日夜主题验收。全文为**建议，尚未据此修改设计**。
