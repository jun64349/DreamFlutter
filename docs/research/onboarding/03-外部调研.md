## 引导与说明：可借鉴，需针对本项目验证

- 渐进披露：将少用的高级内容收起，不把常用任务和关键费用、权限、数据去向藏起来；参考 [Microsoft Windows 桌面 UX](https://learn.microsoft.com/en-us/windows/win32/uxguide/top-violations)（Windows 7 时代的旧原则参考，非当前视觉规范）和 [Apple Layout](https://developer.apple.com/design/human-interface-guidelines/layout)。这是设计推断，不代表可以改已定型界面。
- 空状态可给出情境化下一步，避免重复标题及过多操作；示例能否编辑、是否会立即发送、真实帮助程度均待测试。[Atlassian Empty state](https://atlassian.design/foundations/content/designing-messages/empty-state)。
- 清单可帮助记住必要设置，但可能增加界面负担；要比较可跳过和可重新找到的方式，而不把清单等同于全部配置。[Business Central Checklist](https://learn.microsoft.com/en-us/dynamics365/business-central/dev-itpro/administration/onboarding-checklist)。
- 导览可演示动作，代价是打断当前任务；可探索按需、短、可跳过且可重开的独立导览；需要相关功能时按需提供情境帮助，是否主动出现和具体时机须另行设计并验证。[Apple Onboarding](https://developer.apple.com/design/human-interface-guidelines/onboarding)、[Microsoft Teaching tips](https://learn.microsoft.com/en-us/dynamics365/business-central/dev-itpro/administration/onboarding-teaching-tips-tours)。本轮没有查到足以支持“很多人跳过”的统计数据，不把它写成已证实事实。
- Tooltip：无文字的图标动作应有简短提示，并提供可供辅助技术读取的名称；[Microsoft 基本无障碍信息](https://learn.microsoft.com/en-us/windows/apps/design/accessibility/basic-accessibility-information)讨论图像按钮名称，这是 WinUI/XAML 指导，不证明 Flutter 当前实现合规。已有文字不必重复，关键警告不能只藏在 tooltip；Windows 普通 tooltip 不放交互控件，可包含可用快捷键。[Microsoft WinUI](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/tooltips)。[Apple HIG](https://developer.apple.com/design/human-interface-guidelines/offering-help)建议简短、针对控件动作，约 60–75 字符是 Apple 语境，不是中文限制。[Android Material 3](https://developer.android.com/develop/ui/compose/components/tooltip)区分可含按钮的富提示，不能套用为 Windows 普通提示。Flutter 属性默认值、React 的延迟各有组件范围，实际项目值未查；键盘焦点及相关可关闭、可悬停和持续可见条件参考 [WCAG 2.2](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus)，具体适用范围须核实。逐项详见 [规范来源](Q3-来源-引导规范.md)。
- 文档按读者任务区分[教程](https://diataxis.fr/tutorials/)、[操作指南](https://diataxis.fr/how-to-guides/)、[参考](https://diataxis.fr/reference/)和[解释](https://diataxis.fr/explanation/)。应用内短帮助易在情境中找到；随包内容可离线但可能过时；在线文档易更新但依赖网络和维护。这些取舍是项目推断，入口尚未批准。

## 帮测试者付费：服务端约束才是边界

打包进客户端的固定总 Key 可能被接收者从程序资源、配置或代码中提取，造成未授权调用和费用；[OWASP 移动应用硬编码凭据说明](https://mas.owasp.org/MASWE/MASVS-STORAGE/MASWE-0004/)可支持此类威胁假设，迁移到 Windows Flutter/Node 是安全推断，本次没有逆向或检查真实凭据。[Google API key 建议](https://docs.cloud.google.com/docs/authentication/api-keys-best-practices)主张服务端加密钥、限制、监测和轮换。

建议以后评估每人独立、可撤销、有限额度、到期及模型白名单的凭据，并按身份或凭据限速与看用量；激活码必须有服务端一次性兑换和撤销机制，不能只是共享的永久口令。[New API 令牌文档](https://docs.newapi.ai/zh/docs/guide/feature-guide/user/token)列出配额、有效期、模型/IP 限制等，但其上游文档写明无限额度可能默认开启；[限流说明](https://docs.newapi.ai/zh/docs/guide/feature-guide/system-settings/settings-security)的网页读取工具失败，随后普通只读 HTTP 获取正文；文档描述模型请求按用户、部分路由按 IP、搜索按用户，不能假定每令牌独立限速，实例仍须核验。[One API 项目说明](https://github.com/songquanpeng/one-api)也列令牌控制，但两个项目及实际部署不可混同。若现有服务无法执行必要限制，才评估薄代理，并计入运维、故障、数据与费用责任。官方密钥页还描述令牌查询账户额度权限，默认和账户隔离需逐项核实，避免泄露其他人或账户的用量；历史预扣文档的仓库已归档，当前版本与预扣条件必须另核。配额对并发或异常的硬上限须实测；见 [来源与风险](Q3-来源-令牌与风险.md)。

实际中转站、版本、权限、日志保留和费用上限均未知；没有访问账户或测试真实接口。对话经过哪些服务、保存多久和谁可访问必须依据实际配置告知，不能承诺未证实的隐私性质。以上均为方案输入，不是已实现能力。
