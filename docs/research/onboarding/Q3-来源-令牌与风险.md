# Q3 官方来源：令牌、成本和隐私边界

检索日期：2026-11-14（Asia/Taipei）。只读公开文档，未登录、注册、部署、测试接口或获取、复制任何真实密钥。下述上游项目是公开参考，**不证明用户实际中转站使用了其中某个系统、版本或开放了这些管理权限**。实施前需由用户确认服务和版本，并在不使用真实敏感数据的隔离环境中验证。

## 客户端密钥与信任边界

- [OWASP MASWE-0004：应用包中的硬编码敏感数据](https://mas.owasp.org/MASWE/MASVS-STORAGE/MASWE-0004/) 说明应用包内代码、资源和配置中的固定密钥可被包的接收者恢复；混淆只提高门槛，不能替代服务端保护。该材料以移动应用为背景；**对 Windows Flutter、Node 打包程序也应采用同样的威胁假设，是安全推断，不是本轮对 DreamFlutter 包做过逆向实验**。总密钥泄露后可能产生未授权调用和费用。
- [Google Cloud API key 安全建议](https://docs.cloud.google.com/docs/authentication/api-keys-best-practices) 建议不把密钥写进客户端代码，按用途隔离、限制、监测和轮换；客户端请求可先到服务端，由服务端添加凭据。这是 Google 的产品文档，不能假定所有中转站限制字段或行为相同。
- 客户端“隐藏模型设置”、编译开关、混淆或本机加密可以减少误操作，却不是强制路由或永久保密边界：有控制客户端的测试者仍可能复制其客户端凭证并发起其他请求。**服务端**必须做身份/令牌验证、模型与能力白名单、预算和速率控制；本句是针对本项目的安全设计推断。
- 静态激活码若可重复使用或可换取无限凭据，同样可能被复制；要有一次性兑换或其他可撤销的独立身份/凭据、过期、额度和服务端状态。兑换码与调用令牌是不同凭据，不能认为换了名字就安全。这是方案判断，本轮未实施或实测该候选方案。

## New API：官方文档可支持的具体能力

| 能力 | 官方证据 | 实施边界 / 未验证 |
|---|---|---|
| 按密钥限制额度、到期、模型、来源 IP、分组，启用/禁用/删除 | [New API：API 密钥](https://docs.newapi.ai/zh/docs/guide/feature-guide/user/token) | 检索结果与公开页面描述的是上游文档当前内容；实际托管站是否开放这些选项、白名单是否正确、额度单位/扣费是否精确覆盖所有模态须核实。每名测试者单独分配，便于单独停用，不意味着不能被复制。 |
| 限流的计数范围 | [New API：安全与限制配置](https://docs.newapi.ai/zh/docs/guide/feature-guide/system-settings/settings-security) 描述模型请求按用户计数、同一用户跨密钥共享；Global API / Web、关键接口限流按 IP，搜索限流按用户；多节点是否共用计数受 Redis 配置影响 | **不能把“有速率限制”直接等同于每个密钥独立限速**。若多人共用同一用户账号发多个 key，可能共用该用户的限流窗口；是否需要每人独立账号或代理层另设每凭据限制，取决于实例实测和运维能力。网页读取工具仍报不可访问；随后对该公开文档普通只读 HTTP 请求取得正文，以上是文档描述，具体实例仍须核验。 |
| 按令牌、用户、模型等看用量 | [New API：使用日志](https://docs.newapi.ai/zh/docs/guide/feature-guide/user/log)；管理员日志旧地址现重定向到同一页面，不能算两份独立来源 | 同一页面描述管理员和普通用户视角，并列令牌名、模型、用量、费用、IP、请求 ID 等字段；共享账号记录隔离须另测，不能推断某个调用令牌一定能登录控制台。记录是否开启、保留多久及权限取决于实例，不能只凭文档保证有审计或不含敏感信息。 |
| 配额预扣与结算 | [New API 历史倍率与配额文档](https://github.com/QuantumNous/new-api-docs/blob/main/docs/guide/console/settings/rate-settings.md) 描述预消费和完成后调整；该仓库于 2025-12-01 归档，不能证明当前版本总是预扣。当前[计费设置](https://docs.newapi.ai/zh/docs/guide/feature-guide/system-settings/settings-billing)正文描述钱包和有限额令牌余额均高于门槛时可跳过预扣，订阅和异步任务始终预扣；网页工具失败后普通只读 HTTP 获取正文，仍必须核实实例版本和配置 | 配额不自动证明对并发、流式中断、异常退款、异步任务及不同模态的支出具有零超额硬上限；需要与具体版本及供应商账单对账验证，并另设全局熔断/余额预警。 |

官方 API 密钥页还写明：当前文档所述创建界面中，“无限配额”默认开启、模型限制未选择时不限制；这是上游文档的默认描述，**实际站点可能不同**。同页还列有允许令牌查询用户额度的开关，文档描述默认为开启；多人共用账户时需评估账户总余额/用量暴露风险，发放前核对关闭，或采用隔离账户/代理，并验证各查询接口和日志只暴露授权范围。方案应将有限额度、模型白名单和查询权限作为发放前的明确核验项，不能依赖默认值。来源：[New API API 密钥](https://docs.newapi.ai/zh/docs/guide/feature-guide/user/token)。

## One API：不要把同名系统与 New API 等同

[One API 官方项目说明](https://github.com/songquanpeng/one-api) 描述令牌过期、额度、IP 范围和允许模型等管理能力；其具体部署、版本、后台权限和计费语义仍待核实。官方 README 中的“兑换码”用于账户充值，**不能直接等同于一次性激活码或单人访问凭据**。本轮没有证据证明实际实例提供每令牌独立限速、可用的个人额度或即时撤销语义；不得将 New API 文档直接套用到它。

## 数据与运营

- 代理/中转站能接收到其转发所需的请求数据；具体保留哪些正文、附件、日志、IP、账号信息、处理地区和下游供应商，要以实际服务契约和配置为准。本轮未查看真实账户、日志或请求，不能声称“绝不存对话”。应在试用前清楚说明、提供可理解的隐私说明和联系渠道，并让测试者自主选择是否使用。
- 方案应同时考虑：独立可撤销凭据、按用户/凭据区分的预算和请求速率、服务端模型白名单、全局预算与异常熔断、日志最小化与保留期、密钥轮换、用尽/过期/异常的用户提示、失效后补发流程。全部是方案要求，**不是当前系统能力已验证**。
- 如果使用现有站点自身已覆盖全部需求，可少维护一层服务；若不能提供服务端强制隔离、逐人限额/限速和可审计撤销，需评估额外薄代理或更换服务。代理本身仍有部署、故障、成本和安全维护责任，不能简单当成零成本保护。

## 当前公开文档的预扣边界（补充）

2026-11-14 只读获取 [New API 计费设置](https://docs.newapi.ai/zh/docs/guide/feature-guide/system-settings/settings-billing)和[计费表达式](https://docs.newapi.ai/zh/docs/guide/feature-guide/admin/billing-expression)正文。前者描述输入预扣倍率以预计输入费用为基础，不预估输出 token；倍率对按次和任务计费不生效。后者描述表达式预扣时以输入估算求值、输出及其他用量按 0，Token 档再乘输入倍率、按次档不乘，最后乘分组倍率；实际结算按用量重新求值，多退少补，结算求值失败时按预扣额结算。文档中的 Token 估算器不含请求规则或分组倍率，请求模拟也不含分组倍率。

这些是上游公开文档对所述版本/配置的说明，不等于实际托管站已启用相同机制。**输入预扣不是本方案要求的最坏情况预算预留**：不能假设提高输入倍率就覆盖任意输出，也不能据此推断上游账单硬上限或零超额。未来在获准隔离环境用假服务分别测余额门槛、输入/输出不对称、按次/异步、表达式失败、分组倍率、并发和实际对账；具体站点、上游计费和配置未验证。
