# v0.6 安全设置（T-63）

依据 `Claude Codex Bridge/2026-11-07-01-v0.6阶段派工.md` 第 5 节 S1–S6；Q63-01/02 以该节的用户确认条目为准。

## 路径策略与用户例外

应用受管的读取、写入、编辑、图片读取、文档读取、技能读取、工作目录和搜索使用同一策略。先解析符号链接/junction，包括尚未创建文件的已存在父目录，再统一大小写和 UNC 表示。解析失败时拒绝，不按普通路径放行。

- 默认拒绝：用户 SSH 的 `id_*` 私钥（公钥除外）、Chrome/Edge/Firefox 用户数据、Windows Credentials/Vault、应用自己的密钥目录、`.env` / `.env.*`。`.env.example`、`.env.sample`、`.env.template` 允许。
- 默认需确认：SSH `config` / `known_hosts`、`.aws`、`.kube`、gcloud 配置、`.git-credentials`、`.npmrc`、`.pypirc`。
- 其他路径默认允许。

拒绝类不会向模型提供临时放行对话。用户可在“设置 → 安全与审批 → 路径例外”主动添加工作区例外；目录例外包含子路径。需确认类可以选择“本次允许”或“始终允许此路径”。一次答复不跨调用复用；工作区例外可以查询和删除，模型文字不会改变策略。无人值守和无人值守的子 Agent 遇到需确认路径直接拒绝。

搜索先列举文件名，再逐个检查候选路径，只有已检查文件才交给 ripgrep 读取。搜索的高置信度脱敏发生在展示截断之前，并保留原始行号；敏感私钥块中间的行也不会因为缺失 BEGIN 标记而泄漏。

## 命令与审批模式

S2 使用保守 PowerShell 字面量语法和命令/参数名单，不是完整 PowerShell AST。未列出的命令、别名、参数、动态表达式、复合命令和嵌套 cmd/bash 在非免审批模式下需批准。既往工具级“总是允许”不会免除这次命令判断；单次已批准的命令不会重复弹出普通工具审批。

免审批模式允许这些未证明安全的命令，遵守 Q63-01。独立的 S1 规则仍生效：命令参数直接出现默认拒绝路径时，免审批模式也必须批准；无人值守没有答复则拒绝。持久 PowerShell 在判断前通过其公开 `run()` 查询实际当前目录；查询失败直接阻止调用。已有沙箱的普通 bash 权限沿用原行为，不将 S2 扩展为 Linux 命令解析器。

应用层过滤无法限制已经批准的任意 shell 命令、任意自定义扩展或 MCP 服务的内部行为，也不能排除检查与 I/O 之间由外部进程制造的竞争。不承诺绝对安全或 Windows 系统级隔离。

## 脱敏与文件保护

模型工具输出遮盖私钥块、已知服务商密钥格式及应用保存的密钥原文，标记为 `〔已遮盖：疑似密钥〕`。日志、审计和诊断文本额外处理 Authorization、Proxy-Authorization 和代理 URL 凭据。普通程序示例中的 `password` 字样不会因此被遮盖。

正式 DPAPI 保存/读取流程会登记密钥；会话开始和运行前从当前应用密钥目录通过正式 DPAPI 批量解密流程装载已有密钥，以覆盖尚未调用过的渠道。原文只存进程内脱敏集合，不写入审计。凭据无法装载时，工具调用拒绝继续。缓存会在后续运行/调用重新核对，用户正常保存密钥立即登记。

文件和完整文档先脱敏再截取窗口/分页。发生遮盖的规范化文件路径在该运行时标记，写入和编辑均拒绝；向任何文件写入遮盖占位符也拒绝。重新打开运行时仍须重新读取已有文件，不能绕过原有观察版本要求。

标准 shell 的输出通过公开 `JobRegistry.start` / `OutputStream.push` 适配器，在进入缓存和 spill 文件前处理分块、UTF-8 与跨行私钥。单行超过 1 MiB 会标明超出缓存上限并省略该行，不将普通长行说成密钥。持久 shell、后台通知、工具结果和增量文本在公共工具边界脱敏。未经识别的片段、用户显式批准的外部程序和外部程序自行写出的文件不构成系统级防泄漏保证。

## MCP

通过 Pi 1.4.0 公开的 `createMcpExtension({loadConfig, createTransport})` 接线，使用公开 `StdioTransport({inheritEnv:false})`。不读写 SDK 私有字段。

- 只保留平台运行所需的 PATH/PATHEXT、Windows 系统、临时目录及用户目录变量，再合并该服务显式声明的 `env`；不继承 NODE_OPTIONS、其他渠道 token 或系统代理变量。
- 显式配置继续支持字面量、`$NAME` / `${NAME}`、`$$` / `$!` 转义和 `!command` 凭据引用。`!command` 自身也使用最小平台环境。
- HTTP 的显式请求头和公开 OAuth/AuthProvider 的 token / 401 刷新回调保留。只向相应服务注入它声明/请求的凭据。
- 配置绑定当前应用的 agentDir；受信任工作区才加载 `.pi/mcp.json`。保留全局服务的项目启用/暴露覆盖，并拒绝项目自行选择全局 provider auth。
- transport 在 Pi 收到 `notifications/message`、保存大工具结果及写 MCP 日志前脱敏。MCP 日志位于当前应用 agentDir。
- “检查连接”使用同一公开 extension/factory 的内存会话，不调用会继承整个后台环境的 `pi mcp list` 子进程，也不调用模型。

OAuth 的实际登录/令牌存储和刷新实现仍由 Pi 公开扩展处理；本轮验证使用本地 HTTP 服务和合成 token，未进行真实账户登录。

## 本地审计与接口

SQLite `security_audit` 记录路径策略、审批结果、命令判断、遮盖事件（无内容）和 MCP 启动。字段包括时间、策略版本 `T63-1`、脱敏对象、结论、理由、slot 与运行/请求关联；会话初始化和独立 MCP 检查也生成请求标识。声明为应用备份的一部分，不上传远端，不做不可篡改保证。

启动、查询、导出、记录事件及每小时清理超过 90 天的条目。导出时再次脱敏；导出为 JSONL，可由用户通过保存对话框选择位置。

| RPC | 参数与返回 |
| --- | --- |
| `security.exceptions` | `{cwd}` → `{paths}` |
| `security.addException` | `{cwd,path}` → `{ok}`；解析并保存规范化工作区例外 |
| `security.removeException` | `{cwd,path}` → `{ok}` |
| `security.audit` | 可选 `{before,limit,kind}` → `{events}`；按 id 倒序，limit 上限 1000 |
| `security.export` | `{}` → `{name,text}`；90 天内全部 JSONL |

## 蝶君沙箱与验证边界

安全分类复用现有 `SandboxPanel` 与 `sandbox.status/setOnline/reset/selfTest`，没有新建隔离机制。原沙箱分类保持可用，避免修改共享设置页的其他部分。资源限制不写全局 `.wslconfig`。

2026-11-07 在已有 `DreamFlutterSandbox` 上复用了现有 boot/self-test：11 项逃逸自检全部通过；联网直连 example.com 返回 200；离线直连与显式代理请求均返回 000/超时；结束恢复了原 nft 规则。本机 WSL 是 NAT，原生提示 localhost 代理未镜像；本证据不推断其他网络模式或未来系统代理变更的行为。

自动化使用临时目录、faux 模型、合成凭据和本地 MCP HTTP 服务，覆盖一次/持久例外、链接与不存在目标、三种审批模式、无人值守/子 Agent、持久 cwd、文件/文档/搜索遮盖、防写回、流式缓存、已有凭据重载、MCP 隔离与 OAuth 刷新、审计保留、浅/深色与 150% 字号下的界面操作。最终命令、计数和本轮限制见 T-63 任务回执。
