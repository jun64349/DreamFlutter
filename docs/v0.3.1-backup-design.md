## 二、模块各自声明自己的数据（报告 §3）

后台新增 `BackupRegistry`：每个模块注册一个导出器，声明它的表、文件、敏感等级、版本，以及导入时要做的事（路径重映射、恢复后暂停…）。加一个测试：**数据库里的每张表都必须有导出器认领**，以后新加表忘了写备份，测试就会失败。三级记忆、Goal、后台压缩这些还没有的功能，做的时候顺手加导出器。

## 三、备份包

- 扩展名 `.dfbackup`，实际是 zip（读写用后台已有的 `cards/zip.ts` 的思路，单独写一个支持 Deflate 和大文件的版本，或用成熟的 zip 库，开工时定）。
- 内容：`manifest.json`（格式版本、来源应用版本、数据库版本、时间、各模块及数量、包含 / 排除、每个文件的大小和 sha256、路径对照表的源路径、凭据模式）+ `data\`（数据库副本、会话、卡片、Pi 设置、偏好、沙箱 tar、资料副本）+ 可选 `secrets.enc`。
- **迁移密码**：Node 自带的 `crypto.scrypt`（参数写进清单，导入时限制上限）+ AES-256-GCM。明文不落盘、不进日志。密码错就是恢复失败，不会退回明文。

## 四、导出

1. 预检：估算大小（按实际文件）、目标磁盘空间。
2. **有任务在跑就先请用户等它结束或停掉**（第一版不做边运行边备份，报告 §5 最后一条）；暂停定时任务；不接新的运行。
3. 数据库 `VACUUM INTO` 到临时目录；会话按当时长度复制；卡片、设置、偏好复制；沙箱 `tar`；资料复制。拿到副本后马上恢复定时任务。
4. 在副本上压缩、加密、算摘要，先写临时文件，全部完成后改名成最终文件；中途取消、磁盘满、出错都删掉临时文件，不留看起来像成功的包。备份目录不会被下一次备份收进去。
5. 结果：路径、大小、包含了哪些、凭据模式、检查结论。

## 五、导入（第一版只做整套替换）

1. **检查包**：格式版本、摘要、大小上限、路径安全（拒绝绝对路径、盘符、`..`、链接、重复路径、解压炸弹）、版本（比当前应用新的包直接拒绝，不改任何数据）。
2. **预演**：来源版本和时间、会话 / 记忆 / 任务 / 卡片数量、会被替换的内容、要重填的 Key、对不上的路径（让用户改对照表）。
3. **暂存**：解到 `%APPDATA%\DreamFlutter\restore-staging\`，按迁移链升级数据库（就是后台平时的 `MIGRATIONS`），做路径重映射，检查引用。
4. **先备份当前数据**（自动，见第七节），这就是回退用的。
5. **切换**：后台不能替换自己正在用的数据，所以写一份「切换记录」后退出；下次启动时**在打开数据库之前**按记录完成切换（数据目录、Pi 的会话和设置、偏好），任何一步失败就按记录回到旧数据。窗口负责让后台重启。
6. **恢复后**：定时任务全部暂停，用户检查后再开；蝶君的沙箱按需重建并放回 `/workspace`；结果页列出恢复了什么、没恢复什么及原因、要重填的 Key、撤销这次恢复的入口。

**和报告不同的地方**：报告 §7 要求同时有「恢复成一套独立数据，和现在的并存」。我们的应用只认一个数据目录，要并存得另做切换界面 → 放到以后。第一版只做整套替换 + 替换前自动备份（用户 2026-11-02 同意）。合并导入也放到以后。

## 六、路径重映射

数据库里很多地方记着完整路径（任务、运行、卡片的会话文件和 cwd、资料、工作区工具规则、会话索引），Pi 又按工作区路径给会话文件夹起名（例：蝶君的会话在 `--C--Users-21669-AppData-Roaming-DreamFlutter-butterfly--`），会话文件头里也有 cwd。换电脑或换 Windows 用户名，这些都会失效。

- 清单记下源电脑的 `%APPDATA%`、`%USERPROFILE%`、`.pi` 目录、蝶君的家、每个工作区。
- 导入时自动生成对照表（平台自己的目录一定对得上），工作区对不上的让用户在预演页改（或标记「这台电脑上没有」）。
- 按对照表改数据库里的路径列、改会话文件头的 cwd、按新路径重新给会话文件夹起名。

## 七、版本与自动备份

- 支持的来源：**v0.3.0 及以后**的备份包（数据库第 8 版起）。v0.2 的数据由应用自己在第一次启动时升级，不经过备份包。
- 新版本做的包，旧版本拒绝导入，不改数据。
- 升级前（后台发现数据库要升级时）和导入前各自动备份一次，各保留最近 3 份，放在 `%APPDATA%\DreamFlutter\backups\`；设置里能看到占了多少空间，可以删。清理旧备份不会碰记忆或其他数据。

## 实现记录（2026-11-03）

代码在 `core/src/backup/`：`path-map.ts`（路径对照）、`archive.ts`（zip 读写和检查）、`crypto.ts`（迁移密码）、`parts.ts`（各模块的声明和路径列改写）、`export.ts`、`restore.ts`（检查、预演、暂存）、`switch.ts`（重启时切换）、`backup.ts`（模块和 RPC）。窗口是 `app/lib/ui/backup_panel.dart`（设置 › 数据与迁移 › 备份与恢复）。和上文不同或上文没写的地方：

- **zip 库**：用 yazl 3.3.1 / yauzl 3.4.0（MIT，支持 zip64 和流式读写），不自己写。读包时先把每个条目过一遍：拒绝绝对路径、盘符、`..`、反斜杠、重复（不分大小写）、链接、总量超过 64 GB、大文件压缩比超过 200:1；清单之外的文件、清单里大小对不上的都拒绝；解开时逐个对 sha256。
- **模块声明**：每个模块在构造时 `core.declareBackup({ id, tables, paths, onStage })`。`paths` 写哪些列是路径、是 `normalizeCwd` 键、是含路径的 JSON、还是 Key 引用；`onStage` 在暂存的数据库上做恢复后的事（定时任务暂停就在这里）。数据目录里的文件不逐个声明：除了排除清单（`excludedFromData`）都打包，以后加的文件夹自动跟着走。
- **会话**：后台的会话索引本来就收录会话文件夹里的**所有** `.jsonl`（包括用户自己用 Pi 命令行的会话），所以全部备份。恢复时只写入包里的会话（同名覆盖），**这台电脑上其他的会话文件不删**（它们可能是 Pi 命令行的）。
- **Key 的三种方式**：`none`（不带 Key，恢复后保留这台电脑现有的 `secrets\`，对不上的渠道列出来）；`password`（迁移密码，scrypt N=2^15 + AES-256-GCM，读包时 N 上限 2^20）；`local`（只给自动备份用：DPAPI 文件原样带上，同一台电脑同一个 Windows 用户才解得开，换了人就当作没带）。Pi 的 `models.json`、`mcp.json` 里如果有明文 Key，不带 Key 时打包前抹掉；`auth.json` 只在带 Key 时出现。DPAPI 一次 PowerShell 处理全部 Key（`dpapiMany`）。
- **Key 引用里的绝对路径**：`gateway_keys.secret` 和 Pi 配置里的 `!"node" "secret.mjs" "…\secrets\x.dpapi"` 恢复时改成这台电脑的 node、脚本和数据目录（`relocateSecretRef`）。
- **路径对照**：平台目录（数据目录、Pi 目录、会话目录、用户目录）自动对上；工作区先试原路径、再试「换掉用户目录」后的路径，预演页可以改。会话按新工作区重新放进 Pi 的文件夹（`piSessionFolder`，和 Pi 的命名规则一致），文件头的 `cwd`、`parentSession` 一起改；`trust.json` 的键也改。窗口偏好（`workspace`、`recentWorkspaces`）由后台改好路径，窗口重连后读 `backup.restoreResult` 写回一次（小数用 `{"double": x}` 包着，免得 1.0 变成 1）。
- **切换**：每一步都是「当前的挪到 `restore-old\`，暂存的挪到位」。回滚只看磁盘上的实际状态，所以从任何一步中断都能回滚；启动时没完成的记录先回滚再重做，重做失败就回到旧数据，结果写进 `restore-result.json`。数据库的 `-wal`、`-shm` 一起挪走（留着会弄坏换上来的数据库）。
- **沙箱**：导出时以 root 在沙箱里 `tar --numeric-owner` 打包 `/workspace` 和 `/home/agent`，经 `\\wsl.localhost` 拷出来；恢复时放在 `sandbox\pending-restore.tar.gz`，沙箱下次启动（boot）后清空这两个目录再解开，没有沙箱就等建好后第一次启动。
- **导出时**：有任务在跑就拒绝；拷贝期间 `core.maintenance` 让定时任务等着、新消息被拒绝，拷完就放开，压缩在副本上做。
- **自动备份**：升级数据库前在 `main.ts` 打开数据库之前做（只对 v0.3.0 起的数据），导入前在 `backup.apply` 里做；各留 3 份。手动导出记在 `backups\history.json`，删除只是移出记录。

## 九、验收（报告 §11 落到我们的测试）

- 全模块往返：建一套有会话、任务、卡片、记忆、定时、蝶君资料和沙箱文件的数据 → 导出 → 换一个数据目录（模拟另一台电脑、另一个用户名）导入 → 数量、关系、文件摘要都一致，会话能打开，路径都换对了。
- 每张表都有导出器认领（测试）。
- 有任务在跑时导出被拦下；导出中途取消、磁盘满不留假的包。
- 错误密码、损坏的包、比当前新的包、恶意 zip（越界路径、链接、炸弹）：当前数据不变，原因说得清。
- 切换中途断电（模拟进程被杀）：下次启动回到旧数据或完成切换，不会半新半旧。
- 恢复后定时任务都是暂停的。
- 撤销恢复能回到导入前，且能正常启动。
- 不含 Key 的包导入后列出要重填的渠道；含 Key 的包在另一个 Windows 用户下能用。
