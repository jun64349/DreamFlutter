## 二、每份报告放到哪里

### 02 任务边界 → 0.5（5.11），已合并进 memory-design 第十六节

- 采纳：五个时间尺度（快照跟着「任务」换，不跟消息、轮次）；边界分确定 / 候选 / 普通 / 维护四类；准备和启用分开、带版本比较后提交；紧急纠正、删除、撤权不等边界；「已保存」和「已用上」两张回执；只读记忆模式；压缩和记忆完成都不自己续跑。
- 和报告不同 / 补充：报告没给具体信号。原设计第十二节第 9 条的「隔 ≥ 2 小时」「相关度很低」不再直接切任务，降为「触发一次轻量判断」的门槛；判为新任务时旧任务记「挂起」，界面给「改为继续上一个」一键修正。新增「写笺交给蝶君」「定时任务每次运行」为确定边界（报告里没有，是本项目特有的入口）。

### 05 后台压缩 → 0.5（5.12），原 6.3 的压缩阈值一起挪过来

- 为什么放 0.5 不放 0.6：记忆快照、压缩摘要、目标约束挤在同一个上下文窗口里，共用一个预算；「被纠正的事实不从摘要复活」是记忆和压缩一起测的；0.6 原本就是最重的一版。
- 顺序照报告的三阶段：先把普通压缩做对（否定条件、未验证、后台任务、工具成对、约束每次单独放进上下文）→ 再做单候选的后台压缩 → 动态提前量等高级调度以后再说。
- **已核对 Pi 1.4.0**（`core/node_modules/@earendil-works/pi-coding-agent/dist/core/extensions/types.d.ts`、`compaction/compaction.d.ts`）：扩展的 `session_before_compact` 事件带 `preparation`（`firstKeptEntryId`、要总结的消息、上次的摘要）、`reason`（manual / threshold / overflow），返回值可以给出现成的 `compaction: CompactionResult`；`prepareCompaction(entries, settings)` 是公开函数，可以提前算出切点。所以「后台先写候选、到点检查前缀没变就直接换上」不用改 Pi。
- 和报告一致：候选第一版只放内存、不落盘；一个会话最多一个候选；没用上的也记账；OpenCode 的 85% 提前量只作参考。
- 默认范围是建议：蝶君和长任务会话默认开，工作台普通对话设置里可开，拿到对照数据再定。

### 04 Goal → 0.8「长任务与目标」，0.4 先写开发设计（4.9）

- 原 0.8 的「后台子 Agent 与等待、插话、计划清单、提问框、中间过程、测试集」都还在，但现在挂在目标服务下面：后台等待就是目标的「等依赖」状态，插话就是交给目标的执行者。
- 采纳：目标 ≠ 计划 ≠ 会话；状态机（每个状态有原因和恢复条件）；唯一调度者 + 带幂等键的续跑意图；三层验收（程序检查 → 只读审查模型 → 用户验收）；进展指纹防空转；停止的四种意思；统一预算账本（调用前预留、返回后结算）。
- **在现有基础上扩展**：后台已有 `tasks` 表（有 `goal`、`status`、`runs`、`turns`、`cost` 字段）、`runs`、运行上限和花费上限的暂停卡片、继续卡片、定时任务。目标服务在这些上面加字段和状态，不另起一套。
- 为什么设计放在 0.4：0.5 的任务边界事件要从目标 / 工作项来，0.4 的右侧面板要给目标留位置，先把接口定下来免得返工（和 0.3 先写记忆设计、0.5 再实现一样）。

### 03 DSH → 拆到 0.8 和新的 0.9

- 「工作项独立于会话、执行尝试、跟进消息有唯一主人、暂停 ≠ 停止、阶段由状态推导而不是模型自报」这些和 Goal 是同一套东西 → 0.8。
- 「事件接入和去重、Gate + Assessment 准入、关 / 观察 / 自动三档主动规则、Mandate 不因新资料扩权、先存状态再做副作用（effects / outbox）、崩溃后对账不重放、注意力优先的通知」是蝶君主动工作才需要的 → 和原 8.7 蝶君成长合成新的 **0.9「蝶君自主与成长」**。
- 不搬的：原型的 `danger-full-access` 全宿主权限（蝶君继续用 WSL 沙箱 + 不给 root）、单仓库 PR 生命周期（蝶君的文档任务看产物和验收，不看 PR 关没关）、GitHub / 飞书来源（第一批只接内部来源）。
- 主动模式默认「观察」：只记录「本来会接什么」和理由，用户看过命中质量再对窄范围的规则开自动。

### 蝶君体检报告 → 0.4（4.8）

缺 C 编译器、Node、ffmpeg、OCR，Chromium 缺系统库（蝶君从 Ubuntu 归档手动解 deb，在 Debian 沙箱里混 Ubuntu 的包不稳）。镜像加 Debian 自己的 `build-essential`、`nodejs`/`npm`、`ffmpeg`、`tesseract-ocr` + 简体中文、`chromium`。镜像会变大（粗估压缩后多 300–500 MB，要实测），太大的改成需要时由应用代装。放 0.4 而不是更晚：0.8 的长任务测试集和 0.9 的自主工作都要用到这些工具。OpenAI 421、知乎 / 百度反爬是对方网站的限制，不处理。

## 三、版本变化一览

| 版本 | 修订前 | 修订后 |
|---|---|---|
| 0.4 | 外壳与呈现 | 不变，加 4.8 沙箱镜像、4.9 长任务内核开发设计；右侧面板给目标留位置 |
| 0.5 | 记忆系统 | **记忆与上下文**：加 5.11 任务边界、5.12 压缩和后台压缩 |
| 0.6 | 模型、设置、仪表盘、安全、数据与版本 | 压缩阈值挪走，变轻；仪表盘多几类费用 |
| 0.7 | 技能与 MCP | 不变 |
| 0.8 | 长任务 + 蝶君成长 | **长任务与目标**（工作台、蝶君共用） |
| 0.9 | 打磨 + 深度测试 | **蝶君自主与成长**（新） |
| 0.10 | — | 打磨 + 深度测试（原 0.9） |

多了一个版本。另一个办法是把 0.9 的蝶君自主塞进 0.8，但 0.8 会变成最重的一版，而且自主接活要等目标服务稳定了才安全，所以建议分开。

## 四、要用户现在定的

1. 这版计划（尤其是多出 0.10、压缩挪进 0.5）行不行。
2. 沙箱镜像加软件的方向（4.8）行不行；具体加到多大，0.4 实测后再问。

其他待定项（任务边界的信号、后台压缩的提前量、目标的预算和轮数、主动规则……）按惯例在 0.4 期间写进两份开发设计、给建议值，再和用户逐项定。
