# DreamFlutter v0.4 发布说明

0.4 是「外壳与呈现」：窗口框架、右栏、对话过程、输入框、首页和图标都按设计稿重做了，工作台和蝶君共用一套框架。设计资料在 [design/](design/README.md)（界面设计语言、品牌）。

## 窗口框架（4.2）

- **顶栏**：左边是蝴蝶标志和名字，中间是「工作台 / 工作区 / 会话标题」，右边是详情开关和窗口按钮（你选的设计稿方案三 + 方案一的顶栏）。
- **工作区下拉**：点顶栏的工作区按钮、按 Ctrl O，或点侧栏「某工作区 的对话」旁边的切换按钮，都能打开。里面列出每个工作区的完整路径，选了就换。
- **一个侧栏通用于所有页面**，原来的图标导航条去掉了。侧栏从上到下依次是：
  - 工作台 / 蝶君切换、新建对话（旁边是无痕对话）、搜索、任务（显示待处理数）；
  - 这个工作区的对话；
  - 底部一排：记忆、技能、仪表盘、外观、设置。
  
  侧栏可以拖宽，下次打开还是那么宽。
- **详情（右栏）按需打开**：默认关着，点顶栏的按钮打开。窗口宽时停在对话旁边，窄时盖在对话上；也能拖宽。原来右上角「⋯」里的功能（存成技能、存为模板、定时接着做、记忆快照）变成了详情里「常用操作」的按钮。

## 详情分块（4.3）

详情的「概览」分成几块：进度、最近的步骤（多了只显示最近 5 步，可以展开）、产物与改动、子 Agent 与后台、上下文与花费（圆环显示用了多少上下文）、常用操作。每块都能折叠，折叠状态会记住。

## 对话过程（4.4）

- 思考、命令这些过程**默认折叠**。运行中只露出最近三步，每步一行，写着「正在…」。
- 命令也是一行，点开才看到终端；**命令出错时自动展开**。终端颜色跟主题走：白天是纸色，夜里是深色。
- 工具返回的图片、你发的图片都显示成缩略图，点开看大图，可以缩放。
- MCP 工具会写明是哪个服务、哪个工具。

## 回复下方（4.5）

模型、耗时、花费这一行和操作按钮平时隐藏，鼠标移上去才出现，完整的数字在悬停提示里。按钮也加大了。

## 输入框里选模式（4.6）

输入框里可以直接选「标准 / 极简 / 无痕」。**无痕**就是原来的临时对话，改了名字：不保存、不读写记忆、用极简模式。从无痕切到标准或极简，会新开一个正常保存的对话。设置里的默认模式还是只有标准、极简两种。

## 选中文字回复（4.7）

在回复里拖选一段文字，松开的地方会浮出两个按钮（右键菜单里也有）：

- **回复**：把选中的内容作为引用，接在输入框已有文字的后面。
- **侧边对话**：在详情的「侧边对话」标签里，专门就这段内容提问。它带着主对话到目前为止的内容，但**不会往主对话里加任何东西**，会话文件也只读不写。问完可以点「带回主对话」，把最后的回答作为引用放进输入框；点「结束」关掉，它在后台的会话也一起关掉。无痕对话里没有侧边对话。

## 首页

新对话只显示蝴蝶和一句问候语，问候语按清晨、上午、午后、傍晚、深夜挑，另有一组不分时段的，蝶君也有自己的一组；同一个对话里这句话不变。原来的说明文字、建议卡片、底部的工作区按钮都去掉了（v0.3.1 实测第 5 条）。第一次使用时的「开始之前」引导还在。

## 品牌（4.1）

- **图标就是你给的那只橙色蝴蝶**，做了一份 1:1 的矢量版（[design/assets/butterfly.svg](design/assets/butterfly.svg)）：从原图描出来，不改造型；分层、可换色，方便以后二创和组合。和原图逐像素比，平均差 0.96（满分 255）。
- **蝴蝶的颜色跟着名画主题变**：「蛱蝶」就是原图的颜色；其余主题用各自画里的颜色；深色主题的轮廓线是白色。这套配色是你看过预览后同意的。
- exe、快捷方式、托盘图标都换成了这只蝴蝶（原图配色，带圆角底）。很小的尺寸（顶栏、托盘）把线条稍微加粗，免得发灰发虚。
- 「工作台」「蝶君」两个名字不变。

## 沙箱镜像（4.8）

按你定的「平台不能太重」，蝶君的沙箱里只加了三样：C 编译器、Node 和 npm、文字识别（含简体中文）。镜像从 282 MB 变成 451 MB。ffmpeg 和浏览器没装，记在「需要时再装」的清单里，以后做成由应用代装。

## 长任务设计（4.9）

0.8 要做的长任务（一个目标自己推进到完成）的开发设计写好了：[long-task-design.md](long-task-design.md)。第十八节有 11 个待定项，各给了建议值，0.8 开工前要你定。

## 没做的、要注意的

- 设计稿里顶栏的「分支」按钮没做，分支还在详情的「分支」标签里。工作区下拉里每个工作区的对话数、「在运行」也还没显示。
- 「梦蝶」朱印、组合标志要不要用，你还没定，这一版没动。
- **记忆和技能的入口**在侧栏最底下那排图标里：灯泡是记忆，书本是技能（鼠标停上去会显示名字，有待确认的会标数字）。你发现它们不显眼，这一版先不改。
- 侧边对话用真实模型试过一问一答（见下面的测试），还没长时间用过，用的时候请留意它有没有影响主对话。

## 测试时发现并修好的

- **升级后第一次打开，提示「后台没有在 20 秒内启动」**（你第一次试 0.4.0 安装包时碰到的）：后台其实没坏，只是升级后第一次启动用了 22 秒。刚复制进来的几千个文件在第一次被读取时，Windows 会逐个扫描，所以特别慢；第二次启动只要一两秒。窗口原来只等 20 秒就放弃了。现在只要后台进程还活着，窗口就一直等，最长 2 分钟；后台要是中途退出了，就马上报错，不用干等。回归测试在协议层 `core_test`。
- **顶栏右边的按钮没靠右**（你试的时候发现的）：详情按钮和最小化、最大化、关闭按钮离窗口右边缘空出一大截，宽窗口里能空出 200 多像素。原因是顶栏中间的路径（工作台 / 工作区 / 标题）和空白拖动区各分走一半剩余空间，路径用不完的那部分没有还给拖动区，就成了最右边的空白。现在路径叠在拖动区上面，按钮贴着右边缘。组件测试默认不画窗口按钮，所以之前没测出来；现在 `window_frame_test` 会检查按钮贴右边缘（去掉修复会失败），我也在真窗口里把窗口按钮打开量过位置。

- **侧边对话点「结束」后，后台的会话还开着**：窗口里拿掉了，后台那份要等空闲一阵才回收。这期间它多占一个后台会话；要是窗口关掉再打开，它还会被当成一个没名字的对话接回来。现在点「结束」、换一段新的侧边对话、关窗口时，后台那份都一起关掉；后台给每个会话标明「它是谁的侧边对话」，窗口重新连接时不会再把它接成普通对话。这是端到端测试第一次用真实模型走侧边对话时撞出来的。回归测试：`side_chat_test`（点「结束」后后台收到关闭）、`agent_controller_test`（侧边对话不被接回）、后台 `slots.test`；都确认过去掉修复会失败。

## 测试

- 全量：窗口 126（新增 `butterfly_mark_test` 3 个）、协议层 47（新增启动等待 4 个）、后台 200 + 类型检查、场景巡检 5（真窗口：阅读、选字、拖放、所有页面和主题）、卡片、视觉检查（截图看过：首页、顶栏和各主题的蝴蝶），全部通过。
- **真实模型端到端**（OpenCode Go 的 deepseek-v4.1-flash）：全部步骤通过，2 分 23 秒；以前时有时无的语义树错误这几次都没出现。0.4 新加了一步**侧边对话**：在一条真实回复上开侧边对话、问一句，检查回答对、主对话一条没多、会话文件一个字节没变，再「带回主对话」「结束」。
- 端到端脚本里有两处还用着旧界面的名字（「新会话」按钮、「工作区 · 」），跟着 0.4 改了；脚本里用到的所有界面文字都和新界面核对过。

## 要你试的

1. 打开就看一眼：顶栏、侧栏、首页的蝴蝶和问候语；去「外观」换几个主题，看蝴蝶的颜色跟着变；切到深色主题看白色轮廓线。
2. 任务栏和托盘里的新图标，看清不清楚。
3. 发一个会跑好几条命令的任务：过程应该折叠，只露出最近三步；点开一条命令看终端；让一条命令故意出错，看它是不是自动展开。
4. 点顶栏右边的按钮打开详情：看「概览」的分块，折叠一块再切换会话，看它是不是还记得。把窗口拉窄，详情应该盖在对话上。
5. 在一条回复里选一段字：试「回复」和「侧边对话」。侧边对话问一两句，再「带回主对话」；回到主对话确认里面没有多出东西。
6. 输入框里切到「无痕」聊一句，再切回「标准」：应该新开一个对话，无痕那段不在列表里。
7. 拖宽侧栏和详情，关掉应用重新打开，宽度应该还在。
