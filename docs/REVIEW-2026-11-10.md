# 全面核对：设计、进度、实现与体量（2026-11-10）

范围：对照 [交互设计](design/interaction-design.md)（概念表 40 项、12 个流程、统一交互规范）、[1.0 原型](design/prototype/interaction-v2.html)、[roadmap](roadmap.md)（v0.8 UI.0～UI.12、v0.8.1）、[开发规范](dev-guide.md)、[v1.0 收敛说明](v1.0-convergence.md)、[AGENTS.md](../AGENTS.md)，核对当前 main（`2d45eb5`，0.8.1-test.1 候选包）的代码、测试和安装包。

方法：在代码里逐项搜设计要求的界面和后台接口；看端到端和组件测试实际覆盖了什么；脚本统计没人引用的代码、窗口不调用的后台接口、超长行和安装包各部分体积。没有跑真实模型（见第三节第 1 条）。

## 一、结论

- **方向没有偏**：概念表 40 项里 37 项已按设计落实，3 项部分落实；12 个流程都有实现，其中 9 个有端到端测试。0.8.1 按用户实测把右栏、对话区、设置和花费页补齐，设计文档和原型也同步修订了。
- **有 4 处需要处理的偏差**：①"模型组"在 roadmap 里是答应过的功能，0.8.1 却把它的界面去掉了，**要用户定**；②测试清单和用词表还写着旧界面（"⋯"菜单、本次改动、定时再做一次）；③发布前检查有几项没做（真实模型、启动退出耗时、去掉修复测试会失败）；④安装器还没有，用户只能用免安装版。
- **代码有可清理的余量，但不算臃肿失控**：窗口约 2.3 万行、后台约 3.1 万行，测试约 2.1 万行。窗口里约 600 行已经没人用；后台 277 个接口里 102 个窗口不调用，其中一部分是旧界面留下的。安装包 1.13 GB，比 0.4 时的 855 MB 大，主要是 0.7 加的办公用 Python 库和 Git。

## 三、偏差和错误

### 1. 模型组：roadmap 答应过，0.8.1 却去掉了界面（要用户定）

roadmap 第二节"模型网关"、6.4"模型组拖动排序"、附录 B 第 3 条、子 Agent 角色卡"可选模型组"，都是用户早先要的。0.8.1 按实测第 20 条（"这个模型组也是没用的了"）做了三件事：设置里去掉"模型组"和"按模型覆盖上下文窗口"；模型列表里不再列模型组；后台功能保留。

两者冲突，需要用户在下面三条里选一条：

- **A** 从 1.0 范围里正式去掉模型组。把 roadmap 和设计里相关的条目改掉，再删后台和窗口里的模型组代码（窗口约 270 行，后台网关里的分组路由也要删）。
- **B** 保留模型组，只是不放在显眼处。在"模型 › 高级"放回一个简化入口。
- **C** 保持现状：界面上没有，后台留着。

不选的话，C 会让代码和文档长期不一致。

### 2. 文档过时

- [testing/scenarios.md](testing/scenarios.md) 第 37、58、59 行还写着"对话⋯"、"本次改动"、"定时再做一次、这段对话不记忆"，第 179 行写着"模型组自动换渠道"。开发规范第六节第 3 条要求本版改动在清单里有对应的行。
- [design/glossary.md](design/glossary.md) 第 34、35、43、45 行还把"本次改动""定时再做一次""这段对话不记忆"写成现行用词。

### 3. 发布前检查没做全（开发规范第五、六节）

1. **真实模型**：从 0.7 起，测试版里的 OpenCode Go 密钥一直是 401。0.8.0 和 0.8.1 都只用假模型验证过。用户这次实测里的超时、上下文 62%，都是真实模型才暴露出来的。
2. **启动和退出耗时**：规范要求每次发版记录冷启动、再次启动、退出各一次，0.8.0-test.2 和 0.8.1-test.1 的说明里都没有。
3. **"去掉修复，测试会失败"**：0.8.1 新加的回归测试（重试后不留错误卡、已删除渠道不缩小窗口、中间输出进过程链），我没有逐个把修复撤掉再跑一遍确认。
4. **组件测试里的偶发失败**：`agent_controller_test` 里删临时文件夹时文件被占用，偶尔失败一次，单独重跑能过。

### 4. 安装器缺失

0.8 的 UI.9 要求"安装位置可选"（承接 V07-01），交互设计 4.1 也写的是"双击安装包 → 选安装位置"。打包工具（Velopack）在 0.7 清理时被删了，所以 0.8.0 起的候选包都是免安装版。开机启动因此也是灰的。

### 5. 版本和发布状态

- `app/pubspec.yaml` 和 `core/package.json` 的版本号还是 0.7.0，候选包的版本号是打包时临时指定的。
- 0.8.0 一直没有定版。
- main 比远端多 15 个提交，没推送，也没打标签。

`agent_controller.dart` 什么都管，是最该拆的一个。

### 5.2 窗口里已经没人用的代码（约 600 行，可以删）

- `gateway_pages.dart` 的 `GroupList` 和 `GroupEditorDialog`（约 270 行）、`model_settings.dart` 的 `ModelWindowSetting`：0.8.1 起不再出现在界面上。删不删取决于第三节第 1 条。

- `zoom.dart` 的 `ThemeChoiceRow`、`showAppearanceDialog`。

- 只剩测试在用的：`describeQuota`、`showMemoryDetails`。

### 5.3 后台接口：277 个里 102 个窗口不调用

不全是多余的，分四类：

- **内部用的**：定时器、调度触发，比如 `schedules.tick`、`butterfly.tick`、`core.startup`。不用动。
- **给 Agent 工具或协议层用的**：比如 `webSearch.search`、`cards.*` 的一部分。不用动。
- **留给 0.10 接口文档和 0.9 目标服务的**：比如 `context.*`、`runs.*`、`tasks.*`。0.10 时统一整理。
- **旧界面留下的，候选删除**：
  - `notes.*`：写笺 / 书桌，已删。
  - `materials.*`：资料栏。
  - `templates.*`：模板已并进技能。
  - `memory.newTask` / `continueTask`："下一条作为新任务"按钮，已删。
  - `schedules.fromSession`："定时再做一次"，0.8.1 已删。
  - `ledger.importHistory`：旧账本导入。
  
  删之前要逐个确认 Agent 工具也没在用。

其中 20 个左右连后台测试也没有覆盖，比如 `cards.events`、`memory.export`、`webSearch.fetch`。

### 5.4 可读性

窗口有 216 行、后台有 503 行超过 200 个字符。这些行把一整个界面或函数写成一行，集中在 `settings_workspace.dart`（26 行）、`setup_wizard.dart`（21 行）、`ledger_table.dart`、`garden_page.dart`。开发规范不让用 `dart format`，但这些行读、改、审查都很难，0.8.1 的几次误改也多出在这类行上。建议改哪个文件时，顺手把它拆成正常的多行写法，不搞一次性的大格式化。

能省的地方（按 roadmap 12.5 的"最终复核"做，不现在动）：
