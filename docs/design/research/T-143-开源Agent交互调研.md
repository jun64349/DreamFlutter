# 开源 Agent 交互调研

2026-11-16 · DreamFlutter 原型候选

这轮按 Windows 个人助手的三个实际场景筛选：中途换对话回来接着看、从「等你处理」回答后继续、在聊天里找到文件再发出去。对照了四个项目的官方文档和公开源码。下列链接把源码固定到本次查阅的提交，产品行为依据源码、文档或仓库里的验收测试判断，未安装运行这些项目。梦蝶现状按 [v1 原型](../prototype/v1-redesign.html)、[规格](../v1-redesign-spec.md)、[差距清单](../T-143-差距清单.md) 和 [定型行为](../settled-0.8.3.md) 判断。

HanaAgent 里已经学过的过程块薄底、路径从目录端缩短、图表切换源码、展开时只淡入，属于这次的出发点。下面主要看切换时怎样保持上下文、内容怎样从一个现有入口跳到另一个入口。 [HanaAgent 调研](../hana-study.md)

## 八个具体做法

### 1. 切回对话时，回到上次正在看的地方

- **来源与证据**：AionUi 的 `previewScopeKey()` 以项目标识优先、工作区兜底，同一范围内切对话保留预览，越过范围则切换预览状态。预览状态包含打开与否、现有标签和当前标签。 [范围计算源码](https://github.com/iOfficeAI/AionUi/blob/e108b6b56b1a6eb99a00904878d0582f657b2908/packages/desktop/src/renderer/pages/conversation/Preview/context/previewScope.ts#L8-L33) · [预览状态读取源码](https://github.com/iOfficeAI/AionUi/blob/e108b6b56b1a6eb99a00904878d0582f657b2908/packages/desktop/src/renderer/pages/conversation/Preview/context/PreviewContext.tsx#L420-L434)
- **梦蝶操作**：在温湿度周报对话打开「这个对话 › 文件 › 周报-W45.md」，切去另一条对话，再选回周报。回到原滚动位置，恢复周报那条对话的文件选中；另一条对话只显示属于自己的右栏。仅恢复窗口内现有页签、文件标识和位置，文件已不可用就回本对话文件列表。无痕只在该对话还在内存时恢复。
- **与现状的差别**：原型侧栏多条演示对话共同指向 `chat`，右栏用共享的 `S.rtab`；当前稿无法验证返回另一真实对话时的预览隔离。
- **定型判断**：保留第 2、3、6、7 条的对话入口、工作区位置、列表排序和右栏预览；恢复位置应以用户此前的操作为准。单击历史仍不影响列表顺序。若一份文件同时出现在两个对话，各自保留其原有预览状态。

### 2. 计划条只接受最新一版实际步骤

- **来源与证据**：OpenHands 的 `useTaskList()` 倒序找最近一条 `TaskTrackerObservation` 计划事件，读取结构化步骤及状态；列表给 `in_progress` 行单独的当前标记。 [读取计划事件源码](https://github.com/OpenHands/OpenHands/blob/2914e63bc8af5bcb58debb5dc869c73e292433df/src/hooks/use-task-list.ts#L14-L47) · [步骤显示源码](https://github.com/OpenHands/OpenHands/blob/2914e63bc8af5bcb58debb5dc869c73e292433df/src/routes/task-list-tab.tsx#L9-L35)
- **梦蝶操作**：蝶君接到原有对话请求后直接动手。用户在输入框上方点击「计划 2/5」；如果补了一步核对运费，清单保持展开，从真实计划刷新成 2/6，仍突出当前在做的步骤。没有计划就不占一块；有清单但没有进行中项时不拼「正在」。
- **与现状的差别**：原型 `vChatBf()` 固定了一份 2/5 和整组步骤。真实窗口已有读取真实待办的 `GoalPlan`，本条先补「计划更新时用户已经展开」的原型场景，保留现有数据接入。
- **定型判断**：符合第 1、2、12、13 条。沿用输入框同一容器，第 2 条限制的对话头仍不承载任务信息。不借独立 Planner 页，也不把计划确认变成开工前置条件。

### 3. 折起过程再展开，正在做的工具时间继续走

- **来源与证据**：LibreChat 的端到端场景固定时钟，折叠 8 秒后展开，断言工具计时至少 8 秒；再次折起 3 秒再展开，断言时间至少多 3 秒。它验的是用户真正看到的过程行，不是时钟函数本身。 [LibreChat 过程计时验收](https://github.com/LibreChat-AI/LibreChat/blob/9363db541ecd4e23ab6a41dca47ca48ee2bd418e/e2e/specs/mock/scenarios/tool-timer.spec.ts#L29-L55)
- **梦蝶操作**：用户在过程行点开「运行 · 汇总脚本」，看见已运行 8 秒；收起去看正文，3 秒后再展开显示 11 秒；运行结束即固定用时。工具输出还是在步骤行点开，失败步骤沿现行规则自动展开。失去运行时间的旧记录只显示已有事实。
- **与现状的差别**：现原型有固定用时与展开层级，未演示运行中计时跨折叠延续。只更新正在运行那一行，秒数留固定占位，避免重排聊天正文；无开始时间可用时不推算。
- **定型判断**：第 8、12、13 条的回复统计、蝴蝶与滚动保持。过程步骤计时与回复统计是不同对象。折叠时保留现有摘要，没有第二条状态横幅。

### 4. 授权与提问，都跳到准确的一张卡

- **来源与证据**：Cline 的 VS Code 跟进代码先交给待批准动作处理，再交给待回答问题；切换任务后若标识已经不同，则取消旧任务的跟进，避免把答复送错。OpenHands 的官方文档给出等待批准后做决定的流程。这些项目提供的是请求分流和保护时序，精确落点与同一请求同步是给梦蝶的提案。 [Cline 请求分流源码](https://github.com/cline/cline/blob/72b3d7140553a733242126e51a7c2e87efe75c64/apps/vscode/src/sdk/sdk-followup-coordinator.ts#L65-L112) · [OpenHands 确认流程](https://github.com/OpenHands/docs/blob/main/openhands/usage/confirmation-mode.mdx)
- **梦蝶操作**：在「等你处理」看到「是否把仅海外出售的型号算进去」。点「去对话里说」落到这张问题卡；点选后同一请求的收件箱入口变成已处理。如果待办是文件修改授权，仍按原卡执行「允许 / 拒绝 / 这个对话里都允许这类操作」。用户在等答复时切回另一条会话，原请求仍绑定原会话；过期项显示已处理，不落到另一个待答项。
- **与现状的差别**：原型有两类卡和选项，尚未串联「从案头定位卡片再回案头」。实窗 `openAttentionTarget` 已按会话/运行槽打开对话，尚需核实可否从现有目标数据取得稳定的消息或请求标识；缺标识时只定位到对话，不改后台字段。
- **定型判断**：遵循第 1、2 条以及 [现有即时处理规则](../interaction-design.md#49-处理等你处理)。已有批准档位与授权范围照旧，紧急项继续即时、无撤销。问题答案走问题本身，普通聊天继续走公共输入框。开放任意新授权范围不在此提案。

### 5. 看改了什么时，保留「前后不同」和「现在内容」两条路

- **来源与证据**：Cline 在过程中的检查点提供 Compare 与 Restore，官方文档把看差异与回退分成独立操作，代码定义工作区比较的结果结构。梦蝶只借「看差异在原步骤旁，和改变状态的动作分开」。 [Cline 检查点文档](https://github.com/cline/cline/blob/72b3d7140553a733242126e51a7c2e87efe75c64/docs/core-workflows/checkpoints.mdx) · [差异源码](https://github.com/cline/cline/blob/72b3d7140553a733242126e51a7c2e87efe75c64/sdk/packages/core/src/session/checkpoint-diff.ts#L15-L28)
- **梦蝶操作**：批准前在原卡看拟改的具体文字。修改发生后，在过程块打开已有差异；点差异标题中的可点击文件名交给同一右栏的「改了什么」。右栏点击「现在的内容」看当前文件。连续改同一文件两次，第一处历史步骤若只有当时差异，就原地呈现该差异，绝不用最新内容冒充当时结果。
- **与现状的差别**：原型已有拟改卡、过程内联差异和右栏文件列表，未把它们连成可走一遍的路径。现有规格已规定右栏可看文件；没有可靠历史差异数据时仅保留过程已有展示，不补造快照和版本。
- **定型判断**：符合第 7 条的右栏文件预览，不替代右键四项；不加入回滚、版本管理或二次批准。候选中的新增点击只挂在原来已能显示路径的区域。

### 6. 聊天里点文件，复用右栏同一个文件预览

- **来源与证据**：AionUi 的文件预览明确按同一文件复用标签，树上快速浏览可复用活动预览；源码接口注释明确说明保留未保存内容时例外。梦蝶借文件身份复用和快速浏览。 [AionUi 中文技术文档](https://github.com/iOfficeAI/AionUi/blob/e108b6b56b1a6eb99a00904878d0582f657b2908/packages/desktop/src/renderer/pages/conversation/Preview/README.cn.md#L5-L23) · [复用选项源码](https://github.com/iOfficeAI/AionUi/blob/e108b6b56b1a6eb99a00904878d0582f657b2908/packages/desktop/src/renderer/pages/conversation/Preview/context/PreviewContext.tsx#L78-L85)
- **梦蝶操作**：点击交付消息里的 `对比报告.md`，已有「这个对话」右栏切到文件、选中同一文件；再从右栏列表点相同文件，“看文件”的位置保持。用现有返回入口回到原滚动位置。两个目录里的同名文件按完整文件身份区分。
- **与现状的差别**：现原型的工作台文件列表和蝶君交付项多用于位置与样式示范，未让对话内文件和右栏列表的选中状态同步。右栏保持一个预览，不增加浏览器标签栏或自动抢打开。
- **定型判断**：遵循第 7 条预览和原有右键菜单，第 2 条右栏继续叫「这个对话」。只有用户点了可用文件才切到预览，模型输出的普通文本路径不能靠猜测绑定文件。

### 7. 复用已交付文件，发送前看得到这一轮的附件

- **来源与证据**：LibreChat 的附件面板列最近文件，选中已有文件可重新附到消息，发送前在输入区上方看到本轮附件。开源挂钩 `useRecentFiles` 把已有文件查询和附入动作交给同一界面。 [LibreChat 输入框文档](https://www.librechat.ai/docs/features/composer) · [复用附件源码](https://github.com/LibreChat-AI/LibreChat/blob/9363db541ecd4e23ab6a41dca47ca48ee2bd418e/client/src/hooks/Input/useRecentFiles.ts#L9-L43)
- **梦蝶操作**：原型先在附件入口加可演示的「本对话的文件」候选。用户选 `对比报告.md` 时，文件在输入框附件位置出现，随手移掉或发送。只显示当前对话、现有发送入口已经支持的文件类型；引用一段文字仍走「引用」。仅能预览、原路径已失效或无当前访问权的文件不进入这次发送。
- **与现状的差别**：梦蝶有附件钮，实窗已有部分附件预览及移除；原型未演示从本对话产物复用，也未展示误选同名文件时如何确认。真实通用文件格式和跨空间复用仍有数据依赖。本次只模拟适用类型，不建立全局文件索引。
- **定型判断**：保留第 1、6、10 条的会话与工作区边界、看图能力匹配，以及无痕的现有含义。预览一份文件不代表它已作为上下文发给模型。

### 8. 用渠道和模型名搜索，清楚当前将用哪个

- **来源与证据**：LibreChat 的 `ModelSelector` 有可键盘进入的搜索框、过滤结果和分组浏览。选择项同时保留端点、模型与预设标识。它自己的按钮允许省略文本，梦蝶仍按既定完整显示。 [LibreChat 模型选择器源码](https://github.com/LibreChat-AI/LibreChat/blob/9363db541ecd4e23ab6a41dca47ca48ee2bd418e/client/src/components/Chat/Menus/Endpoints/ModelSelector.tsx#L74-L127)
- **梦蝶操作**：点输入框「模型 · 渠道」，按原排序显示模型组和常用项；打开已有「更多模型…」才进入搜索。可按模型名或渠道查找，结果同名时第二行写渠道；方向键确认、Esc 回原位置，取消保留已选模型和草稿。选了模型组，要看实际使用的渠道时继续从现有提示、切换提示和回复信息读取。
- **与现状的差别**：实窗 `_ModelChip` 的「更多模型…」已经会打开搜索，原型只画当前按钮。先补可走通的演示，对应检查现有搜索是否支持按渠道区分同名模型；无需再加输入框顶层入口。快捷键先复用现有键盘操作，无全局新快捷键。
- **定型判断**：第 8、10、11 条优先；菜单顺序、完整按钮名称、模型组的渠道切换行为照旧。搜索结果的可辨认性属于展示。取消搜索不应触发模型切换。

## 三条原型操作方案

用现在的温湿度传感器、W45 周报、SHT40 对话作为演示样本。原型数据可以模拟事件，正式界面只响应已有数据来源。

### A · 蝶君换对话后接着看

1. 蝶君对话打开正在进行的清单，显示「计划 2/5 · 正在：整理成对比表」。
2. 模拟实有计划更新，新增核对运费，暂时显示 2/6。点开运行中的过程，折叠几秒再打开，耗时连续。
3. 侧栏点另一条对话，再回到这条。原来的计划仍展开，滚动回到此前附近；当前步骤已完成时显示新状态。对话列表位置只按最后一条消息或置顶规则更新。
4. 验收屏幕三态：切换前、另一条对话、切回后。核对每个右栏属于当前对话；减少动效时步骤内容立即更新，正文和主体位置稳定。对应做法 1–3。

### B · 在案头答问题后走到交付

1. 在「等你处理」点「去对话里说」，对话滚到「海外型号是否算入」那张问题卡，不自动打开其他问题。
2. 点「先不算」后保留答案回执，任务继续；回到案头同一项只处理一次。对话存在但消息锚点不可用时，落到对应对话并保留正常操作；请求已失效时显示已处理。
3. 交付出现时点 `对比报告.md`，右栏直接选中该文件。若这是两次修改后的同名文件，可在右栏看现在的内容，从某一步打开则仍能看到该步已有差异。
4. 验收屏幕三态：请求待答、已回答仍在原位置、交付并选中文件。另做一份批准卡对照，核对允许、拒绝、会话内授权三按钮照旧。对应做法 4–6。

### C · 复用报告并切到正确渠道

1. 在工作台的原附件钮选「本对话的文件 › 对比报告.md」，现有附件位置出现 `对比报告.md ×`。可移除；如果原文件已经不可用，给具体原因。
2. 点当前模型按钮进入旧顺序的菜单，点「更多模型…」，搜同名模型。结果显示各自的渠道，键盘确认。若用户按 Esc，附件和草稿仍在、选中模型不变。
3. 重新选择后，输入框写完整「模型 · 渠道」。发送时仅把用户看到的这一轮内容和已确认附件交给现有路径。若选的是模型组，真实回退还是遵循原规则并用原有提示。
4. 验收屏幕三态：有文件还未发送、同名模型结果、选中后仍有草稿。图片路由仍按能否看图验证。对应做法 7–8。

第一轮建议先画 A 的「切回已有对话」和 B 的「准确落到问题卡」，它们能看出单场景截图无法检验的状态衔接。C 可在第二趟核实允许复用的现有附件类型后，用演示文件走通一次。
