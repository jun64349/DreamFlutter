## 一、用户怎么用（用户 2026-11-09 确认）

- **主要用途**：日常工作处理；论文和代码；辅助学习；项目开发（包括物联网开发）。
- **工作台 = 用户主导**：用户把握工作怎么进行，Agent 是在旁边动手的助手。用户要看得到它在做什么、改了什么，关键操作要用户点头。
- **蝶君 = 高度自主**：用户只来聊天或布置任务，然后拿结果。过程不需要盯着，要的是进度说得清、结果交得出、卡住了才来找用户。
- **记忆 = 偶尔看一眼（B）**：不用管它，它自己记、自己整理；用户偶尔去看它记了什么，看到不对就改或删；对话里说一句"这条不对"也能改。

### 用户最烦的地方（用户 2026-11-09）

1. 各种功能解释又杂又乱。
2. 每个模块的交互逻辑各不相同，养不成操作习惯。
3. UI 动画不足。
4. 操作逻辑混乱。
5. 易用性不够，上手门槛高。

## 二、设计原则（用户 2026-11-09 确认）

1. **按用户的意图组织，不按后台模块组织**：每个界面回答"你现在想做什么"，而不是"系统里有什么"。
2. **默认自动，事后可查可撤**：任务边界、压缩、记忆写入和整理由系统判断，留记录，能撤销，不设按钮。
3. **只在三种时候打断用户**：要批准的操作；要用户做的决定；出了错需要处理的事。这些都进同一个"等你处理"。
4. **说人话**：界面不出现层级、状态码、tokens、快照这类内部词。
5. **一件事一个入口**。
6. **设置只放偏好，不放机制参数**：机制参数要么取消，要么放进每组底部的"高级"。
7. **让布局来说明**（用户 2026-11-09 加）：Avoid unnecessary secondary labels and descriptions. Let the layout do the explaining. 避免不必要的次要标签和描述，让布局本身来传达信息。能靠位置、分组、顺序、图标或状态看懂的，不再加副标题、说明行、提示文字；想加一行说明前，先看能不能改布局让它不需要说明。设计里明确要的除外：页面诗意标题下的直白名、状态短句下那一行实际在做什么。

## 四、核心流程（用户 2026-11-09 确认）

每个流程写成"你做什么 → 你看到什么"。括号里的编号对应第三节概念表。

### 4.1 安装和第一次启动

1. 双击安装包 → 选安装位置（默认给一个非 C 盘的推荐位置，如果有的话）→ 安装 → 自动打开。
2. 欢迎页：蝴蝶 + 一句话 + "开始"。
3. 向导五步，顶上有进度点，每步都有推荐值，可以一路"下一步"，也能"上一步"：
   1. **数据放哪**：默认跟软件放在一起；显示剩余空间。
   2. **怎么称呼你**。
   3. **连接一个模型**：选服务商 → 填密钥 → 自动测试连接（转圈 → 打勾，或者告诉你错在哪）→ 自动给出三个模型的推荐：对话、小任务、大任务。
   4. **默认工作区**：选一个常用的项目文件夹，可以跳过。
   5. **蝶君**：一句话介绍蝶君是什么；"现在准备沙箱（约 N 分钟，后台进行）"或"以后再说"。
4. 进入工作台首页：蝴蝶 + 问候语 + 3 个可以直接点的示例。向导里没填的，以后在设置里都能改。

### 4.2 再次打开（V07-02、V07-07）

1. 双击图标：如果已经开着，就把已有窗口调到最前面，不再开第二个。
2. 启动慢的时候显示启动画面（蝴蝶 + 进度一行字，比如"正在准备记忆……"），不让人以为没反应而再点一次。
3. 关窗口：默认缩到托盘，蝶君的任务继续；托盘菜单"退出"才真正退出，退出时有任务在跑会提示一句。

### 4.3 工作台：开始一件事

1. 顶栏点工作区名字 → 下拉选项目文件夹（或"打开文件夹…"）。
2. 侧栏"新对话" → 首页（问候 + 示例）。
3. 在输入框打字；可以拖文件进来、粘贴截图；输入框里能选模型和思考深度，有一个"无痕"开关（这次不保存、不记忆）。
4. 回车发送 → 回复开始流出。

### 4.4 工作台：看它做、批准

1. 过程默认收成一行（"正在读取 2 个文件……"），点一下展开，看每一步；命令和改动有自己的样式。
2. 需要批准时，对话里出现一张批准卡：做什么、为什么、会改哪些文件（改动可预览）。按钮：**允许**、**拒绝**，以及"这个对话里都允许这类操作"。如果你不在这个页面，"等你处理"上的数字 +1，同时发系统通知。
3. 随时可以停止；生成中也可以继续打字插话。
4. 出错时：对话里一行说清原因 + 能做的按钮（重试 / 换个模型 / 去设置），发送按钮恢复可用。

### 4.5 工作台：拿结果

1. 回复下面一行（悬停才出现）：复制、重新生成、从这里重来、⋯。
2. 右栏"本次改动"：改了哪些文件（点开看差异）、生成了哪些产物（点开预览或打开所在文件夹）。
3. 项目是 Git 仓库时，右栏有"提交这些改动"→ 自动写好提交说明，你可以改 → 确认提交。
4. 对话"⋯"菜单里有：存成技能、定时再做一次、这段对话不记忆、导出、删除。

### 4.6 选中追问

在回复里选中一段 → 浮出"引用 / 问一下"：
- **引用**：变成输入框里的引用卡片，接着问。
- **问一下**：右栏开一段小对话，不打扰主对话；问完可以"带回去"或关掉。保存后的小对话缩进显示在原对话下面。

### 4.7 交给蝶君一件事

1. 侧栏顶部切到"蝶君"。首页：蝶君的问候 + 当前在做的事 + 示例（"每周一帮我整理上周的周报"）。
2. 像聊天一样说要做什么，可以拖文件进来（这就是原来的"写笺"）。
3. 蝶君先用一两句话复述它理解的任务和打算怎么做；只有关键信息缺失时才问你。你说"可以"或者直接走开都行（等一会儿没回应就按它的理解开始）。
4. 任务进入蝶君的任务列表，状态只有四种：**进行中、等你、已完成、没做成**。

### 4.8 蝶君干活、卡住、交付

1. 进行中：列表那行显示一句当前进度（"正在汇总第 3 份表格"）。点进去能看过程，但默认收着。
2. 卡住了（缺信息、需要你批准、超了预算）：状态变成"等你"，进"等你处理"，并发系统通知。你在那里直接回答或点按钮，它就接着做。
3. 完成了：系统通知 + 侧栏蝶君旁边亮一个点。点开，最上面是**交付卡**：一段总结 + 交付的文件（可预览、打开、另存）+ 花了多少钱和时间。
4. 不满意就在同一个对话里接着说，它在原来的基础上改。
5. 说"每周一都做一次"，它就建定时任务；在任务详情里能看到下次什么时候做，可以暂停或删除。

### 4.9 处理"等你处理"

1. 侧栏一个入口"等你处理"，有数字；数字变化时有动效。
2. 列表分两组：**现在需要你**（批准、问题、卡住的任务）和**有空看看**（采用一个新技能、接一个服务、一条要提升为全局的记忆）。
3. 每项一行：谁（工作台 / 蝶君 / 哪个对话）+ 要你做什么 + 为什么；旁边直接有按钮。点了之后这项淡出，底部给"撤销"。
4. 想看来龙去脉就点"去看看"，跳到对应对话的那个位置。

### 4.10 找回以前的东西

1. 侧栏顶部一个搜索框：一次搜对话（标题和内容）、产物文件、记忆，结果按这三类分组。
2. 对话列表按时间分组（今天、昨天、本周、更早）；不想看的可以归档，归档的在列表底部"已归档"里。
3. 删除的对话进回收站，30 天内可恢复。

### 4.11 偶尔看一眼记忆（B）

1. 侧栏底部"记忆"→ 分三组：关于你、关于这个项目、蝶君自己的。每条一句话 + 来源（哪次对话、哪天，可点）。
2. 顶部一个"最近"：这一周记住了什么、忘了什么，按天。
3. 改：点那条直接改字；删：删了底部给"撤销"。
4. 在对话里说"这条不对，我其实……"：它改好后在回复下面出一行小字"已更新记忆 · 查看 · 撤销"。

### 4.12 加技能、接服务

1. 最常用的方式是在对话里说："帮我找一个能处理 X 的技能"或"接上 X 服务"。它会先找现成的、成熟的方案，必要时自己写，在蝶君沙箱里试过，然后放进"等你处理"："采用技能 X？"附来源和试用结果。你点"采用"才生效。
2. 手动方式：技能页右上角"新建"→ 从文件夹导入 / 从链接导入 / 让 Agent 帮我做。
3. 技能页每行：名字 + 状态（可用 / 已停用 / 等你确认）+ 一句话；点进去看来源、用了几次、试一下、停用、删除。

## 五、统一交互规范（用户 2026-11-09 确认）

针对"每个模块逻辑不同""解释杂乱""动画不足""上手难"。所有页面都按这一套做，新功能也必须套进来。

### 5.1 只有三种页面结构

1. **对话页**：工作台和蝶君共用，布局一致，只有右栏内容不同。
2. **列表 → 详情页**：技能、连接的服务、记忆、渠道、任务、对话历史都用它。左边或上面是列表（每行：名字 + 一个状态 + 一句话），点开是详情；"新建"永远在列表右上角，单项操作永远在详情里。
3. **设置页**：左边分组，右边内容，顶上搜索。每组最下面是收起来的"高级"。

### 5.2 同样的事，同样的做法

- **删除**：直接删，底部弹出"已删除 · 撤销"（几秒内可撤）。只有真正不可恢复的（彻底删除、清空）才弹确认框。
- **开关**：列表行右侧的开关，点了立即生效，不需要"保存"。
- **编辑**：在详情里原地改，离开自动保存；出错时就在那个输入框下面提示。
- **等你处理**：所有要你点头或决定的事都在同一个地方，每项旁边直接有按钮（同意 / 拒绝 / 继续 / 结束），不跳转到别的页。
- **右键 / "⋯"菜单**：对话、消息、列表项都有，内容按同一个顺序排：常用操作在前，危险操作（删除）最后并标红。

### 5.3 说明文字的规矩

- **总原则**：让布局来说明（第二节第 7 条）。下面几条都是它的具体做法。
- 每页顶部最多一句话说明这页是干什么的；不写段落。
- 设置项只写名字，必要时加一行灰色小字；更多解释放在"?"悬停提示里。
- 一个词只有一个意思、全应用统一（建一份用词表，例如统一叫"对话"而不是会话 / 任务 / 会话文件混用）。
- 空页面不写解释，而是给 1～3 个可以直接点的示例（比如蝶君空着时："帮我每周一整理上周的周报"）。

### 5.4 动效

- 统一三档时长：短（约 150 毫秒，悬停、按下）、中（约 250 毫秒，展开收起、列表增删）、长（约 350 毫秒，页面切换、右栏打开）；统一缓动曲线。
- 必须有动效的地方：页面切换、右栏开合、列表项出现和删除、过程步骤展开收起、新消息出现、"等你处理"数字变化、开关切换、生成中的状态。
- 系统设置了"减少动画"时跟随。

### 5.5 降低上手门槛

- **首次启动向导**（参考 HanaAgent）：安装和数据位置 → 你的称呼 → 连接一个模型（填密钥）→ 选默认工作区 → 蝶君沙箱现在准备还是以后。每一步都有推荐选项，可以一路"下一步"。
- **默认就能用**：不改任何设置也能正常工作；模型只要求选三个：对话模型、小任务模型（标题、记忆整理）、大任务模型（压缩、深度分析），看图模型可选。
- **逐步展开**：一开始只露最常用的；用到了才出现相关入口（比如第一次接了 MCP，技能页才出现"连接的服务"分区）。
- **每个操作都有反馈**：点了就有变化（加载中、完成、失败及原因和下一步怎么办），不会"点了没反应"。
