# 悬停提示：规则和盘点

日期：2026-11-14。来源：上手门槛调研（`docs/research/onboarding/`）把「图标按钮悬停给一句简介」列为降低门槛的一项。Claude 按 `app/lib` 源码盘点了现状，再参考 HanaAgent 调研。**状态：建议，等用户看过再派给 Codex 改；没有改代码。**

## 一、现状

- 只有图标、没有文字的按钮一共 75 处（`IconButton`、`_ActionButton`、`PopupMenuButton`），**全部都有提示**。调研里「覆盖情况未知」那条可以划掉了。
- 自己用 `InkWell` 拼的图标按钮，只找到一处没有提示：**侧栏对话行悬停时出现的「⋯」**（`ui/sidebar.dart` 约 944 行）。
- 问题不在「缺」，而在「不统一」：同一个图标叫法不一样，有几条写得太长，快捷键写法有两种。

盘点方法：Claude 写的两个只读脚本，一个列出所有图标按钮和它们的 `tooltip`，一个找没有提示的自绘按钮。脚本没有放进仓库；以后要复查，按本文第三节的位置看就行。

## 二、规则（建议）

1. **只有图标的控件必须有提示；有文字的控件不加。** 提示只说明这个按钮做什么，不讲道理。要讲道理，说明布局本身有问题（「让布局自己说话」）。
2. **写动作，动词开头，越短越好**，一般不超过 8 个字。按钮暂时不能用时，写为什么不能用，例如「回复结束后才能编辑」。
3. **同一个图标，同一个词：**

   | 图标 | 统一叫法 | 用在 |
   |---|---|---|
   | ⋯ | 更多 | 所有「⋯」菜单 |
   | ×（弹窗、面板、大图） | 关闭 | 关掉一个层 |
   | ×（附件、引用、已选的项） | 移除 | 从一组东西里拿掉一项 |
   | ×（搜索框、输入框） | 清除 | 清空输入的文字 |
   | 垃圾桶 | 删除… | 写清删的是什么：「删除渠道」「删除记忆」 |

4. **快捷键写在括号里，键名之间用「 + 」**：「选择工作区（Ctrl + O）」。
5. **重要的事不能只放在悬停里**：授权、花费、删了找不回来这类信息，必须直接显示在界面上或者在确认框里。悬停只是补充。
6. 出现的延迟和样式用 Flutter 默认值和现有主题，不另定数字。调研里提的「12 字、300 毫秒」只是参考，不当标准。
