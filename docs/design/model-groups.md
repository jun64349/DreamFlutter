# 模型组（恢复，0.8.3）

日期：2026-11-11。状态：**用户已定（2026-11-11，第八节全部按建议），在 0.8.3 做**。2026-11-10 用户定过“模型组从 1.0 去掉”（[REVIEW-2026-11-10](../REVIEW-2026-11-10.md) 第三节第 1 条），今天用户改主意要恢复。原因：

- 订阅渠道的模型太多，比如 ChatGPT 登录后有四十多个。
- 用户同时有好几种订阅（ChatGPT 登录、编程套餐）和好几个按量付费的 API 渠道（中转站）。同一个模型常常几处都能用，需要“这个不行自动换下一个”。

## 一、模型组是什么

**一个模型组 = 一队“渠道 · 模型”。在所有选模型的地方，它和一个模型一样用；排在前面的用不了，就自动换下一个。**

两种用法，用的是同一个东西，不分两个功能：

| 用法 | 例子 |
|---|---|
| 同一个模型，几处都能用 | 「GPT-5.5」：ChatGPT 订阅 → 中转 A → 中转 B |
| 不同模型顺延 | 「日常」：ChatGPT · GPT-6.1 Sol → 智谱套餐 · GLM → DeepSeek · V4 |

## 二、放在哪（装进现有页面，不另起结构）

1. **「设置 › 模型」**，卡片顺序：
   - 「用哪个模型」（对话 / 小任务 / 大任务 / 看图）
   - **「模型组」（新）**
   - 「渠道」
   
   「模型组」卡片里每组一行：
   - 组名，下面是这一队，例如 `ChatGPT · GPT-6.1 Sol → 中转 A · GPT-6.1 Sol → DeepSeek · V4`；每个成员前面有状态点，绿是能用，黄是在等恢复，灰是停用。
   - 右边一个箭头，点进编辑。
   
   卡片底部有「新建模型组」。拖动整行可以给模型组排序（附录 B 第 3 条，用户早先要的拖动排序）。
2. **所有选模型的地方**列表都一样：最上面一段是模型组，下面按渠道分段，列各渠道的常用模型（见第六节）。这些地方包括：
   - 设置里的四个模型；
   - 输入框的模型按钮；
   - 出错卡片上的「换个模型」；
   - 蝶君、子 Agent、定时任务。
3. **编辑页**和渠道编辑页同一套样子：
   - 分卡片：「名字」、「这一队」、「高级」（默认折叠）。
   - 底部固定「测试」「保存」。
   - 有改动没保存就离开，会先问你。

### 编辑页「这一队」

- 一行一个成员：拖动手柄 · 渠道图标和名字 · 模型 · 状态点 · 删除。
- 「添加」打开选择框：按渠道分段，能搜索，一次可以勾好几个（比如把三个中转站里的同一个模型一起加进来）。
- 「测试」把每个成员都试一遍，结果标在各自那一行（用的是渠道页那套直白报错）。

### 「高级」里（默认不用碰）

- **订阅用完后，转到按量付费的渠道**：默认开。关掉的话，订阅都用不了时就停下来问你，不花钱。
- **和上一个轮流用**：勾上后，这一行和上一行算同一档，请求按比例分给它们（默认各一半）。适合几个中转站分摊着用。

## 三、什么时候换、换到哪（后台规则）

1. **先换 Key，再换渠道**：同一渠道有多个 Key 时，先在渠道里换一个健康的 Key（0.8.1 已经这么做），整个渠道都不行了才换下一个成员。
2. **会换的情况**：
   - 额度用完，包括 ChatGPT 的 usage limit；
   - 余额不足；
   - Key 失效或被拒；
   - 限流，Pi 自己重试过了还是不行；
   - 服务器出错或超时，连着失败。
3. **不换的情况**：
   - 内容太长：先整理上下文，再用同一个模型；
   - 你点了停止；
   - 回复已经输出了一半：换了会重复，这时出错卡片，你点重试。
4. **换到哪**：
   - 队里下一个能用的。
   - 同一档的按比例挑。
   - 订阅优先：只要还有订阅能用，就不轮到按量付费的。
   - 第 2 条里的失败会让成员“休息”到它恢复。额度类按平台给的恢复时间（ChatGPT 会告诉几分钟后恢复），没给就按现有的熔断时间。
5. **一个对话粘在一个成员上**：同一个对话一直用当前这个成员，因为提示缓存是按渠道算的，来回换会更贵、更慢。
6. **前面的恢复了**（要你定，见第八节第 2 条）：建议新对话从第一个开始用，正在进行的对话不回切。
7. **全都用不了**：错误卡片一行说清每个渠道为什么不行、什么时候恢复，例如「ChatGPT：额度用完，16:20 恢复；中转 A：余额不足」。卡片上有「重试 / 换个模型 / 去设置」三个按钮。

## 四、换了怎么让你知道（按“让布局说话”，不加说明文字）

- **回复下面那一行**写实际用的模型，例如「中转 A · GPT-6.1 Sol · 55 token/秒 · 24 秒 · 14:32」。用的是哪一个，一眼就能看出来。
- **换的那一刻**，对话里出一行很淡的提示：「ChatGPT 额度用完（16:20 恢复），换到 中转 A」。一次换只出一行。如果是从订阅换到按量付费，这一行用强调色（以前的“已转到付费渠道”）。
- **输入框的模型按钮**显示组名，悬停看现在用的是哪个成员。
- **右栏「上下文」块**多一行：模型组 · 现在用的成员。

## 五、组和成员不一样的地方怎么办

| 项 | 规则 |
|---|---|
| 上下文窗口 | 取组里最小的。这样换到窗口小的成员也不会超长，整理上下文按它算 |
| 思考深度 | 输入框列出组里任何成员支持的档位。到了不支持的成员那里，自动降到它支持的最近一档 |
| 看图 | 这次请求带图时，跳过不能看图的成员；全都不能看图时，交给看图模型（现有逻辑） |
| 花费 | 记在实际用的渠道和模型上，账本另记一份属于哪个组。花费页的「按模型」图照旧，以后可以加「按模型组」 |

## 六、顺带解决“模型太多”：渠道的常用模型

截图里的问题：ChatGPT 登录后有四十多个模型，全部挤在下拉框里。

- 每个渠道有「常用模型」，只有勾上的才出现在各处的模型列表里。
- 自己加的渠道，模型本来就是你填的，默认全部常用。
- 订阅登录这类模型多的渠道，默认只勾几个最新的主力型号，其余在渠道编辑页「模型」卡片里勾选。
- 模型列表最下面有「更多模型…」：打开后能搜全部模型，不必先去设置里勾。

这一条和模型组互相配合，但可以单独先做。

## 七、技术上怎么接（给实现看的）

- **后台**：
  - 从 `601aa2a^` 取回 `router.ts` 的 `pickEntry`（档位、权重、粘着、订阅优先），这套逻辑原来就有测试。
  - 恢复 `gateway.groups / saveGroup / removeGroup / reorderGroups` 和 Pi 虚拟模型注册。Pi SDK 的 `registerVirtualModel` 还在。
  - `gateway_groups` 表一直保留着，旧组的数据还在。但 0.8.1 已经把设置里引用旧组的地方换成了具体模型，这部分不自动换回来。
- **新增 1：ChatGPT 额度用完要认成“额度用完”**，并带恢复时间。现在只认 `usage limit reached / exceeded` 这几种写法，Pi 给的提示是 “You have hit your ChatGPT usage limit … Try again in ~N min”，要补上。
- **新增 2：订阅登录的渠道要算“订阅”**。现在 ChatGPT 登录这类 Pi 的 OAuth 渠道按地址认，会被当成按量付费，订阅优先就失效了。
- **新增 3：Pi 自己的服务商在组里时，包一层流**。旧代码就是这么做的，这样才能记录失败、熔断和换成员。
- **新增 4：常用模型**：渠道上记一个常用列表，窗口里的模型列表只列这些。
- **窗口**：
  - 从 `2ecc49e^` 取回模型组数据类，列表和编辑器按设置卡片的样子重写。
  - 模型列表改成“组在前、按渠道分段、常用模型”。
  - 出错卡片和对话里的“换到”那一行要接上。
- **测试**：
  - 后台：路由规则、订阅优先、额度恢复时间、同一个对话不乱换、带图跳过、ChatGPT 额度识别。
  - 窗口：卡片、编辑页的改动、保存、离开提醒、拖动排序。
  - 端到端：两个假渠道，第一个返回额度用完，确认换到第二个、对话里出了那一行、回复下面写的是第二个。
  - 每个新测试都要确认去掉修复会失败。

## 八、用户定的（2026-11-11，全部按建议）

1. 名字叫「模型组」：以模型为单位、按顺序自动切换的一组模型；不叫「号池」（用户 2026-11-11 又强调了一次）。可以建任意多个，名字、成员、顺序都由用户自己定。
2. 前面的恢复后：正在进行的对话不回切，新对话从第一个开始。
3. 订阅用完转到按量付费：默认开，开关在编辑页「高级」里。
4. 「和上一个轮流用」放进「高级」。
5. 常用模型和模型组一起做。
6. 单独做 0.8.3（0.8.2 已在本地提交：7399422、4fcbd18、5c8d5a8）。roadmap、交互设计、词表、测试清单里“去掉模型组”的记录改回来。
