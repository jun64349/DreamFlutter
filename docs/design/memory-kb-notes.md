# 高级记忆与资料库：讨论记录

2026-11-13 用户和 Claude 的讨论，**未定稿，以后版本做**（资料库、检索是基座内置功能，不是 2.0 的可插拔模块）。起因是 Anthropic 的《The components of agent memory》；调研提示词见 [research/agent-memory-large-corpus-research-prompt.md](../research/prompts/agent-memory-large-corpus-research-prompt.md)，调研报告见 [research/agent-memory-large-corpus.md](../research/agent-memory-large-corpus.md)（报告里部分「事实」的数字和 2026 年的文献还没核实，见第七节）。

## 一、用户已定的方向

1. **弱模型、强约束、固定规则**：为了压成本，平台用的模型按 Anthropic 文章的分法都算「弱模型」。现阶段记忆写入继续用固定类型、固定规则、程序校验；**不采纳**报告里「放宽类型限制」的建议。以后要用强模型做长程深度任务时，单独做一个可选的嵌入式模块，在那里弱化固定规则，让强模型自己判断该记什么。基座的程序校验不随之放松。
2. **文章那套做法主要用在蝶君**：蝶君长期自主学习和工作，需要「失败 → 假设 → 验证 → 写成带依据的规则」这类做事经验，要作为平台基础能力做进蝶君。工作台日常以现有的记忆快照为主，基本够用；但工作台的长任务（深度研究、写代码的计划）也需要长程的做事记忆，见第三节。
3. **回看原文要有触发时机，不做定期全量核对**：用户表示「你记错了」、记忆错乱、明显不满意时，触发「自我怀疑」，去查原始对话记录和会话里的文件来核对。见第二节。
4. **资料库和检索是以后的重点**，作为平台内置的基础能力。
5. **工作台以后改成「主控 Agent + 专精 Agent 团队」**（和蝶君无关）：灵感来自 DeepSeek Harness 团队的 Super Agent，由主控 Agent 派活和路由，团队内部有群聊式的沟通机制。成本待定，多 Agent 管理是重点。到那时再处理多 Agent 同写记忆的问题（Anthropic 的教训：一页只由一个 Agent 负责、原文逐字引用）。
6. **现有特色不能被新设计冲掉**：作用域隔离、改动留痕可撤销、锁定、彻底删除只留哈希、可信度分级、预算记账、约束靠程序。新设计只要检查会不会和这些冲突、导致不收敛。

## 二、自我怀疑机制（Claude 的展开，待用户定）

- **触发**：
  - 用户信号（主）：说「你记错了 / 不是这样 / 我没说过」，或纠正的内容正好来自记忆，或明显不满；
  - 程序信号（辅）：程序预筛出矛盾、用了某条记忆的任务失败或被用户推翻、记忆来源对应的文件变了。
- **范围**：只查这一次快照用到的条目（快照记录里有条目和版本），再加上**同一次提取、同一来源**的其他条目（同一次提取很可能犯同样的错）。不查全库。
- **做法**：记忆 Agent 顺着来源找回原始会话条目和会话里的文件，逐条核对，提出改动；程序校验后作为一个批次提交，可整批撤销；记忆日志写清楚「因为用户说记错了，核对了哪些，改了什么」。
- **和现有机制的关系**：用户纠正立即替换快照的机制不变（只修被点名的那条）；怀疑机制是在它之后多走一步，把可能同样错的条目一起查。

## 三、工作台的短对话和长任务怎么分（Claude 的展开，待用户定）

- Anthropic 文章里的记忆不只是单个长任务内部的记忆，而是**跨会话的做事经验**（CL-Bench 每题都是新会话，只靠记忆目录传经验）。
- 担心的问题成立：日常短对话也触发「做事经验」的写入和整理，会写进大量一次性的经过，干扰日常快照，不收敛。
- 建议**由程序判断，不由模型判断**，低把握时一律按短对话处理（和任务边界协议「低把握沿用当前」一致）：
  - 长任务的信号：有目标或长任务工作项（0.8 长任务内核）、计划模式、工具调用和轮数超过阈值、出现「失败后修好并验证」的过程；
  - **做事经验只在有验证结果时写**：目标验收通过、失败后换办法成功并经工具验证、用户确认。失败的任务只能写「避坑提示」，不能写成推荐做法（报告 5.3 的「结果门控」，和现有提取规则一致）；
  - 做事经验默认挂在工作区（项目）作用域，不进全局；不常驻快照，只在任务相关时检索出来。日常短对话照旧只走现有的用户记忆提取。

## 四、链接和逐层往下翻（Claude 的意见）

- 值得做。报告引 Anthropic 数据：wiki + 搜索每题省约 2 万 token，跨文档综合问题效果更好；但只靠 wiki（48%）不如搜索，**链接要和检索一起用**，不能替代检索。
- 我们其实已有半条链：快照素材句末标着覆盖的条目（#id），条目又有来源指回会话条目。缺的是一个「往下翻」的工具（素材 → 条目 → 来源摘录 → 原始会话），以及主题之间的横向链接。
- 链接的维护成本：死链和指向被替代条目的链接由程序零成本检查、自动改指到替代它的条目；不需要模型。
- 对记忆 Agent 的好处：整理和怀疑核对时只看相关的邻居，不扫全库。

## 五、报告建议里和现有设计冲突的地方（要定）

1. **删资料库文档 ≠ 彻底遗忘**：报告建议删文档时级联物理删除派生的记忆。这和「不自动彻底删除、软遗忘可恢复」冲突。建议：删文档只把由它支撑的记忆标「来源已删除 / 待复核」，派生的索引、分块、向量可以删；只有用户选「彻底删除」才走哈希黑名单那条路。
2. **按热度调度 ≠ 按热度遗忘**：报告建议按访问频率安排整理。现有设计规定「使用次数只作复核线索，不算证据；没被用到不是改动的理由」。建议热度只决定**先查谁**，不决定**改不改、忘不忘**。
3. **主 Agent 的「候选池」工具**：报告建议加 `mark_memory_candidate`，候选等记忆 Agent 核对后入库。这和「默认自动生效」冲突。建议：用户明说「记住」照旧用 memory_save 立即生效；新工具只给 Agent 自己推测、还没验证的假设用（进候选，验证后才生效）。
4. **快照里加资料库目录索引（200–300 token）**：要从现有 2000 token 的配额里分，配额怎么调要定。
5. **派生内容的作用域取最严格的交集**（报告 5.1）：和现有作用域设计一致，采纳。
6. **资料库内容标为不可信来源**：记忆 Agent 不能从资料库内容直接生成用户偏好或全局规则。和可信度分级一致，在来源上加一个可信等级即可。

## 六、报告里可以先记下的技术选择（资料库开工时再定）

- 检索：SQLite FTS5（中文要先分词，trigram 兜底）+ 向量（先 sqlite-vec，超过约 20 万分块再迁 LanceDB）+ 重排；
- 本地模型：Qwen3-Embedding-0.6B（降到 512 维、int8）、bge-reranker-v2-m3（INT8）；
- 入库快慢两条线：先做全文索引（几分钟内能搜），向量在后台低优先级慢慢补；状态机支持断点续建；
- 不做：全量 GraphRAG、ColBERT 多向量、全量预建 wiki。wiki 只给跨文档反复综合的主题按需建，单文档查找不建。

## 七、报告的可信度

- 报告给 Anthropic 文章安的几个数字原文正文里没有（如 wiki 膨胀到原文的 1.77 倍、第 1,935 步到达华蓝市、CL-Bench 的具体奖励分），可能出自文章的图，也可能是编的；其中「Sonnet 4.6 从 0.330 到 0.364 算翻倍」自相矛盾。
- 大量 2026 年的 arXiv 编号和博客（如「3,283 篇论文元分析，遗忘清除通过率不足 1.5%」）没有核实。
- 用法：技术选型方向可以参考；具体数字在拿来做决策前要抽查原文。
