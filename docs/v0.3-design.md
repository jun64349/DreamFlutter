# v0.3 设计说明：Agent 运行时、子 Agent、执行环境

- 对应 [roadmap.md](roadmap.md) 的 3.2–3.5。用户 2026-11-02：「先按你的做，效果不符合预期再改」。
- 调研：[research/subagents.md](research/subagents.md)、[research/wsl-sandbox.md](research/wsl-sandbox.md)（都是待核验素材）。

## 顺序

1. **子 Agent（3.4）先做**：不依赖沙箱，用户要求「立即补上」。
2. **执行环境抽象（3.2）和 WSL 沙箱（3.3）一起做**：抽象要对着两种真实环境设计，只有本机一种时抽出来的接口多半不对。
3. 蝶君骨架（3.5）建在前两者上。

## 一、角色卡（Agent 运行时的核心）

一个「角色卡」描述一个可以被派出去干活的 Agent。子 Agent、记忆 Agent（0.5）、蝶君（3.5）都是角色卡。

| 字段 | 含义 |
|---|---|
| `id`、`name` | 例如 `explore` /「调研员」 |
| `description` | 给主 Agent 看的：什么时候派它 |
| `instructions` | 给子 Agent 看的：它的职责和交付格式 |
| `tools` | 允许的工具（标准模式工具的子集）。子 Agent 永远没有 `agent`（不嵌套）、`ask_user_question`、`exit_plan_mode`、`todo_write` |
| `model` | 指定模型或模型组；空 = 跟主 Agent 同一个 |
| `maxTurns` | 轮数上限，到了就停下交回已有结果 |
| `env` | 执行环境：`host`（本机）；3.3 起可以是 `sandbox` |

0.3 内置两张：

- **通用（general）**：除上面排除的之外的全部标准工具，做一件完整的子任务。
- **调研员（explore）**：只读：读文件、搜索、读网页、读文档、看图、只读命令。用来查资料、读代码、找东西，不改任何文件。

以后用户可以自己加角色卡（放在技能与模板旁边，0.7 的管理页）。

## 二、子 Agent 工具 `agent`

- 主 Agent 调用 `agent`，参数：`role`（角色卡 id，默认 general）、`description`（3–8 个字的标题，窗口里显示）、`prompt`（完整的任务说明：子 Agent 看不到主对话，要把需要的背景都写进去）。
- **并行**：同一轮里调用几次 `agent` 就同时跑几个（Pi 的 `executionMode: "parallel"`），上限 4 个同时跑，多的排队。
- **上下文**：全新，只有角色说明 + 任务说明（研究报告里各家的共识：子 Agent 用干净的上下文，只交回摘要，主对话才不会被撑爆）。
- **结果**：子 Agent 最后一条回复作为工具结果交回；附带轮数、token、花费、用过的工具。长内容让它写成文件，回复里只给路径和要点。
- **审批**：子 Agent 的工具调用走同样的审批规则（工作区「总是允许」也算），审批框出现在主对话里，标题注明是哪个子 Agent 要做。
- **停止**：主对话点停止，子 Agent 一起停。
- **花费**：子 Agent 的花费算进主任务这次运行（每日 / 每月上限照样管住它）。
- **窗口**：子 Agent 在过程块里占一行「子 Agent · 调研员 · 查找 X」，运行中显示它正在做什么，结束后可以展开看它的回复和统计。

实现：子 Agent 是一个只在内存里的 Pi 会话（和临时对话同一种），复用后台创建会话的那套（模型网关、审批、读网页、读文档），不加载记忆、定时、技能提议、卡片这些属于「一个对话」的模块。

## 三、执行环境（3.2，和 3.3 一起做）

工具不直接碰本机，而是经过「执行环境」：

| 能力 | 本机 | WSL 沙箱 |
|---|---|---|
| 执行命令 | `pwsh`（常驻 / 单次 + 后台任务） | `bash`（经一个常驻 `wsl.exe -u agent` 进程） |
| 读写文件 | Windows 路径 | Linux 路径 `/workspace/...`，宿主经 `\\wsl.localhost\<发行版>\` 读写 |
| 搜索 | 自带 rg | 沙箱里的 rg |
| 审批 | 照旧 | 沙箱里不审批 |

提示词随环境变（沙箱里告诉模型它在 Linux 的 `/workspace`，用 bash）。沙箱的具体做法按 roadmap 3.3 和 WSL 调研的修正（Debian 底包、`agent` 用户无 sudo、启动时以 root 卸载 `/mnt/wsl` 和 `/mnt/wslg`、vhdx 复制重置、`ip link` 离线）。

**跨环境派活**（调研的「沙箱探路」）：沙箱就绪后，`agent` 工具的角色卡可以指定 `env: sandbox`，工作台的 Agent 就能把试装依赖、跑不放心的代码派到沙箱里。
