# DreamFlutter v0.3.4 发布说明

按用户 v0.3.3 实测（`dfv0.3.3测试记录.md`）做的补丁版。报告里没有别的明显 bug，这一版只修下面这几件事。

## 修好的问题（v0.3.3 实测）

- **行内代码、文件名选中时还是不显示高亮**：v0.3.3 以为修好了，其实没有。我们去掉了自己写的底色，但 Markdown 组件会把它自带的默认样式合并进来，默认的行内代码样式带一层浅白底色，正好盖住选区。现在明确写成「没有底色」，并加了测试直接检查画出来的文字有没有底色（上一版的测试只查了我们自己写的样式，所以没发现）。文件预览里的 Markdown 也一起改了。
- **文件名链接后面断了行**：链接原来是段落外的一个单独小部件，所以它后面的字被挤到下一行，拖选整段时它也不在选区里。现在链接嵌在句子里：不断行，跟着选区一起高亮，复制出来的顺序也对。
- **链接的说明气泡去掉了**：照你说的，鼠标移上去时链接铺一层浅底色、下划线变深、光标变成手形，一看就知道能点。左键在资源管理器里显示（文件夹直接打开），右键用默认程序打开，和原来一样。
- **排队消息发出后、以及平时时不时「往上弹」、不明的刷新**：在测试里一帧一帧地看，「贴在底部」时排队消息插进去、工作过程折叠，位置一直是对的，所以弹跳出在**你往上看的时候**。查到三个原因，都修了：
  1. 对话列表会把滚出屏幕的消息先拆掉，滚回来再重新搭建。卡片重新搭建时先显示一个矮的「正在打开…」，再撑到真实高度（体检报告那种卡片有好几百像素），下面你正在看的文字就被整体推下去，看起来就是「往上弹」。图片解码、折叠状态也会这样。现在加了**阅读锚定**（浏览器也是这么做的）：你没在底部时，屏幕上方看不见的部分变高变矮，眼前的内容保持不动。
  2. 卡片的信息和高度记住了，滚回来直接是原来的样子，不再先闪一下「正在打开…」。
  3. 生成过程中往上翻，滚回来的旧消息会重播一次「淡入」动画，像整段对话在刷新。现在只有真正新出现的消息才有入场动画。
- 另外：**发消息（包括插队的消息）时，对话回到底部**并跟着往下走。原来如果你正往上看着，按 Enter 后看不到自己刚发的话。

## 没改的

- 蝶君沙箱体检报告（81 分）：缺 C 编译器、Node、ffmpeg、OCR，跑 Chromium 缺 14 个系统库（蝶君自己从 Ubuntu 归档下 deb 解包才跑起来，在 Debian 沙箱里混用 Ubuntu 的包不稳）。这些要往沙箱镜像里加软件，镜像会变大，放进 0.4 计划里一起定，这个补丁不动镜像。OpenAI 421、知乎 / 百度反爬是对方网站的限制，不是应用的问题。

## 测试

- 新增回归测试（都确认过「去掉修复测试就失败」）：
  - `markdown_view_test`：行内代码和文件链接画出来没有底色；文件链接和前后文字在同一段里、同一行；拖选整段时链接显示为选中；复制出来是完整的一句话；没有说明气泡。
  - 视觉检查的示例回复里加了一个文件名，截图里看过：在句子中间、没有底色、有下划线。
  - `chat_reading_test`：往上滚到一张卡片刚被重新搭建、还没拿到信息时，等它撑开，眼前那条问题的位置一像素都不动；卡片滚走再回来直接是原来的高度；生成中滚回来的旧消息不重播动画；往上看时发消息回到底部。
  - `chat_scroll_test`：排队消息插进去、工作过程折叠、运行结束，每一帧都贴着底部（这个在修之前就能通过，留作防护）。
- 全量：窗口 102、协议层 43、后台 199 + 类型检查、场景巡检 5、视觉检查、卡片，全部通过。
- 真实模型端到端：所有步骤都走通，但测试被判失败，原因是一开始就冒出的 Flutter 框架内部的语义树错误（v0.3.0 时出现过，v0.3.3 那次没有）。为了确认不是这次改的，把窗口代码换回 v0.3.3 又跑了一次，同样报这个错，所以和这个补丁无关，是这台电脑上时有时无的老问题，留到 0.4 做外壳时查。

## 要你试的

1. 找一个上面有卡片（比如体检报告）的长对话，用滚轮慢慢往上翻，看还会不会突然跳。
2. 生成过程中往上翻一翻，旧消息不应再一闪一闪地淡入。
3. 生成过程中往上看着时插一条消息，应该回到底部看到它。
4. 回复里有行内代码、文件名链接的一段，拖选整段，看高亮；鼠标移到链接上看看效果。
