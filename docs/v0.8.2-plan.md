# v0.8.2：按 0.8.1-test.2 实测报告修复和优化

日期：2026-11-11。来源：用户实测 0.8.1-test.2 的报告（`dfv081测试记录.md`，12 条带截图），用户评价"很失望""极度的不满意"（最生气的是第 10 条：蝶君发一句话就进一次「等你处理」）。

## 一、为什么会这样

- **蝶君被做成了"每句话都是一个任务"**：0.8 按交互设计 4.7「先复述再开工」做成了：蝶君对话里每发一句，窗口都先让后台用小模型"复述任务"，生成一份开工计划挂进「等你处理」，再把下一句拼成"原任务 + 用户补充：…"重新复述。打招呼也被当成任务，对话本身从来没发给蝶君，所以"输进去都没反应"，上面一块计划卡、下面一块对话，"上下是两个界面"。
- **设置页只照搬了原型的分组，没照搬它的版式**：原型把设置限制在 900 宽的一栏里，我们的实现铺满整个窗口，名字在最左、值在最右，全屏时对不上。渠道编辑页是旧的毛坯，编辑时下拉框和选择片改了不会保存（只有输入框失焦才存），也没有保存和测试按钮。
- **"打开对话"被当成"对话有新动静"**：侧栏按"最后活动时间"排，而打开一个对话本身会刷新这个时间（窗口端），打开时 Pi 还会往会话文件里追加模型、标题等记录（后台按文件修改时间排）。
- 其余几条（花费只有横条、记忆一长串、右栏两个文件列表、回复下没有速度和时间）是 0.8 / 0.8.1 做得太省，没对照用户以前说过的要求。

## 三、设置页调研（RikkaHub、HanaAgent / openhanako，2026-11-11 看源码）

- **openhanako**（`desktop/src/react/settings`）：设置是固定宽度的面板；每组是 `SettingsSection`：标题在卡片外，内容在一张卡片里，行（`SettingsRow`）左名右控件、行间一条贴边细线；服务商是"左列表 + 右详情"在同一张卡里，列表按 OAuth / 编程套餐 / API 分组，每项一个状态点；密钥输入框失焦自动保存，旁边一个「验证连接」按钮（保存并测试），结果用提示条说清楚。
- **RikkaHub**（`ui/pages/setting`）：总设置页是分组的列表（每项名字 + 一行说明），点进去是详情页；服务商详情分「配置 / 模型」等标签页，底部固定「保存」，右上角删除，有专门的「连接测试」；模型在自己的表单里改（不在一行里塞所有字段），获取模型列表后多选添加。
- **我们采用的**：内容限宽居中 + 标题在外的卡片 + 行间细线（openhanako）；渠道"列表 → 详情"，详情底部固定「测试连接」「保存」，模型单独对话框编辑（RikkaHub）；难懂的迁移、版本细节进「开发者选项」。
