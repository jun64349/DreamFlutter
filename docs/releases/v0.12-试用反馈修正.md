本轮通知需求必须触及 Core 的设置和通知分发；原有字段/读写路径保留，只新增 workbenchNotifications 和 butterflyNotifications。蝶君结果按明确任务来源、未完成的 started intent 或实际成功写入/命令等动作识别；纯文本自由对话没有可靠任务完成标记，仍保持静默。关闭来源会抑制延迟通知，不在重新开启时重放旧通知。

- chat_reading 原有阅读/选择守护通过；新增菜单在物理缩放 1.0、1.25、1.5、1.65 下 4/4 通过。1.65 即新基准显示的 150%。包含滚动、菜单位置与引用操作。初次菜单测试取到了换行间隙，已改为真实字形边界；旧阅读夹具显式保留旧字号，未改变行为断言。
- inline_settings 最终 6/6 通过，包括新增草稿保护与延迟保存。曾出现按钮不在视口的假点击警告，已修为滚动后点击，并明确断言后台保存已开始、按钮禁用；加载时按钮定位也已修正。最终无未命中警告。
- 定向分析涉及 18 个 Dart 文件，零问题；原型 JS 语法检查通过。Core 通知定向检查、类型检查通过，命令和范围见任务卡。
- 原生 Windows 只拍 trial-* 11 个场景，保留 1500×920 PNG。首批 9 图成功，最后菜单场景因样本正文定位失效中断；修正样本定位后只补菜单与折叠位置，后仅补新增表单构图和外观开关状态，没有重拍整套。
- 日志位于 app/build/trial-*.log。早期失败日志保留，最终菜单日志为 trial-menu-final.log，分析为 trial-analyze-final.log，实窗补拍为 trial-native-final.log / trial-native-editors.log，inline 子代理最终回执为 trial-inline-agent-result.txt；各批有重合，不相加为全量结果。
