# 梦蝶 V1.1.0 · Windows x64

本次提交的源码版本为 **1.1.0+23**，包含[真机反馈修正](v1.1.1-test.1.md)。普通版首次启动时，在向导里完成其余偏好即可进入工作台；模型渠道、蝶君语气和工作区可在设置中单独配置。下文的安装包及实测数据对应先前交付的 +21 构建。

梦蝶随程序交付官方 DeepSeek Harness 0.2.2-rc.5、Cordis 4.1.0 和 Node。窗口连接同一台电脑上的后台，打开已有记录、浏览插件和运行本地工具都在本机完成。选择在线模型或读取公开网页时，网络请求按用户配置发往相应服务。本版使用 Windows 原生 AppContainer 运行蝶君。

## Windows 程序

本地交付版本为 **1.1.0+21，Windows x64**。安装版运行 `DreamFlutter-Installer.exe`。免安装版请完整解压，再双击解压目录最外层的 `DreamFlutter.exe`。

使用安装版并把数据放在安装目录以外时，卸载程序可以从 Windows 的「已安装的应用」打开。程序内的卸载预演与「找回保留数据」只处理能确认归属的安装目录数据。外置资料可通过备份或再次选择原文件夹使用。[卸载与数据保留](../api/uninstall.md)

如果 1.0 曾把数据放在安装目录之外，升级后又出现欢迎页，请在数据位置向导里选原文件夹。早期版本可能只记了一个全局路径，无法确认这份资料属于哪一份安装。再次选择会沿用旧记录。

1.1.0 会为每一份安装记住所选目录。把便携版和包内数据一起复制到另一块盘时，新副本可按相对位置找回自己的数据。数据放在包外时，另一份安装需要自己选择目录。[Windows 数据位置回归](../../app/windows/tests/data_location_test.ps1)

## 打开旧对话

更新后可以像原来一样查看 1.0 的记录、分支、工具结果和图片。点「继续」会建立一条新对话，以选中的分支为上文。新模型收到该分支保留的消息、附件和工具结果；旧记忆快照、旧系统指令及其他分支仍保存在历史记录里。可以分别打开原记录与这条新对话。过去的工具调用保留为记录。工作台的标准、极简、无痕、侧边会话和蝶君使用 DSH 的本机会话与 AgentLoop。无痕对话的上下文和图片在内存中处理。[会话契约](../../core/test/api-contract/dsh-workbench.test.ts)

## 蝶君的 Windows 工作区

蝶君使用独立 Windows 身份、专用工作目录和受限进程。文件读写、PowerShell、Python 子进程、执行预算和审批沿用原来的入口。需要建仓、提交或使用 Git worktree 时，可以在「设置 › 蝶君 › 蝶君沙箱」选择「启用 Git 兼容工作区」。窗口先显示新的实际位置，确认后迁移工作文件。原目录保留，重启使用上次选中的工作区。Windows 在部分较深的数据路径下会启用 PowerShell 受限语言模式。普通命令与管道仍由 PowerShell 执行。可按名称和字面参数直接调用随包的 Node、Python、Git、rg、fd 和 uv；这些进程使用同一个 AppContainer。旧版 WSL 的磁盘位置可在设置中查看。已有 1.0 备份若包含沙箱，可从备份恢复工作文件及个人目录。在 1.0 中只备份了普通应用数据的用户，仍需要保留原沙箱里的工作文件。旧 Bash 脚本、Linux 二进制程序和 apt 安装的软件包需要相应的 Windows 实现，含 Linux 专用文件名、链接或设备文件的归档受 Windows 恢复规则约束。[蝶君 API](../api/butterfly.md) · [原生工作区集成测试](../../core/test/appcontainer-provider.test.ts)

### HTML 截图

Windows 原生蝶君可以把本地静态 HTML 和 CSS 渲染为 PNG，工作区内的样式表和图片通过受限文件接口读取。系统渲染器支持的 CSS 与 Chromium 有差异。依赖 JavaScript、Canvas 脚本或网页联网才能生成的内容，可以用随包 Python 和 matplotlib 导出 PNG，再作为本地图片放入报告。验收核对了图片实际像素、出箱文件字节、外部请求数和投递列表。[工具说明](../api/agent-tools.md) · [截图实测](../../core/test/render-html.test.ts)

## 验收环境

窗口插件验收在 Windows 实窗里使用实际后台和同一份隔离数据库。记忆试验启动三个独立后台进程，分别核对启用、停用、重新启用时发给模型的内容。渠道切换、计费与模型回答均用本地测试数据；隔离进程、文件、备份和更新器实际运行。[窗口测试](../../app/integration_test/v11_plugins_test.dart) · [模型与插件测试](../../core/test/dsh-models.test.ts)

本次实测使用 Windows 11 x64 开发机上的独立目录和用户数据副本。安装器已做文件和内嵌载荷校验，全新 Windows 系统上手动运行安装器的完整流程尚未实测。模型对话走本地测试端点，未调用付费模型。
