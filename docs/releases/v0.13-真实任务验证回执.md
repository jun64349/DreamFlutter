## 修复与复验（2026-11-17，用户要求修 1–3）

- **问题 1 技能**：技能登记表加修订号；已开对话发现修订号变了，就按同样的信任/启用过滤重新读技能列表，技能目录与 skill 工具都用它（`core/src/pi/host.ts`、`agent/harness.ts`、`agent/interaction-tools.ts`、`modules/library-registry.ts`）。停用也在已开对话里立即生效。
- **问题 2 日程写入**：查明蝶君的沙箱会话本就放行全部工具，没写成是任务说明里「只允许只读工具」让模型自己没动手。蝶君的日程不再带这句；宿主上的工作台日程仍只读，说明改为「需要就照常调用，被拦会记为没做成」（`modules/scheduler.ts`）。
- **问题 3 没做成记完成**：定时运行中有工具被拦，运行记为失败并写明哪些工具没放行，不自动重试，任务同步记为失败（`modules/scheduler.ts`、`modules/tasks.ts`）。按设计把显式写记忆改为候选的拦截不算。
- **回归测试**：`core/test/v013-fixes.test.ts` 3 项，修复前均失败。受影响的 33 个后台测试文件 265 项：除改动前就失败的 7 项外全部通过（同一批在改动前代码上对照跑过，7 项相同：T102、T106×2、T99、T73 技能计数、重放完成、T120 预算提醒，未改其期望）；记忆相关 101 项通过。
- **真实复验（第 5 轮）**：只跑日程、技能、收尾。日程：沙箱写出「日程任务完成」，提醒照常通知；技能：批准前已开的对话调用成功并盖章。5 次请求，闸门估算 USD 0.0072。**九项全部通过**；五轮合计 53 次请求，USD 0.0595。

## 发现的问题（1–3 已修，其余待用户决定）

1. **技能：批准前已打开的对话用不了新批准的技能**。离线复现：先开对话、再导入并批准，skill 工具报找不到；批准后再新开对话则正常。窗口预先开好的空白「新对话」就属前者，且会话技能目录里列着它，模型看到却调不到。
2. **日程：时令页建的「蝶君去做」只有只读工具**。`allowedTools` 为空即只读，而界面没有放开写入的入口，所以凡需写文件的蝶君日程任务都做不成。与「沙箱里什么都能做」的方向不一致。
3. **日程：没做成也记为完成**。上条那次运行没产出文件，运行状态仍是 done、任务 completed。与「做完了由程序按客观证据判断」不一致。
4. **日程时间不认「N 分钟后」**，只认「今天 14:00」「明天下午3点」「每天 08:00」等。
5. **时令日历「二」那一列特别宽**（`app/build/v013_live_run2/S6_failed.png`），疑似排版问题。
6. **工作台的模型自称「蝶君」**（第一轮技能场景的回复）。
7. 工作台脚本的中文输出在 Windows 控制台显示乱码，数字与文件正确。
