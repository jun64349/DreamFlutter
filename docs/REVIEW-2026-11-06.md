## 4. 实际候选修改

| 编号 | 发现与触发 | 改动 | 验证 |
|---|---|---|---|
| R1 | MemoryWork.stop 调用 drain，暂停规则仍可放行 correction 优先级；3 秒后可能关库而模型作业未结束 | MemoryJobs 增加终止认领并等待当前作业的 stop；MemoryWork 传递取消信号，等待作业记账完成再允许关库 | 空闲队列不启动高优先级作业；忙队列只完成当前作业；完整 Core 退出接入 |
| R2 | 记忆模型在取消后仍可能返回工具调用；后续请求抛异常会让前面已发生的调用用量丢失 | 循环开始、模型返回后及每个工具执行前检查取消；捕获模型异常并返回已累计的用量 | 取消前不请求；迟到写入被拒但用量保留；第二次调用抛错仍保留第一次用量 |
| R3 | 任务边界判断的 8 秒 Promise.race 只停止等待，不取消模型；迟到费用漏记 | 超时/关闭均传入 AbortSignal，迟到判断不改变任务；收到的用量独立记账，退出等待记账结束；清理计时器 | 真实 8 秒超时和主动关闭两种假传输场景，迟到用量均入账 |

## 6. 未在本轮强行重构的项（交 Claude 评估）

1. **会话所有权**：窗口仍直接读/删除会话文件，Core 管索引和关联。V0.5 第 7 步应统一考虑关系与删除，避免两侧各自清理；本轮只修异步覆盖，未改变接口。
2. **大模块职责**：AgentController、MemoryModule、MemoryWork 偏大。按职责拆分有价值，但不应在第 7、8 步接口尚在变化时做大规模机械拆文件。
3. **预算规则分散**：tasks、context、memory 的限制和入账路径要在 V0.8 统一预算接入时核对；本轮只修已经明确会漏记的路径，不声称账本已经完全统一。
4. **同步会话扫描**：每分钟扫描目录并全量读变化的 JSONL，长会话下可能阻塞 Node。需要以大历史样本量测，再决定增量方案；未宣称当前已测得卡顿或性能提升百分比。
5. **历史已记录的待修项**：HANDOFF 的旧审查尚列有多进程锁竞争、回放与实时事件顺序、跨 Agent 文件锁等；本轮没有把这些历史条目自动标成已解决，应在对应专项验证中复核。
6. **停止的边界**：本轮选择在关库前等待已取消作业完成收尾，不再在 3 秒时直接遗弃写入。标准模型传输应响应 AbortSignal；若第三方传输永不响应取消，退出等待仍可能延长。未用另一个强制关库计时器掩盖该问题，Claude 复核时请关注这一取舍。
7. **模型费用的可见性**：只有供应商返回 usage 才能精确入账；请求已取消而服务端仍收费但不返回用量时，无法凭空补算。
