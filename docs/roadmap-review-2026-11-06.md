## 一、最重要的一条：后端优先（第 6 条）

用户原话（节选）：「如果说每次都是前端后端一起做的话，然后出现后端变动后前端失效的情况……交互冲突的情况是比较多的，所以我觉得我们现在主要集中在推后端的开发进度，优先完成后端，只做必要的前端，后端搞完了我们再去做前端的部分……做完后端的开发就把接口说明等相关的内容做成文档以后设计前端就可以更加清晰准确的定位然后与后端耦合」。

理解和做法：

1. **后端阶段**（0.5–0.9）：原计划各版本的后端部分照做，加上这次报告里的新能力。每样功能只配「能用、能测」的最少界面：沿用现有组件，设置里一个开关、一个简单列表就够，不做新设计、不追求好看。功能是否正确主要靠后端测试和端到端测试保证。
2. **接口文档**（0.10）：后台对窗口提供的全部接口（JSON-RPC 方法、事件、数据结构、错误码、会话里 Pi 扩展的 `df_*` 命令和事件）写成一份参考文档，配一套按文档检查的接口测试；同时清理接口里的历史包袱。
3. **前端阶段**（0.11，可分几个小版本）：照着接口文档统一设计、重做界面。这次报告里所有界面类的要求、原计划里挪出来的界面工作都在这里做。
4. 之后是原来的打磨 + 深度测试（改为 0.12），再 1.0。
5. 名画主题小版本（原定从 0.4.1 开始）**暂停到前端阶段**：主题属于界面，现在加会和前端重做冲突。

为什么认同：0.3.2 以来用户几次说「不收敛」，0.4 的全场景测试里也看到，界面一边追着后端改，一边自己重排，问题多半出在两者的交界处（例如侧边对话的后台会话没关、顶栏按钮的布局）。先把能力和接口定住，界面只设计一次。

## 二、逐条

### 1. 分叉的对话应该挂在原对话下面

- 现状：分叉（「分叉为新会话」）出来的对话在侧栏里是单独一条，有个分叉小图标，和原对话可能分在「今天 / 昨天」两组里。后台已经记着来源（会话文件头的 `parentSession`，数据库 `sessions.parent_session`），窗口只用它显示了图标。
- 去向：后端在 0.5 的「会话关系」里把来源关系做成正式接口（列表里带上父会话、子会话，侧边对话也在里面）；侧栏怎么分组、折叠在前端阶段做。

### 2. 内置 Git 版本管理（工作台和蝶君都要）

- 用户要的：右侧边栏里展示并操作管理，对话里也能直接让 Agent 用 Git。
- 现状：没有。Agent 现在只能自己在命令行里敲 git；沙箱镜像里装了 git；本机这台的 git 是 Hermes 带的，别的用户的电脑不一定有。
- 去向：0.7 新增「Git 服务和工具」：后台的 Git 服务（状态、改动对比、暂存和提交、分支、历史、回退到某个版本，回退前自动留一个可恢复的点），给 Agent 的 Git 工具（读的操作直接做，提交 / 回退按工作台的审批规则），工作台和蝶君都能用；右栏面板在前端阶段做。
- 要用户定：本机没有 git 时怎么办（随安装包带精简版 Git 约 50 MB，还是提示用户安装）。

### 3. 侧边对话也要保存、能打开查看，只是不参与平台的其他活动

- 理解（用户确认）：指 0.4 的「侧边对话」（分叉出来的对话本来就保存）。
- 用户定的规则：**保存下来，挂在原对话下面，可以打开看；不进记忆、不进搜索、不进任务；算进统计**（花费、用量照常统计）。
- 现状：侧边对话只在内存里（`SessionManager.inMemory`），点「结束」就没了。
- 去向：0.5「会话关系」：侧边对话存成单独的会话文件，标明「是谁的侧边对话、引用了哪段」；记忆提取、会话搜索、任务都跳过它；花费和用量照常记账。打开查看、在原对话下面列出来的界面在前端阶段做，0.5 只给最少的入口。

### 4. 上下文功能放进右栏

- 现状：右栏「上下文与花费」只有圆环和花费；详细数字、自动压缩开关、「立即压缩」在一个弹窗里（用户截图）。
- 去向：0.5 的上下文服务（5.12）把这些数据和操作做成接口（这本来就在 0.5）；搬进右栏是前端阶段的事。

### 5. 蝶君的「工作」页没什么用，要重构蝶君的交互

- 用户原话：「这些都没啥用不如我直接在交流对话里表达明确需求然后布置好工作任务就好了……思考需要删掉 / 保留 / 强调哪些部分内容功能」。
- Claude 的初步看法（方向，前端阶段细化）：
  - 保留并强调：和蝶君对话、它的产出物（交付的文件）、它在做的任务和进度；
  - 去掉：写笺和「交给蝶君」这一步（和在交流里直接说是重复的）；
  - 资料改成在对话里直接附上；产出物和任务放进右栏，和工作台一样。
- 去向：后端在 0.8 / 0.9 按「在交流里布置任务 → 目标服务推进 → 交付产出物」这条路做（0.9 的事件来源里「写笺交付」改成「交流里布置的任务」）；现有写笺、资料的后台接口先不删，前端阶段定了再清理。

### 6. 后端优先

见第一节。

### 7. 搜索 / 网页功能不行

- 现状：**没有搜索工具**，只有「读取网页」（`web_fetch`：直接下载 HTML 转成文字，不执行网页脚本，反爬的网站拿不到内容）。
- 用户提到 DeepSeek 官方的 Search 和 Fetch 接口（各自每 1000 次成功请求 5 元，按次计费）。用户的 DeepSeek 余额不多。
- 用户定：**先调研再定**。调研范围：DeepSeek 官方 Search / Fetch（接口、限制、能否单独用）；其他模型厂商的联网搜索；国内的搜索 API；网页抓取 / 正文提取服务；在沙箱里用无头浏览器渲染（ffmpeg、浏览器已记在「需要时再装」）；各自的价格、稳定性、在国内能否直连。结论出来后做成可切换的「搜索服务 / 抓取服务」，设置里选。
- 去向：0.6 新增「联网搜索与网页抓取」。

### 8. 子 Agent 的可视化

- 用户：放到 1.0 以后做 Agent 团队时再做，1.0 前能发挥功能就行。
- 去向：第七节「1.0 之后」。

### 9. 常用办公技能做成内置能力

- 用户要的：PPT、Word、Excel、PDF 等办公能力和大批量数据处理，做成平台内置、对话里用自然语言积极调用。
- 现状：Agent 要临时装 Python 包；用户截图里装 `pymupdf` 时 pypi 连接超时（网络问题），说明临时从网上装不可靠。沙箱镜像里已有 pandas、numpy、matplotlib、openpyxl。
- 去向：0.7 新增「内置办公与数据处理能力」：常用库随安装包带好（工作台的便携 Python 和沙箱镜像都带：Word、Excel、PPT、PDF 的读写和转换、表格大数据处理），配套的内置技能（怎么做出好看的文档、批量处理的套路），对话里按需调用；网络安装支持系统代理和国内镜像源（这条放 0.6 的网络部分）。原 8.9「Word / Excel / PDF 和表格可视化补齐」并到这里。
- 要用户定：带哪些库（会让安装包变大，像 4.8 那样先实测大小再定）。

### 10. 调研 Hermes 的记忆机制，强化遗忘机制的设计

- 用户：遗忘机制是平台独特能力的一部分，开发前一定要再加强完整设计。
- 去向：0.5 开工前的硬性前置（5.0a）：先调研 Hermes 的记忆机制（看有什么可借鉴），再把 memory-design 里遗忘机制的设计补强、和用户定稿，然后才写 0.5 的代码。

### 11. 后台任务也要显示出来，放右栏

- 现状：右栏「子 Agent 与后台」只统计「别的对话在不在跑」；PowerShell 开的后台任务（`job_*` 工具，用户截图里那个）的状态和输出后台没有对外提供，窗口只能显示一行「（无输出）」。
- 去向：0.8 的 8.5（后台工作与等待）里加「后台任务接口」：每个会话的后台任务列表、状态、输出、结束事件、停止；面板在前端阶段做。

## 三、顺带发现的

- 工作台里装 Python 包会因为网络超时失败（第 9 条的截图）：后台给工作台的 Python 环境传系统代理、可选国内镜像源 → 0.6。
- 0.4.0 安装包第一次试用的两处问题（升级后第一次启动超过 20 秒被判失败、顶栏按钮没靠右）已在打 tag 前修好，见 [v0.4-release-notes.md](v0.4-release-notes.md)。
