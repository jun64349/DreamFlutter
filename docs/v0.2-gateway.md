# 阶段 3b：模型网关、仪表盘、设置重组（用法，2026-10-31 已确认）

2026-10-31。按 [v0.2-plan.md](v0.2-plan.md) 第五节已确认的决定写：网关在后台里自建，不做对外接口，不导入 CC Switch；优先适配 DeepSeek 官方、中转站、GLM / Kimi / MiniMax 编程套餐。
下面写的是**「渠道」和「模型组」怎么用**。标「已确认」的四处是 2026-10-31 你拍板的（都选了建议的做法）。

## 一、两个新概念

**渠道**：一个能调用模型的地方 = 接口地址 + 一个或多个 Key + 这里能用的模型 + 价格。例子：

| 渠道 | 类型 | 说明 |
|---|---|---|
| DeepSeek 官方 | 按量付费 | 自动查余额 |
| 随想中转 | 中转站 | OpenAI 或 Anthropic 兼容接口，价格自己填 |
| 智谱 GLM 编程套餐 | 编程套餐 | 每 5 小时 / 每周有额度，显示用了多少、什么时候恢复 |
| Kimi / MiniMax 编程套餐 | 编程套餐 | 同上 |

**模型组**：你在输入框里选的「模型」，背后可以挂几个渠道里的模型，网关替你挑一个能用的。例子：

```
模型组「主力」
  1. 智谱 GLM 编程套餐 · glm-5.3        ← 优先用（套餐额度不花钱）
  2. DeepSeek 官方 · deepseek-flash     ← 1 用不了时用
  3. 随想中转 · deepseek-flash          ← 都不行时兜底

模型组「快速便宜」：DeepSeek 官方 · deepseek-flash
模型组「看图」：只挂支持图片的模型
```

一个渠道里的模型也可以直接选（和现在一样），不必都放进模型组。

## 二、日常怎么用

1. **添加渠道**：设置 › 模型与网关 › 添加渠道。先选平台（DeepSeek、智谱、Kimi、MiniMax、OpenAI 兼容中转、Anthropic 兼容中转），已知平台自动填好地址和接口类型，你只粘贴 Key；点「获取模型列表」勾选要用的模型；点「测试」发一句话确认能用。Key 和现在一样用 Windows 账户加密保存。
2. **建模型组**（可选）：给组起名，从各渠道里挑模型排好顺序。
3. **用**：输入框的模型菜单里，模型组排在最前面，下面是各渠道的模型。设置里的「新会话默认模型」「辅助模型」也都可以选模型组。
4. **看**：仪表盘看花费、额度、每个渠道是否正常。

## 三、网关怎么挑渠道（路由规则）

1. **按顺序**：每次从模型组的第一个开始，跳过正在「休息」的渠道（见第 3 条）。
   已确认：同一顺位放几个渠道时**支持按比例分流**（例如两个中转各 50%），默认不用，放在「高级」里。
2. **一个对话尽量不换渠道**：同一个对话第一次用了哪个渠道，之后一直用它，只在它出错时才换。原因：DeepSeek 等平台的缓存按渠道算，换渠道会让缓存失效，花费变多、速度变慢。
   已确认：这样做（不每次重新挑）。
3. **出错自动换**：遇到下面这些情况，这一次请求立刻换到下一个渠道，对话不中断，回复下方会注明「已从 A 换到 B：额度用完」：
   - 限流、服务器错误、连不上、超时；
   - **额度用完、余额不足、Key 失效**（Pi 自己遇到这类错误不会重试，网关会接管）。
   出错的渠道进入「休息」：限流等临时问题休息 30 秒起，连续出错时间加倍（最长 10 分钟），到时间先用一个小请求探测，正常了再用；额度用完则休息到套餐恢复时间；Key 失效则一直停用，直到你修改它。
4. **一个渠道多个 Key**：轮流用；某个 Key 出错只停这个 Key，同渠道其他 Key 照常。
5. **编程套餐用完时**：
   已确认：每个模型组一个开关「套餐用完后允许转到付费渠道」，**默认打开**，转过去时提示一次。
6. **全部都不能用**：显示每个渠道各自的原因（例如「GLM：5 小时额度用完，16:20 恢复；DeepSeek：余额不足」），不会无声失败。

## 四、额度和余额

- **编程套餐**：按平台的周期（5 小时、每周）显示已用 / 总量和恢复时间。平台有查询接口就用接口；没有就按网关自己记的请求数估算（标明「估算」）。用到 80% 提醒一次。
- **按量付费**：DeepSeek 等有余额接口的平台自动查余额（打开仪表盘时和每 10 分钟一次），低于你设的金额时提醒。
- **中转站**：多数没有统一的余额接口，只统计花费；你可以手动填「充值了多少」，按花费算剩余。
- 各平台的地址、额度和查询接口见附录 B（Antigravity 调研，实现时逐个实测）。

## 五、仪表盘

导航栏底部「仪表盘」打开（替换现在的用量统计页）：

- 顶部：今天 / 本周 / 本月的花费和 token，和上一周期比较；
- 渠道卡片：每个渠道一张：状态（正常 / 休息中 / 停用 + 原因）、余额或套餐额度条、今天的请求数、平均首字延迟、最近一次错误；
- 趋势图：最近 30 天每天的花费，可以按渠道或模型着色；
- 拆分表：按渠道、模型、工作区、任务看花费和 token；
- 预算：每日 / 每月花费上限（沿用现在的「每天花费上限」，加一个每月），到 80% 提醒。

## 七、现有配置怎么过渡

- 你现在在 Pi 里配好的服务商（包括 DeepSeek）**自动出现在渠道列表里**，标「来自 Pi 配置」，可以直接放进模型组，也可以在这里改 Key。不需要重新填。
- 现在的「备用模型链」自动变成一个叫「自动」的模型组，内容和顺序不变；选了「自动（主模型 + 备用链）」的旧会话照常能用。
- 新加的渠道存在 DreamFlutter 自己的数据里，**不写进 Pi 的配置文件**（Pi 命令行看不到它们）。
  已确认：这样做，不改动你的 Pi 设置。

## 附录 A：实现要点（开发用）

- **模型组 = Pi 的虚拟模型**（`registerVirtualModel`，现在的备用链 `core/src/ext/fallback.ts` 就是一个）：`route()` 按顺序、权重、休息状态挑物理模型；路由状态记在会话分支上（`VIRTUAL_MODEL_STATE_ENTRY`），实现「一个对话粘住一个渠道」；`reason: "retry"` 带 `failed` 时换下一个。回复记录的是物理模型，所以现有的 `usage_records` 天然能按渠道统计。
- **渠道 = 扩展注册的 Pi 服务商**（`registerProvider`，id 形如 `df.<渠道>`，多个 Key 时每个 Key 一个服务商 `df.<渠道>.<n>`），带自己的 `streamSimple` 包装 pi-ai 的流：
  - 记录每次请求（渠道、Key、模型、首字延迟、耗时、错误、token、花费）到新表 `gateway_requests`（schema 第 6 版），仪表盘和健康状态都从这里来；
  - Pi 的 `isRetryableAssistantError` 不重试额度 / 余额 / 401，这些错误在**还没输出内容时**改写成可重试的错误信息（保留原文），让 Pi 重试并调用 `route` 换渠道；已经输出了内容的错误不改写。
  - 重试间隔：换渠道时不需要等 Pi 的退避时间。实现时确认能否让 `route` 换渠道的那次跳过等待；不能的话在包装里直接试下一个渠道（同一请求内切换，只在没输出内容时）。
- **熔断**：每个（渠道, Key）一个状态：正常 / 休息到某时刻 / 停用；探测用 `providers.test` 同样的小请求。
- **额度**：编程套餐的周期窗口从 `gateway_requests` 计算，平台有接口时以接口为准；余额查询按平台写适配器（DeepSeek `GET /user/balance` 等，见附录 B）。
- **Pi 配置里的服务商**：`Providers.list()` 照旧读出来，作为只读来源的渠道（改 Key 仍走 auth.json / models.json）。
- **窗口**：新页「渠道」「模型组」在设置的「模型与网关」下；`usage_page.dart` 换成仪表盘；设置页拆成左侧分类。

- 额度用完多数也返回 **429**，Pi 会当成临时限流去重试。网关必须自己看业务码 / 关键字区分「限流（休息 30 秒起）」和「额度用完（休息到恢复时间）」，不能只看状态码。
