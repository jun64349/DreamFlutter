# T-118 失败情形与试跑记录

分支 `v0.10-backend`，基线 `8574a26`。A 段和 B 段空跑用隔离数据、假模型、通知替身和合成文件。B1 只导入生产筛选函数。

## A 段

| 用例 | 检查与证据 |
| --- | --- |
| A01 重复与乱序 | 后到的旧事件照常立项，两条事件各有一个规则命中、授权和目标，重复投递只记审计。 |
| A02 自己的回声 | 蝶君日程进事件入口后被忽略。由用户确认的主机写入实际执行，随后扫描认出产物，未再接活。用户替换同一个文件后，规则正常命中。 |
| A03 资料注入 | 文件走资料夹扫描、复制与立项。假模型尝试越出工作区写入，原件与外部哨兵保持原样，无交付效果和外发。明确邮件请求由交办入口要求补充范围。 |
| A04 规则变更 | 在模型响应返回受保护写入前分别关规则、缩小交付范围和切换观察。下一次操作均进入权限暂停。 |
| A05 重复跟进 | 同一操作编号在同一会话重复投递和重启后换连接重发，只登记一条跟进和一份授权。验证的是后台 `record.operationId` 接口。 |
| A06 用户优先 | 一个自主执行请求保持在途，交办仍可入队并先完成，随后自主目标暂停且未写产物。 |
| A07 先存后做断点 | 构造计划已存、已领取、目标已落库而未记录回执、已排队而启动回执未落库四个持久化状态。正常重启逐一对账，每个状态只有一个目标和运行意图。 |
| A08 已送达或已写入 | 实际调用假通知渠道和主机写工具。抹去自主效果回执后，文件按摘要核对，通知从统一送达回执补记。连统一送达回执也缺失时记待核对，两个情形都不重发。 |
| A09 停止 | 对话交办取消，学习和规则目标标为停止。重启、跨日、重投同一规则事件，三个旧目标都没有新执行账本。 |
| A10 交付硬门槛 | 模型先后对缺失、空文件和错目录产物报告完成，三次均缺交付检查项。正址非空文件和验收说明齐备后才发布一份交付回执。 |
| A11 重复阻塞 | 使用统一通知入口。重投、换租约和重启都沿用同一阻塞键。目标修订后新阻塞仍可送达。 |
| A12 花费对账 | 观察、规则自动执行、学习规划与执行、主动聊天都实际经假模型并入自主账，用户交办只入目标账。检查 10 条带金额的请求回执、执行来源归属和两边预算合计。 |
| A13 纯聊天 | 问候、流程咨询、间接提问、暂缓请求、引用的交办文字走普通回复，目标、交办和授权均为零。 |

在隔离源码副本分别关闭 16 处保护，13 个用例均有对应的预期失败。A07 和 A08 注入的是持久化断点状态，随后正常关停和重启后台。通知渠道没有能确认未知送达的远端查询接口。

## B1 筛选

同一批 30 句，先跑生产旧规则，再跑修正后的规则。人工标签包括普通聊天、沙箱目标、单一主机文件需审批、需补充范围。

| 版本 | 命中 | 误接 | 漏接 | 路由错 |

## 复跑命令

从 `core/` 运行。命令默认使用模拟环境，报告可通过 `--out <新路径.json>` 保存。

```powershell
npm test -- test/autonomy-scenarios.test.ts
node --disable-warning=ExperimentalWarning scripts/autonomy/run.ts --screen
node --disable-warning=ExperimentalWarning scripts/autonomy/run.ts --dry
```

实际试跑入口接受 `--live --source <已有渠道配置的数据目录> --max-usd <获批整轮上限>`。它会复制指定渠道到独立目录、导入独立 WSL、在结算前预留预算，并清理本轮创建的隔离资源。预算建议与批准事项见任务卡第 4 节。
