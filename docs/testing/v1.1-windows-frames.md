# V1.1.0 真机反馈第 7 项 · Windows 窗口帧时间

2026-11-21 在 Windows 11 x64（26200）、Intel Core Ultra 5 125H / Intel Arc 上运行 Flutter 3.47.8 Profile。引擎使用 Impeller OpenGL ES，屏幕报告 170 Hz，应用实际渲染 1732 × 1078 像素，系统缩放 125%、应用缩放 110%。使用默认浅色主题、纸纹和动画。

## 怎么测

- 首页在桌面窗口中连续运行 3.4 秒，动画自然推进。帧数只在这段持续动画中换算为每秒产出帧数。
- 工作台预载 80 轮、160 条历史消息，调用侧栏打开设置所用的控制器方法，开合五次，各间隔 450 毫秒。渲染、布局、动效和生产界面使用同一套组件。
- 同一会话逐段输入 2,637 字符的 Markdown，26 字符一段、间隔 32 毫秒。在输出期间向实际工作台输入框应用 9 个编辑值，记录到 Flutter 完成该帧的时间。电脑键盘事件传递、引擎光栅化和屏幕显示延迟在这项输入数字之外。
- 从 Flutter 引擎采集每帧的构建、光栅化和整体耗时，取 P95。170 Hz 对应每帧约 5.88 毫秒。不同阶段可以流水执行，整体耗时和帧间隔是两种读数。

每轮启动独立的 Windows 进程。各组从同一份源码快照构建，只替换当轮测量的改动。数据和回复由本地夹具构造，外部模型调用 0 次。探针写完数据后主动调用 `windowManager.destroy()`，本机该退出路径出现 `0xC000041D`。交付的免安装包另行验证了正常关闭，窗口和 Core 的退出码均为 0。

## 纸纹和首页绘制

首页构建 P95 低于 1 毫秒，光栅化 P95 为 12.2–14.6 毫秒。把全窗纸纹的透明度交给图片绘制，用独立重绘层隔离固定纸纹和移动的首页笔触。纸纹仍然使用原贴图、透明度和重复方式，首页动效继续使用原时序。

| 场景 | 指标 | 基线两次 | 修改后两次 |
| --- | --- | ---: | ---: |
| 首页连续动效 | 3.4 秒内产出帧数 | 282 / 351 | 370 / 374 |
| 首页连续动效 | 整体帧耗时 P95 | 27.24 / 22.78 ms | 20.78 / 20.76 ms |
| 首页连续动效 | 光栅化 P95 | 14.57 / 12.18 ms | 12.44 / 12.09 ms |
| 设置开合 | 光栅化 P95 | 34.19 / 30.05 ms | 32.91 / 30.80 ms |
| 长对话流式 | 光栅化 P95 | 10.52 / 9.11 ms | 9.54 / 17.96 ms |
| 长对话流式 | 编辑值到 Flutter 完成帧 P95 | 12.57 / 16.64 ms | 20.19 / 22.81 ms |

首页持续动画从约 83–103 帧/秒提高到 109–110 帧/秒。设置开合耗时仍处于基线的波动范围。流式第二次整体帧耗时 P95 为 34.20 毫秒（基线 16.90–20.23 毫秒），两次修改后输入样本也都较慢。现有数据支持首页改善，设置开合、流式和实际键盘响应仍待进一步定位。

另在同一快照试过一次 shader 平铺整窗纸纹。两轮首页整体帧耗时 P95 为 36.13 / 34.65 毫秒，因此保留上表的图片透明度和重绘层方案。主题、减弱动效、对话滚动与选中、Markdown 定向测试共 41 项通过。

## 流式回复和输入补测

在同一份源码快照和纸纹补丁上加入工作台流式更新改动。每段首个非空片段及时通知窗口，同段后续文字由当前回复正文订阅，Flutter 按帧合并局部重建。新问答保留滑移和渐显，首帧已经可见。输入框没有引用时跳过无效的清除操作。同时开发的上下文统计、子代理显示和后台改动未参与这组测量。使用原探针和基线，再跑两个独立 Windows 窗口，每轮核对完整回复，采集 9 次编辑的耗时。

| 长对话流式指标 | 原基线两次 | 仅绘制优化两次 | 绘制和流式优化两次 |
| --- | ---: | ---: | ---: |
| 构建 P95 | 7.65 / 6.92 ms | 7.37 / 13.58 ms | 2.83 / 2.84 ms |
| 光栅化 P95 | 10.52 / 9.11 ms | 9.54 / 17.96 ms | 9.91 / 10.61 ms |
| 整体帧耗时 P95 | 20.23 / 16.90 ms | 18.60 / 34.20 ms | 18.53 / 19.47 ms |

两轮流式构建 P95 较原基线降低约 59–63%，两轮均无构建超过 16.67 毫秒的帧。整体帧耗时仍在原基线范围内。每轮 9 次输入的 P95 即最慢的一次，两轮都慢于原基线。当前结果确认流式界面构建开销下降，实际键盘到屏幕的延迟仍待验证。

## 最终聊天行入场修正复测

全量测试后的最终修正让每条新行只消费一次入场标记。流式更新继续使用该行已有的动画控制器，滚出屏幕后重新挂载也不会重播。向同一测量快照同步该修正，在免安装包实窗验证和压缩都结束后独立跑两轮，继续使用原基线。

| 长对话流式指标 | 原基线两次 | 最终修正两次 |
| --- | ---: | ---: |
| 构建 P95 | 7.65 / 6.92 ms | 2.57 / 2.61 ms |
| 光栅化 P95 | 10.52 / 9.11 ms | 9.54 / 9.46 ms |
| 整体帧耗时 P95 | 20.23 / 16.90 ms | 17.28 / 16.85 ms |

最终版两轮流式构建 P95 较原基线降低约 62–66%。整体帧耗时 P95 接近基线中较快的一轮。输入 P95 回到基线范围，P50 在这两个样本中仍较高。每轮只有 9 次输入，实际键盘到屏幕的延迟仍待验证。

## 复跑

在两个待比较的源码副本分别运行。每次启动的 `DREAMFLUTTER_DATA` 与输出文件仅对该探针进程生效。窗口保持可见。

```powershell
Set-Location 'E:\claude\DreamFlutter-2.0\app'
flutter build windows --profile --target tool/v11_windows_frame_probe.dart
if ($LASTEXITCODE -ne 0) { throw 'Profile build failed' }
$probeOutput = Join-Path (Get-Location) 'build/v11-windows-frame-probe'
New-Item -ItemType Directory -Path $probeOutput -Force | Out-Null
$probeRun = [guid]::NewGuid().ToString('N')
$probeLaunch = [Diagnostics.ProcessStartInfo]::new(
  (Resolve-Path 'build/windows/x64/runner/Profile/dreamflutter.exe').Path
)
$probeLaunch.WorkingDirectory = (Get-Location).Path
$probeLaunch.UseShellExecute = $false
$probeLaunch.EnvironmentVariables['DREAMFLUTTER_DATA'] = Join-Path $probeOutput "isolated-$probeRun"
$probeLaunch.EnvironmentVariables['DF_WINDOWS_FRAME_PROBE_JSON'] = Join-Path $probeOutput "$probeRun.json"
$probeProcess = [Diagnostics.Process]::Start($probeLaunch)
if (!$probeProcess.WaitForExit(55000)) {
  $probeProcess.Kill()
  throw 'Frame probe timed out'
}
Get-Content -Raw -LiteralPath $probeLaunch.EnvironmentVariables['DF_WINDOWS_FRAME_PROBE_JSON']
```

原始 JSON 的 `rawUs` 每行依次是相对该阶段第一帧的 vsync 起点、构建时间、光栅时间和整体耗时，单位都是微秒。
