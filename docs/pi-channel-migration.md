# Pi 服务商迁入渠道（6.1 / T-66）

渠道是应用模型配置的来源。应用启动时在自己的 agentDir 中读取 `models.json`、`auth.json`，迁入渠道后生成同目录下的 Pi 兼容配置。不会自动读取或写入用户的 `~/.pi/agent`。手动导入只在用户选择文件夹后读取，测试使用临时目录。

## 首次迁移与恢复

`PiMigration` 在网关启动前执行。数据库表 `pi_channel_migration` 保存版本、时间、源文件哈希、自动尝试次数、备份位置和结果；`pi_channel_map` 保存旧服务商 ID、渠道 ID、来源、保留的配置元数据及时间。已有成功标记时不再次自动导入。

步骤为：复用现有 `createBackup` 做数据库一致性备份及本机凭据备份，再逐字节备份 models/auth/settings → 准备加密凭据 → 一个数据库事务建立渠道与映射、改写所有引用 → 临时文件由 Pi 公开 `ModelRuntime.create` 加载校验 → 原子替换配置 → 再校验所有迁入模型 → 同事务写完成标记并提交。设置缓存在提交后刷新。

失败会回滚数据库、还原原文件并删除本次新建的加密文件；完成标记不写。失败状态显示原因和备份目录，旧 Pi 编辑入口仍可用。首次自动失败后，下次启动再试一次，此后只能手动“重试迁移”。映射表按原服务商 ID 去重；手动导入不会覆盖已迁渠道，即便所选文件夹同名服务商内容改变。已删除渠道的映射保留，避免重复导入复活用户删除的数据。

迁移备份位于 data/backups 下带时间戳和随机后缀的目录，含 `before.dfbackup` 和原始配置文件；这是本机迁移恢复副本，可能保留迁移前的明文凭据。日志、错误、界面状态和回执不输出这些值。

## 凭据与模型

- 明文 API key 及敏感请求头经现有 SecretStore/DPAPI 保存，并进入 T-63 脱敏登记；生成配置只含解密 `!command` 引用。
- 原有 `!command`、`$VAR`、`${VAR}` 引用原样保留。迁移/临时加载校验不解析环境变量、不执行命令；正常模型请求和用户主动 CLI 列模型时才由 Pi 处理凭据引用。应用请求解析得到的值也登记进 T-63 脱敏名单。
- OAuth 凭据不转成渠道密钥，原 auth.json 条目保持不变。渠道页登录白名单仅`openai`（显示“ChatGPT”，Pi公开目录的`OpenAI (ChatGPT subscription)`，按钮`Sign in with ChatGPT`）；可首次登录、重新登录、取消和退出，续期仍由Pi处理。`openai-codex`是legacy，与其他已登录OAuth一样继续通过`pi:`桥接和自动续期，保留只读项与退出，不提供重新登录；未登录的其他OAuth不显示。T-66已将`openai` API key移至独立`df-*`渠道和SecretStore，后续ChatGPT登录/续期/退出不会修改该渠道的密钥。此限制不影响API key渠道或MCP OAuth。
- cc-switch 前缀服务商标“来自 cc-switch”，其他导入项标“来自 Pi 配置”。迁入渠道可以编辑，完整模型元数据、请求头、上下文窗口、档位映射、图片支持和兼容字段保留。
- 默认、辅助、视觉、记忆、备用模型、窗口覆盖与模型组成员的旧引用，在同一个事务中改写。未知模型引用保留原值，并在状态/面板列出。
- 迁移不改历史会话文件；恢复时取当前分支最后一条模型变更或assistant记录的写入时间，仅在完成标记有效且条目早于该条映射创建时间时翻译旧引用，使用Pi公开的会话创建参数选择同一模型的新ID。缺失/无效时间不映射；后续手动导入不延长已有映射的期限，迁移后的OAuth记录保留原provider。设置引用已在事务中改写，运行时不再映射。若所选模型仍无法解析，会保留原文件与引用、停止恢复并在面板列出，不让Pi静默换成其他模型。正常会话后续写入仍由Pi管理。

## 兼容配置及外部修改

生成的 models.json 第一行写明“由 DreamFlutter 渠道生成，请勿手改”，Pi 支持 JSON 注释。数据库记录每次生成的 SHA-256 和时间。启动、保存/删除渠道或主动重新生成前，会比较当前哈希；外部修改先备份，再从渠道重建，并显示备份位置与手动导入提示。即使外部文件 JSON 已损坏，也会先原样备份。

“Pi 兼容配置”面板显示路径、时间、外部修改状态和可复制命令：

```powershell
$env:PI_CODING_AGENT_DIR='<应用的 agentDir>'; pi
```

路径中的单引号按 PowerShell 规则转义。DPAPI 密钥只适用于同一台电脑和同一 Windows 用户。Pi CLI 使用生成的物理渠道模型与第一个启用密钥；应用内模型组选路、轮换和网关统计继续由应用处理，不将这些运行时行为冒充成 CLI 静态配置能力。

“添加渠道”的 Pi 内置预设来自 SDK 公开的服务商和模型目录。选择服务商后选择所需模型，不手抄供应商列表。迁移成功后原 Pi 入口跳转渠道管理；失败时保留旧编辑页，迁移成功后的旧写入 RPC 会拒绝并提示去渠道页。

## RPC

沿用本地认证 Core RPC，无新监听端口。

| 方法 | 输入与行为 |
| --- | --- |
| `piMigration.status` | 状态、版本/尝试数、源哈希、映射、逐项结果、未映射引用、备份、路径、生成时间、外部修改状态、启动命令；不返回原始保留配置或凭据 |
| `piMigration.retry` | 无参数；应用自己的配置迁移；成功后再次调用是幂等读取 |
| `piMigration.import` | `{folder}`；只读所选 models/auth，跳过已有映射；已有渠道不覆盖 |
| `piMigration.generate` | 从渠道重新生成并更新哈希；先保留外部修改 |
| `piMigration.oauthStart` | `{provider}`；仅允许白名单`openai`，不要求已有登录；其他ID（含`openai-codex`）返回`oauth_login_disabled`且不动凭据 |
| `piMigration.oauthStatus` | `{id}`；流程状态及当前链接/提示，不返回令牌 |
| `piMigration.oauthAnswer` | `{id,value}`；回答当前登录步骤，值不进入日志或迁移状态 |
| `piMigration.oauthCancel` | `{id}`；取消登录 |
| `piMigration.oauthLogout` | `{provider}`；公开logout，只删除指定已保存OAuth；不删除API key。其他OAuth退出后从渠道页隐藏，ChatGPT可再登录 |

状态更新事件 `piMigration.changed`，OAuth 交互事件 `piMigration.oauth`。迁移期间拒绝修改渠道/组及新会话提示，避免并发配置变更混入事务。

## 验证证据

自动化覆盖四类凭据、9 个步骤注入失败后的数据库/文件/引用恢复、重复迁移、外部修改、只读导入、API/模型元数据和公开 CLI 列模型/旧会话恢复。另覆盖请求时命令/环境凭据解析后的脱敏、手动导入被中断后重启恢复既有成功状态，以及旧模型无法映射时保留历史文件并报错。界面覆盖迁移失败与重试、来源、未映射引用、外改提示、登录/退出及浅深色 150%。

真实验证脚本 `core/scripts/live-pi-migration-t66.ts` 仅允许 `E:\DreamFlutter测试版\data`。数据库以只读连接取得一致性临时副本，复制任务相关的 Pi 配置、会话和加密文件，排除缓存、运行文件、旧备份和 WSL 镜像。引用重定位及迁移都在临时目录中进行。非 SecretStore 的任意命令凭据会暂停真实 CLI 验证，不执行它。
