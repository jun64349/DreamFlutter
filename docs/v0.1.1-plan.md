# DreamFlutter v0.1.1 功能清单与架构

日期：2026-10-27
输入：用户的《Agent 功能模块设计》《开源 Agent 设计观察清单》，`docs/research/` 下 4 份调研报告，Pi 1.4.0 文档与 SDK 实测。

本版目标：把功能做全、做稳；界面只做到整洁可用，视觉设计放到下一轮。

标记：**必做** = v0.1.1 一定包含；**可选** = 必做完成且稳定后再做，不做不影响发布；**暂不做** = 记录在案，留给以后。
「Pi 自带」表示直接复用 Pi 的能力，我们只做界面和配置。

---

## 一、架构

```
Flutter 界面 ──WebSocket(127.0.0.1 + 令牌)── DreamFlutter 后台 (Node, core/)
                                               ├─ Pi SDK：会话在后台进程内运行
                                               ├─ 调度器：定时计划 → 执行 → 交付
                                               ├─ SQLite：记忆、书桌、任务、确认卡、计划、用量、全文索引
                                               └─ Pi 扩展：记忆快照、记忆/书桌/计划工具、审批
```

关键决定：

1. **后台用 Pi SDK 进程内运行会话**，不再为每个会话起一个 `pi --mode rpc` 子进程。实测（`createAgentSession` + 内联扩展 + 自定义 UI 上下文）记忆注入、自定义工具、审批弹窗、事件、统计全部可用。好处是：
   - 省内存；
   - 能用 RPC 没有的能力：会话内分支树导航（`navigateTree`）、导出 HTML、用量统计；
   - 扩展直接访问后台的数据库。
   代价是一个会话出错可能影响整个后台。应对：后台崩溃后由界面或托盘自动拉起，会话本身已由 Pi 持久化在 JSONL 里，运行中的任务标记为「中断」，并给出「继续」按钮。
2. **数据存储**：
   - Pi 的会话 JSONL 仍是对话记录的唯一来源。
   - 我们自己的数据放在 `%APPDATA%\DreamFlutter\core.db`，用 Node 内置 `node:sqlite`，不需要原生模块。已实测它支持 FTS5，中文用 trigram 分词。
3. **通信**：
   - 本机 WebSocket，只监听 127.0.0.1。连接令牌由后台首次启动时生成，存在 `%APPDATA%\DreamFlutter\core.token`，界面读取它来连接。
   - 后台只允许一个实例运行（锁文件 + 端口）。
   - 支持多个界面同时连接，事件会广播给所有界面。
   - 会话事件沿用 Pi 的事件格式并加上会话 ID，所以界面上已有的消息解析代码可以继续用。
4. **生命周期**：
   - 打开应用时，如果后台没在运行就自动启动它。
   - 关窗口只是缩到托盘，后台继续运行；从托盘退出时可以选「只关界面」或「连后台一起退出」。
   - 「开机自动启动」是设置里的开关，默认关闭。
5. **运行方式**：后台源码是 TypeScript，直接用 Node 22 内置的类型剥离运行，不需要单独的构建步骤；另外用 `tsc --noEmit` 做类型检查，测试用 `node:test`。

## 二、功能清单

### A. 独立后台（草案 §6）

| # | 功能 | 标记 | 说明 |
|---|---|---|---|
| A1 | 常驻后台、单实例、令牌鉴权、多界面连接 | 必做 | 见架构 |
| A2 | 托盘、关窗口继续运行、开机自启开关 | 必做 | |
| A3 | 迁移 v0.1.0 全部能力到后台 | 必做 | 多会话并行、审批、信任、压缩、分叉、复制等，行为不变 |
| A4 | 重启恢复 | 必做 | 运行中的任务标为「中断」，待处理的确认卡标为「已失效」，界面显示恢复卡（继续 / 放弃） |
| A5 | 执行轨迹 | 必做 | 每次运行记录步骤、工具调用、耗时、用量、错误；界面默认折叠成一行摘要，可以展开查看 |
| A6 | Windows 系统通知 | 必做 | 没有界面连接时，任务完成、需要确认、执行失败都会弹系统通知 |

### B. 模型供应商

| # | 功能 | 标记 | 说明 |
|---|---|---|---|
| B1 | 供应商列表与编辑 | 必做 | Pi 自带的预置供应商，加上自定义 OpenAI / Anthropic 兼容端点（Base URL、自定义请求头）。用表单编辑，后台写 `models.json`，不需要手写 JSON |
| B2 | API Key 加密保存 | 必做 | 用 Windows DPAPI（与当前 Windows 账户绑定）加密，借助 Pi 的 `"key": "!命令"` 机制在使用时解密；不改动已有的明文配置 |
| B3 | 测试连接、拉取模型列表、模型能力信息 | 必做 | 能力信息包括上下文长度、是否支持图片和思考、单价，都可以手动修正 |
| B4 | 备用模型链 | 必做 | 用 Pi 的虚拟模型实现：主模型遇到限流或报错时按顺序换下一个，主要为了无人值守的定时任务 |
| B5 | 辅助模型 | 必做 | 生成标题、提取记忆、生成资料摘要时用的便宜模型 |
| B6 | 用量与花费统计 | 必做 | 按天 / 模型 / 会话 / 任务汇总，数据来自 Pi 记录的每条回复的用量 |
| B7 | 订阅账号登录（OAuth） | 可选 | Pi 本身支持，需要把登录流程接到界面上 |
| B8 | 本地模型预设 | 可选 | 识别本机运行的 Ollama / LM Studio |
| — | 多 Key 轮换、多模型并排对比 | 暂不做 | |

### C. 会话管理

| # | 功能 | 标记 | 说明 |
|---|---|---|---|
| C1 | 全文搜索 | 必做 | 后台为所有会话建 FTS5 索引，搜索标题和正文，点结果可以跳到对应消息 |
| C2 | 置顶、归档 | 必做 | |
| C3 | 自动生成标题 | 必做 | 用辅助模型生成 |
| C4 | 会话内分支 | 必做 | 编辑重发、重新生成都在原会话里产生分支，消息上显示 `‹ 1/3 ›` 切换器，另有分支树面板。Pi 自带树结构，用 `navigateTree` 切换 |
| C5 | 导出与导入 | 必做 | 导出 Markdown / HTML（Pi 自带）/ JSONL，导入 JSONL |
| C6 | 临时对话 | 必做 | 不读也不写记忆，不进入搜索索引 |
| C7 | 标签、批量操作 | 可选 | |
| C8 | 文件检查点 | 可选 | 每次改文件前做影子快照，可以「只恢复文件」，对话保留（参考 Cline） |

### D. 长期记忆与记忆快照（草案 §1–2）

| # | 功能 | 标记 | 说明 |
|---|---|---|---|
| D1 | 记忆库 | 必做 | 每条记忆记录：作用域（全局 / 某个工作区）、类别（偏好 / 背景 / 经验）、来源（你明说的 / Agent 推断的 / 你手写的）、来源会话、更新时间、状态（有效 / 已被替代 / 已删除，旧版本保留可追溯） |
| D2 | 常驻记忆块 | 必做 | 分「关于我」「偏好与习惯」「当前约定」三块，每次任务都带上，有长度上限；每块可以锁定，锁定后 Agent 只能提建议，不能直接改 |
| D3 | 记忆快照 | 必做 | 任务开始时把常驻记忆块加上全文检索出的相关记忆（约 1500 token 预算）打成快照注入，任务期间保持不变，这样对提示缓存友好。界面能看到这次用了哪些记忆，也可以手动刷新 |
| D4 | 记忆工具 | 必做 | `memory_search`、`memory_save` 和修改 / 删除。你明确说「记住…」时直接保存；Agent 自己推断的只能生成候选，等你确认 |
| D5 | 候选记忆提取 | 必做 | 任务结束后由辅助模型从对话中提取候选，并和已有记忆比对，判断是新增、更新、删除还是无需处理，生成「候选记忆卡」，你可以确认、改后保存或忽略。这个功能有开关 |
| D6 | 记忆管理页 | 必做 | 浏览、搜索、编辑、删除、导出、清空，总开关 |
| D7 | 跨会话检索 | 必做 | 给 Agent 一个 `session_search` 工具，可以搜索过去的对话（复用 C1 的索引） |
| D8 | 压缩前保存记忆 | 可选 | 上下文压缩之前，先提示 Agent 把要紧信息记下来（参考 OpenClaw） |
| — | 向量检索、后台空闲整理 | 暂不做 | 单机规模下全文检索已经够用 |

### E. 渐进式技能与任务模板（草案 §3）

| # | 功能 | 标记 | 说明 |
|---|---|---|---|
| E1 | 技能管理页 | 必做 | 加载方式用 Pi 自带的渐进式加载。管理页可以列表、查看、启用 / 停用、删除、从文件夹导入 |
| E2 | 技能沉淀建议 | 必做 | Agent 用 `skill_propose` 工具，或任务结束后你点「存成技能」，生成技能草稿；以确认卡展示完整内容或修改差异，你批准后才写入 |
| E3 | 任务模板 | 必做 | 存成 Pi 的提示词模板（输入 `/名字` 也能用），并加上命名参数，界面上弹表单填写；支持把一次对话存成模板 |

### F. Agent 循环、任务与卡片（草案 §4、§7）

| # | 功能 | 标记 | 说明 |
|---|---|---|---|
| F1 | 任务模型 | 必做 | 任务 = 目标 + 关联会话 + 状态（等待 / 运行中 / 需要确认 / 完成 / 无变化 / 失败 / 中断）+ 来源（对话 / 写笺 / 模板 / 定时）+ 关联的写笺、资料、产物 + 耗时与花费。每个会话本身也是一个任务 |
| F2 | 确认卡 | 必做 | 分成「批准操作」和「补充信息」两类，避免回答了问题就被当作同意执行。确认卡持久保存，关掉界面也还在，集中显示在「待处理」收件箱里；无人值守时可以设置过期时间 |
| F3 | 审批规则 | 必做 | 保留现有三档模式，另外加按工作区的「总是允许某工具」，以及无人值守时的单独策略 |
| F4 | 产物卡 | 必做 | 自动收集任务中写入或修改的文件，可以预览（Markdown / 文本 / 图片）、打开、在资源管理器中显示，或继续修改 |
| F5 | 任务卡 | 必做 | 显示目标、当前步骤、状态、耗时与花费、结果入口；聊天里的卡片保留当时的状态，同时能跳转到最新状态 |
| F6 | 运行上限 | 必做 | 单次运行有最大轮数，每天有花费上限；超出时停止，并生成确认卡 |

### G. 书桌与写笺（草案 §5）

| # | 功能 | 标记 | 说明 |
|---|---|---|---|
| G1 | 书桌页 | 必做 | 每个工作区一张书桌，分资料、写笺、任务、产物四栏；另外默认提供一个「个人」工作区 |
| G2 | 写笺 | 必做 | Markdown 编辑，自动保存；点「交给 Agent」时选择要带上的资料和常用动作（总结 / 核对 / 写成报告 / 提炼待办），然后创建任务；写笺上显示关联任务和状态 |
| G3 | 资料 | 必做 | 添加文件或文件夹、粘贴文本 |
| G4 | 关联与继续 | 必做 | 任务完成后，产物自动挂到书桌上，关联写笺和资料；可以从产物或任务「继续处理」 |
| G5 | 网页资料与资料目录地图 | 可选 | 抓取网页存成资料；辅助模型为每份资料生成摘要，Agent 先看目录再按需读原文 |

### H. 定时任务（草案 §8，按草案语义完整实现）

| # | 功能 | 标记 | 说明 |
|---|---|---|---|
| H1 | 三类记录 | 必做 | 任务计划、执行记录、交付记录，分别保存 |
| H2 | 三种触发 | 必做 | 一次性、固定间隔、按日历（cron + 时区）；时区按计划自己指定，按日历的任务遵循指定时区，不简单理解成每隔 24 小时 |
| H3 | 稳定的触发标识 | 必做 | 防止同一次触发被重复领取；计划修改后，旧的触发失效 |
| H4 | 手动立即运行 | 必做 | 单独记一条执行记录，不影响原来的周期 |
| H5 | 错过时间的处理 | 必做 | 一次性任务补做，并标明原定时间和实际执行时间；监控类合并成最多补查一次；报告类可以选跳过或补做最近一次 |
| H6 | 同一计划不并发 | 必做 | 上次没跑完时新触发先合并等待，结束后再判断是否补做；不同计划可以并行 |
| H7 | 有限重试 | 必做 | 只在还没产生外部效果时自动重试，否则保留记录、提示你处理 |
| H8 | 执行上下文 | 必做 | 默认每次执行都是独立会话，带记忆快照；可以绑定某个已有会话；每个计划有少量专属状态（例如上次检查结果）；只能用计划允许的工具 |
| H9 | 结果与通知 | 必做 | 执行状态区分等待 / 运行中 / 需要确认 / 完成 / 无变化 / 失败 / 中断；交付状态区分已送达 / 未送达 / 不明；监控类任务没变化时不通知，失败不会被当成没变化 |
| H10 | 计划管理页 | 必做 | 修改、暂停、恢复、立即运行、删除，查看历史；Agent 也可以通过工具创建计划，但需要你确认，并有最小间隔限制 |
| H11 | 手机端通知渠道 | 可选 | 例如 Telegram / 飞书 Webhook |

### I. 工具与连接

| # | 功能 | 标记 | 说明 |
|---|---|---|---|
| I1 | MCP 管理页 | 必做 | Pi 自带 MCP，管理页提供表单添加、启用 / 停用、连接状态、工具列表 |
| I2 | 网页抓取工具 `web_fetch` | 必做 | 抓取网页并转成正文 |

## 三、界面结构（功能可用版，不做视觉设计）

界面左侧放一列导航，依次为：

- 对话
- 书桌
- 任务（含定时任务和待处理收件箱）
- 记忆
- 技能与模板
- 设置

设置里包括：供应商、模型与用量、MCP、审批、记忆、外观、关于。

## 四、开发顺序

1. 后台地基：A1–A6，再加 C1 的索引底座
2. 供应商与会话：B1–B6、C1–C6
3. 记忆与技能：D1–D7、E1–E3
4. 任务、卡片、书桌：F1–F6、G1–G4
5. 定时任务：H1–H10
6. 工具：I1–I2
7. 可选项：按价值挑选
8. Codex 审查 → 修复优化 → 全量测试与端到端验收 → 发布 v0.1.1

每个阶段都配单元测试和集成测试，接真实模型的部分用 DeepSeek 跑。
