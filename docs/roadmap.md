# DreamFlutter 路线图（v0.3 → v1.0）

定于 2026-11-01，依据用户的 v0.2 深度测试记录（`本科毕设\毕设学习\2026-11-01 df测试记录.md`，35 条）。v0.9 做一次同样的深度测试，然后发布 1.0。

排法：不按测试记录的顺序，按依赖关系排：先打地基，再统一外壳，之后的新功能都做在新外壳上；后面的版本依赖前面的成果（长任务的后台机制 → 记忆 Agent → 书桌的常驻 Agent）。括号里是测试记录的条目号。

## v0.2 收尾时已经做了

- OpenCode Go 渠道（20）；按模型的思考档位和上下文窗口（1、6 的一部分：来自 Pi 内置目录和平台的模型列表）。
- 渠道编辑页溢出（2）、Ctrl + 滚轮缩放（8）、去掉「后台会话」说明（7）、上下文实时刷新（19）、整个对话区可拖文件（16）、自绘顶栏简版（35 的一部分）。

## 定方向时说好的几点

- **沙箱**：Flutter 窗口不进容器，隔离的是 Agent 执行命令、跑代码的环境。Word 自动化这类任务要 Windows 本机，所以沙箱按工作区或任务可选；前提是用户装 Docker Desktop / WSL2。
- **总路由技能**：不在每条消息前多调一次模型。技能和 MCP 的目录、使用规则放进上下文，由主模型判断；技能很多时再用辅助模型做一次轻量预筛，效果用测试量。
- **书桌**：对话是「公司」，按工作区和任务，即来即走；书桌是「家」，一个固定的私人工作区，长期积累想法。
- **Showcard**：做成技能，不写进系统提示词（用户正式版用一个月后再反馈卡片的优先级）。
- **需要用户提供**：beautiful-article 和 rearticle 的 GitHub 链接（0.6 用）；品牌素材和讨论（0.4）。
- **分工**：Claude 写代码；Codex 只做必要的审查；广泛调研交给 Antigravity（安全、RikkaHub、记忆、Docker、成熟的技能体系）。
