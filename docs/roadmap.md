## 三、每个版本的通用流程

1. **先修 bug**：上一轮实测里确认的 bug 放在版本开头修完。
2. **调研**（需要的话）：广泛调研交给 Antigravity（经 Agent Bridge，后台任务），报告放 `docs/research/`，AI 给的内容一律当待核验素材。
3. **设计确认**：需要用户定的事在开工前一次问清；界面设计先出设计稿让用户挑。
4. **实现**：Claude 写代码（前后端都写）；每个改动配单元测试 / 组件测试；后台 `core/test/`，窗口 `app/test/`。
5. **测试**：按 [testing/scenarios.md](testing/scenarios.md) 走全场景清单（v0.3.3 起），开发时守 [dev-guide.md](dev-guide.md)；后台、窗口、协议层全量；场景巡检（`integration_test/scenarios_test.dart`）；视觉检查截图（`integration_test/look_test.dart`）；真实模型 E2E **走用户在应用里配好的 OpenCode Go 渠道**（`deepseek-v4.1-flash`，E2E 用 `core/scripts/copy-channels.ts` 复制渠道，**不要在测试里新建渠道**）。
6. **安装包实测**：用户主要用安装包长程使用（额外测试就是这样发现 rg 缺失的），每个版本发布前打一次安装包，在没有开发环境的条件下跑一遍关键流程。
7. **审查**：Codex 只做必要的只读审查（额度少），只审这个版本的高风险部分。
8. **发布**：用户验收 → 本地打 tag（不推送）→ 更新 `docs/HANDOFF.md`、发布说明、这份计划的状态。

- **3.1 调研**（Antigravity，三份并行，开工时就派出去）：
  1. **Agent 安全**（10）：Claude Code、Codex、Cursor、OpenHands、Goose、Cline 等的权限模型、沙箱、提示注入防护、密钥管理、审计、网络出站控制；输出「我们缺什么」清单（扩充设置在 0.6 做）。

- **3.2 执行环境抽象**：工具不再直接碰本机，而是经过「执行环境」（本机 / WSL，以后加 macOS 虚拟机）：执行命令、执行 Python、读、写、改、搜索、列目录。本机环境就是现在的行为（审批照旧）。每个 Agent 会话固定一个执行环境，提示词随环境变（沙箱里告诉 Agent 它在 Linux 的 `/workspace`）。
- **3.3 WSL 沙箱**（14、蝶君补充第 2–7 节，按第二节第 3 条修正）：
  - **安装引导**：检测 WSL；没有时给出引导（一键以管理员身份运行 `wsl --install --no-distribution`，提示重启）；没装 WSL 时工作台照常用，蝶君页显示引导。
  - **专用发行版**：名字固定（如 `DreamFlutterSandbox`），装在 `%APPDATA%\DreamFlutter\sandbox\`，不碰用户自己的 WSL 发行版。首次使用时下载官方最小镜像（Ubuntu / Debian，按 3.1 的结论选），用国内镜像源装 Python、uv、git、ripgrep、fd、jq、常用 Python 包（pandas、numpy、matplotlib、openpyxl…），装完导出一份**干净快照**。
  - **加固**：`wsl.conf` 关自动挂载、关互操作；Agent 以普通用户 `agent` 运行，没有 sudo；应用每次启动沙箱前以 root 身份重写 `wsl.conf` 再启动；系统软件（apt）由应用代装（白名单内直接装，其他的问用户一次）。
  - **常驻 bash**：一个一直开着的 `wsl.exe` 进程（同时让沙箱不被自动关机），里面是常驻 bash，结束标记、超时、输出截断照 `pwsh` 工具的做法；工作目录和环境变量跨命令保留。常驻 Python 内核放 0.8。
  - **文件**：Windows 这边经 `\\wsl.localhost\<发行版>\...` 读写沙箱里的文件（读写工具、气闸舱、应用内预览都靠它）。
  - **气闸舱**：`/workspace/inbox`（导入的文件副本，原文件不受影响）、`/workspace/scratch`（随便折腾）、`/workspace/outbox`（交付物，出现新文件时通知窗口）。导出 = 用户选位置后复制回本机。
  - **资源与网络**：进程数等限制在沙箱里设；内存上限要写用户的 `.wslconfig`（影响用户所有 WSL 发行版），只在用户同意时改；联网 / 离线开关，实现方式看 3.1。
  - **重置**：一键恢复到干净快照（先确认，提示 scratch 和 outbox 会清空、记得先导出）。
  - **逃逸自检**：以 `agent` 身份尝试挂载 C 盘、调用 `cmd.exe` / `powershell.exe`、改 `wsl.conf`、`sudo`、访问内网，全部应该失败；作为自动测试（没装 WSL 时跳过），设置里也能手动运行。
- **3.4 Agent 运行时 + 子 Agent**（额外 11、22 的前半）：
  - **角色卡**：名字、提示词、模型（可选模型组，子任务用便宜的）、工具、执行环境、审批规则、能读哪些记忆、轮数和花费上限、上下文怎么给（全新 / 带父会话摘要）。蝶君、子 Agent、0.5 的记忆 Agent 都是角色卡。
  - **子 Agent 工具**：主 Agent 派活，可一次派几个并行（有上限）；子 Agent 在自己的上下文里干完，只把结果摘要交回，长结果写成文件；花费计入主任务；窗口里显示每个子 Agent 的进度、花费，能点开看过程。工作台和蝶君都能用。
  - **跨环境派活**（待 3.1 第 2 份调研确认值得做）：工作台的 Agent 把「试装一个库、跑一段不放心的代码」派给沙箱里的子 Agent，结果经气闸舱回来。
  - 放到后台、主流程等它完成再继续 → 0.8。
- **3.5 蝶君骨架**（26、额外 6、额外 9 后半）：
  - 导航：「对话」改名「工作台」，「书桌」改名「蝶君」（工作名）。
  - 蝶君 = 一张角色卡：执行环境是沙箱，**沙箱里不弹审批**；默认不开 MCP，不给卡片本机授权（沙箱外有真实后果的事以后单独定规则）。共享模型、技能（技能里的脚本复制进沙箱执行）。记忆先用一个「蝶君」分区（0.5 做成正式的隔离分区）。
  - 「交流」：和蝶君的会话列表，和工作台的会话分开，不出现在工作台。
  - 「工作」：现在书桌的写笺、资料、产物、卡片搬进来（数据迁移）。去掉「交给 Agent」的选动作弹窗，直接交给蝶君，有问题它自己问；资料作为副本进 inbox；任务在蝶君里完成，结果留在蝶君。
  - 产物：outbox 里的文件在应用内显示和预览（文本、图片、PDF、HTML 用现有渲染页），简单文本可以直接改；「保存到本机」复制出去。
  - 人格、自主工作、专属记忆不在 0.3，见 0.8。
- **3.6 工作区运行环境**（额外 4）：
  - 工具链（rg、fd、uv、便携 Python 等）由应用统一提供，放在应用目录，所有工作区共用。
  - 每个工作区第一次使用时建 `.dreamflutter\` 文件夹：工作区说明文档（Agent 读的，记录项目是什么、怎么运行）、需要时的 Python 虚拟环境、临时文件。用户的文件不动。提示词告诉 Agent 用这个文件夹，而不是到处现找现搭。
- **3.7 记忆开发设计**（25）：把记忆纪要写成 `docs/memory-design.md`：数据结构、记忆 Agent 的角色卡和程序侧约束（纪要 12.5）、快照在 Pi 上下文里怎么组装（技术验证：注入点、压缩后旧记忆复活怎么防）、v0.2 记忆的迁移；纪要第 19 节的 12 个待定项各给一个建议值。记忆 Agent 的运行隔离和存储按蝶君补充第 4 节。0.4 期间和用户逐项定稿。

**依赖**：用户在开发机上装好 WSL（3.3 开工前）。
**要用户做的**：装 WSL（Claude 给出完整步骤）；3.1 调研结论出来后确认网络控制和跨环境派活的做法。
**验收**：

### v0.5　记忆系统

**目标**：按记忆纪要和 0.3 的开发设计，实现三级记忆和专门的记忆 Agent。原文要点：「记忆快照的机制还是不错的……在它的基础上」进一步优化。

**工作项**（细节以 `docs/memory-design.md` 定稿为准）

- **5.0 修复批**。
- **5.1 三级记忆**（25）：一级近期（近 14 天重点管理、每周整理）、二级阶段（每周轻量复查、每月整理、每季度回顾、事件触发）、三级长期（变化触发复查，一般不遗忘，可锁定永久保留）。每条正式记忆有来源、作用域、生命周期、确认情况、关联关系和操作历史；管理信息不进快照。
- **5.2 快照**：快照仍是日常工作用记忆的主要方式。统一预算 = min(用户上限, 模型上下文窗口的 3%, 扣除非记忆内容和执行预留后剩余空间的 15%)，常驻约定、相关记忆、按需补充都算在内；分层软配额 40 / 35 / 25（初版参数，要实测）。刷新时机按纪要 10.3；防重复注入、过时沿用、压缩后复活、范围漂移、静默失败。
- **5.3 分级写入和确认**：按纪要第 6 节的默认权限（明确要求记住的直接存、Agent 推断的个人偏好进候选、经验要有验证证据……）。
- **5.4 转化与遗忘**：提炼、直接进入、降级、失效都保留关联；遗忘主要发生在提炼中；只有活跃记忆真的满了才提出可复核、可恢复的软遗忘方案；不自动彻底删除；用户明确要求彻底删除隐私内容单独设计。
- **5.5 作用域**：全局 / 工作区 / 共享组 / 临时授权，约束覆盖记忆检索、会话搜索、索引、摘要、缓存、后台任务；**工作台和蝶君的记忆分区**（蝶君分区为 0.8 的专属记忆打底）。
- **5.6 记忆 Agent**：一张由程序锁死权限的角色卡（0.3 的运行时），负责提取、维护、分层整理、去重、冲突处理、快照准备、容量处理和解释；调度和成本统一在设置 / 仪表盘里管（纪要第 13 节）。
- **5.7 用户控制**（纪要第 15 节）：看层级和来源、纠正、锁定、看本次用了哪些记忆和为什么、看记忆 Agent 做了什么和花了多少、批量确认、恢复和回撤。
- **5.8 记忆强度和频率**（9）：设置里选详细程度和整理频率。
- **5.9 模式行为**：标准 / 极简 / 无痕各自读不读、写不写、存不存记录、后台整理不整理，界面上说清楚（纪要第 14 节）。
- **5.10 迁移**：v0.2 的记忆库、常驻块、候选迁过来；缺来源的旧条目标「待复核」，不补造证据；可核对、可回退。

**依赖**：0.3（运行时、开发设计）、0.4（界面框架）。
**要用户定的**：开发设计里的待定项（0.4 期间定完）。
**验收**：纪要 16.2 的核心场景和 16.3 的行为约束都有自动测试（用模拟时间推进两周、一个月、一个季度、一年）；旧记忆完整迁移；无痕模式下完全不读写。

### v0.7　技能与 MCP 体系

**目标**：用户主要通过对话让 Agent 自己建立、测试、调用技能和 MCP；管理界面参考 RikkaHub。

**工作项**

- **7.0 修复批**。
- **7.1 调研**（Antigravity）：RikkaHub 的技能 / MCP 管理；Anthropic 的 Agent Skills 规范和官方 skill-creator、mcp-builder；社区高分常用技能库；MCP 官方文档、Registry 和 MCP Inspector。
- **7.2 管理页**（11、28）：放进「技能」页：技能、任务模板、MCP 服务三个分区和「待确认」；每项有详情、启用开关、来源、使用次数、最后使用时间、测试按钮。先做功能，界面后面再优化。
- **7.3 三个基础技能**（11）：
  1. **总路由**：做法见第二节。
  2. **建技能**：和用户沟通需求 → 先搜社区成熟、高评价的技能 → 用户明确要独特设计时才自己写，也参考成熟设计 → 写入、测试、登记。
  3. **建 MCP**：查官方文档和 Registry → 生成或配置 → 实际连接测试 → 登记。
  - 「测试」可以放进蝶君的沙箱里跑（来路不明的技能脚本不在本机执行）。
- **7.4 showcard_pro 技能**（24）：Showcard + beautiful-article + rearticle（GitHub 的 gardenskill）封装成一个技能，做周报这类交付时直接调用。**不写进系统提示词**。需要用户提供两个项目的链接。
- **7.5 技能和 MCP 的安全**：社区装的默认不信任，经 0.6 的安全规则；蝶君能用哪些 MCP 单独授权。

**依赖**：0.3（沙箱）、0.6（安全设置）。
**要用户定的**：beautiful-article、rearticle 的链接；路由技能的测试任务集。
**验收**：对话里说「帮我做一个 X 技能」能找到或写出、测试后出现在管理页；说「接上 X 服务」能配好 MCP 并通过连接测试；路由测试集命中率达到约定的数；做周报时会调用 showcard_pro。

### v0.8　长任务 + 蝶君成长

**目标**：长任务能放到后台、能插话、进度清楚、中间结果看得到；蝶君有自己的性格、专属记忆，能在沙箱里自主工作。

**工作项**

- **8.0 修复批**。
- **8.1 后台子 Agent 与等待**（22）：子 Agent 和长脚本放到后台，主流程继续；主流程也可以主动停下等后台完成拿到结果再继续（完成 → 通知 Agent → 继续）；在 0.3 的子 Agent 和 v0.2 的 `pwsh` 后台任务上扩展，显示在 0.4 的右侧面板。
- **8.2 插话**（23）：默认仍排队，加「立即插入」按钮打断当前步骤。开工时顺带查长命令运行时的进度反馈够不够（用户当时问「怎么停下来了」）。
- **8.3 计划清单**（23）：固定在输入框上方，一项项打勾。调研成熟 Agent 的做法。
- **8.4 中间过程可见**（17）：渲染 HTML、画图表、看截图时每一步的图片都显示在对话里；大数据用 Python（蝶君里用**常驻 Python 内核**，变量跨轮保留，蝶君补充 4.3）；在用户提示下用 MATLAB（检测本机 MATLAB，工作台里经命令行调用）；Word / Excel / PDF 和表格可视化能力补齐。
- **8.5 提问框**（15）：按 0.4 的新设计重做（选项卡片、自己回答、跳过、限时），和插话、清单一起做成一套「运行中的互动」。
- **8.6 长任务测试集**：文档处理、表格可视化、Python 大数据、MATLAB、HTML 渲染做成可重复的测试任务，用 OpenCode Go 跑，记录成功率、轮数、花费。
- **8.7 蝶君成长**（蝶君补充）：
  - 性格和人格：蝶君的人设、说话方式，用户可调；
  - 专属记忆：在 0.5 的蝶君分区上，记住和用户的交流、自己做过的工作；
  - 自主工作：在沙箱里按计划或用户交代的长期目标自主推进（定时任务可以交给蝶君），结果留在「工作」里等用户看；
  - 自主学习：例如在沙箱里给自己装工具、写技能、测试后登记（用 0.7 的建技能）。
  - 范围和做法开工前和用户讨论；「大肥鱼」那样接入社交平台不在这里（1.0 之后）。

**依赖**：0.3（运行时、沙箱）、0.4（右侧面板、对话呈现）、0.5（记忆分区）、0.7（建技能）。
**要用户定的**：本机 MATLAB 的版本和路径；「立即插入」直接打断还是先问；蝶君的性格设定和自主的边界。
**验收**：一个需要 5 分钟以上脚本的任务放到后台，期间能对话，脚本结束后自动继续；「立即插入」能打断正在跑的命令；清单逐项打勾；测试集全部跑完并留下报告；蝶君能按设定的性格交流，并完成一个自主的定时任务。
